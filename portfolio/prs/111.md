## 문제

모바일 운영자 팝업 설정에서 이미지 리사이즈 핸들을 드래그하면 상단 표시 크기 수치만 변경되고, 실제 이미지와 선택 테두리·8방향 핸들은 화면상 같은 크기로 남아 조절 결과를 즉시 확인할 수 없었다. 데스크톱에서는 같은 기능이 정상 동작하므로 모바일 렌더링 경로에 한정된 회귀다.

## 원인

- 모바일에서도 데스크톱과 동일한 표시 좌표를 사용하면서 반응형 컨테이너가 이미지를 다시 축소해, 저장용 px 값의 변화가 실제 화면 크기에 직접 반영되지 않았다.
- 이미지 요소, 선택 테두리, 핸들이 하나의 모바일 표시 크기를 공유하지 않아 포인터 이동 중 UI가 서로 분리돼 보였다.
- 숫자 입력값을 매 키 입력마다 즉시 정규화해 빈 값 상태를 거칠 수 없었고, 편집 영역 크기 변화와 포인터 취소 경로도 모바일 기준으로 보정되지 않았다.

## 수정

- 모바일 전용 표시 크기와 포인터 리사이즈 계산을 분리하고, 이미지·선택 테두리·8방향 핸들이 같은 너비·높이를 사용하도록 통합했다.
- 모서리는 비율 유지, 상·하는 높이만, 좌·우는 너비만 변경하도록 핸들별 계산을 명시했다.
- 최소 `50×50px`, 편집 영역 내부 최대 너비, 화면 높이 `70vh` 제한을 적용했다.
- 숫자 입력은 편집 중 빈 값을 허용하고 blur·Enter에서 검증·확정하도록 변경했다.
- 큰 저장 이미지는 저장값을 건드리지 않고 모바일 편집 영역 안에 맞춰 초기 표시하며, SVG도 지정된 너비·높이로 렌더링한다.
- `ResizeObserver`와 `pointercancel` 처리를 추가해 화면 회전·영역 변경·드래그 취소 시 상태를 안정화했다.
- 데스크톱 `md+`는 기존 Next Image 렌더링, 즉시 숫자 입력, 리사이즈 계산 경로를 그대로 유지했다.

## 검증

- 팝업 이미지 편집기 집중 단위 테스트 8건 통과.
- web TypeScript 검사 통과.
- 변경 파일 Biome 검사와 `git diff --check` 통과.
- DB·API·마이그레이션 변경 없음.
- 실제 모바일 브라우저에서 핸들 방향별 드래그와 저장 결과는 수동 검수 대상.
