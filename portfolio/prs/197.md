## 무엇을 개선했나
로그인 이후 팝업이 페이지 준비 전에 반복 노출되고, 미처리 신고를 같은 사용자가 다시 접수할 수 있으며, 신고 대상 사용자 조치와 누적 경고 정책이 운영 화면 전반에서 일관되지 않았습니다. 또한 여러 운영자·구인자 목록의 페이지 크기와 이동 방식이 서로 달라 원하는 페이지로 바로 이동하기 어려웠습니다.

로그인·신고·경고 흐름을 서버 정책과 화면 동작까지 함께 정리하고, 숫자를 직접 입력할 수 있는 공용 페이지 이동 컨트롤을 목록 화면에 재사용했습니다.

## 변경 내용

### 로그인 팝업과 중복 신고
- 로그인 화면과 인증 전환 중에는 팝업을 노출하지 않고 목적지 페이지의 인증·라우트·팝업 조회가 준비된 뒤 표시
- 글·댓글·채팅방·공고의 기존 신고가 접수됨 또는 검토 중이면 새 신고를 만들지 않고 `이미 신고된 글입니다. 처리결과를 기다려주세요.` 안내
- 처리 완료·기각 신고 이후의 재신고와 다른 사용자의 동일 대상 신고는 기존 정책대로 허용

### 신고 내역과 운영자 신고 조치
- 구직자·구인자 신고 내역을 최신순 페이지당 10개로 조회
- 운영자 콘솔의 검수 대기·신고 대기·경고 사용자 통계를 해당 화면에 연결
- 신고 상세에서 글·댓글·공고 작성자 또는 채팅 피신고자를 신고자와 구분해 표시
- 채팅 신고 요약을 `채팅방 → 피신고자 → 신고자` 순서로 배치하고 채팅방만 말풍선 아이콘 사용
- 대상 사용자 카드와 유저 보기 버튼을 실제 `/moderator/users/{userId}` 상세에 연결
- 신고 상세의 경고 버튼에 사용자명 확인 AlertDialog를 추가하고 사용자 관리와 같은 경고 카운트 반영

### 누적 경고 5회 제한
- 누적 경고가 정확히 5회가 되는 순간부터 72시간 제한 시작
- 구직자는 자유수다·밤문화 이야기·중고거래의 글과 댓글 작성만 제한
- 구인자는 신규 공고 등록만 제한하고 기존 공고 수정·끌어올리기·광고 기능은 유지
- 6·7회 경고에서는 제한을 새로 시작하거나 연장하지 않음
- 제한 안내에 서버 기준 남은 시간을 `HH:MM:SS`로 표시하고 확인 버튼으로 정상 종료
- 72시간 만료 시 관리자 조작 없이 계정 상태를 자동 정상화
- 정상 복구는 누적 경고 횟수를 유지하면서 현재 제한만 즉시 해제
- 최근 경고 1회 되돌리기는 아직 취소하지 않은 최신 경고 한 건만 차감하고 5→4가 되면 제한 해제

### 사용자 관리 상태 보존
- 사용자 검색·상태·역할·휴대폰 인증·누적 신고·경고 필터와 현재 페이지를 URL에 보존
- 상세 조치 후 목록 복귀 시 기존 필터와 페이지 유지
- 경고 사용자 필터의 빈 결과와 실제 조회 실패 안내를 구분
- 행 높이와 페이지네이션 영역을 분리해 조직명 유무와 관계없이 이동 컨트롤 위치 고정

### 공용 페이지네이션
- 이전 버튼·숫자 전용 입력·다음 버튼을 `PageControls` 공용 컴포넌트로 통합
- Enter 또는 포커스 해제 시 이동하고 범위 밖 값은 첫·마지막 페이지로 보정
- 운영자 사용자·신고·공고·검수·금칙어·채팅·출석·후기·수집 공고·수집 커뮤니티 목록에 적용
- 구인자 내 공고·광고 관리와 사용자 신고 내역에도 적용
- 운영자 채팅·출석·후기 목록을 페이지당 10개로 통일
- 최신 develop의 수집 공고 URL 상태·스크롤 복귀·일괄 삭제 기능을 유지하면서 공용 컨트롤 결합

### DB migration
- `bambi_profile.warning_restriction_until` 컬럼 추가
- 만료 제한 조회를 위한 `bambi_profile_warning_restriction_until_idx` 추가
- 최신 develop의 `0091·0092` 뒤에 `0093_needy_lightspeed.sql`로 Drizzle migration 재생성
- snapshot과 journal 이력을 `0091 → 0092 → 0093` 순서로 정리
