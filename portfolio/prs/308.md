## 개요

본인인증을 마치고 `/seeker`를 이용하던 비회원이 공고 상세 등 회원 전용 화면에서 회원가입으로 이동할 때, 유효한 인증을 이어받지 못하고 다시 본인인증해야 하던 문제를 수정했습니다.

서명된 게스트 토큰과 서버의 기존 인증 로그를 연결해 재인증 없이 가입 정보 입력 단계로 복원합니다. 본인인증만으로 회원이나 로그인 상태가 되지는 않으며, 기존과 같이 계정·프로필 생성 후 역할별 온보딩으로 이동합니다.

- 설계: `docs/superpowers/plans/2026-09-08-guest-verification-signup-reuse.md`

## 변경 내용

### 비회원 인증 복원

- `onboarding.getGuestSignupStatus`를 추가해 개인정보를 응답하지 않고 `available`·`account_exists`·`reauthenticate` 상태만 반환합니다.
- 회원가입 직접 진입과 회원 전용 경로의 게스트 차단 리다이렉트에서 같은 상태 조회를 사용합니다.
- 유효한 인증이면 가입 정보 입력 단계를 열고, 인증 기록이 없거나 불완전하거나 만료되었으면 본인인증 단계를 유지합니다.
- 30일 기준은 별도 숫자로 복제하지 않고 기존 `GUEST_TOKEN_MAX_AGE_SECONDS`를 밀리초 상수와 판정 함수의 정본으로 재사용합니다.

### 가입 제출·프로필 생성

- 가입 제출 직전에 게스트 인증 상태를 다시 확인합니다. 만료 시 입력값과 약관 동의를 비우고 재인증 단계로 돌아갑니다.
- 기존 회원과 생년월일·전화번호 또는 CI·DI가 일치하면 로그인 화면과 기존 계정 안내를 표시합니다.
- 저장된 비회원 인증으로 프로필을 생성할 때 서버가 검증된 guest context와 최신 인증 로그를 다시 확인합니다.
- 프로필 생성 트랜잭션에서 `guestId` 연결을 조건부로 해제해 동일 인증을 한 번만 소비합니다.
- 프로필 생성과 동의 기록이 끝난 뒤 게스트 쿠키를 제거합니다.

### 유지한 동작

- `/seeker` 공고 목록과 공개 수다방 등 기존 비회원 허용 범위는 변경하지 않았습니다.
- 회원 전용 경로의 가입 유도와 가입 완료 후 역할별 온보딩 이동은 유지했습니다.
- DB 스키마 변경과 migration은 없습니다.
