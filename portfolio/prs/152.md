## 주요 변경

### 1. 변경사항 미제출 상태

- 사업자 인증 상태에 `changes_unsubmitted`를 추가하고 화면에는 `변경사항 미제출`로 표시합니다.
- 인증 완료 업체가 업체명·사업자등록번호·대표자명·개업일자 또는 인증 서류를 변경하면 해당 상태로 전환합니다.
- 수정 중인 업체 정보는 별도 임시 필드에 자동 저장하며 재접속 시 복원합니다.
- 업체 정보 제출 전까지 서류를 계속 추가·삭제할 수 있습니다.
- 제출 전 변경사항은 Admin 심사 목록과 알림에서 제외합니다.

### 2. 변경 확인 및 이탈 방지

- 인증 완료 상태에서 서류를 추가하거나 삭제할 때마다 AlertDialog로 재심사 전환과 서비스 제한을 안내합니다.
- 사이트 메뉴·내부 링크·모바일 메뉴·브라우저 뒤로가기는 커스텀 AlertDialog로 막습니다.
- 주소 직접 이동·새로고침·탭 닫기는 브라우저 기본 이탈 확인창을 사용합니다.
- 이탈 안내 확인 시 업체 정보 제출 버튼으로 부드럽게 스크롤하고 포커스와 primary 강조 효과를 적용합니다.

### 3. 미제출 상태의 이용 제한

- 기존 공개 공고와 광고를 즉시 비공개로 처리합니다.
- 신규 공고 등록과 광고 구매를 차단합니다.
- 기존 채팅방 열람은 유지하되 신규 채팅과 기존 채팅 답장을 모두 차단합니다.
- 다시 승인되면 기존 정책에 따라 공개 가능한 공고와 광고를 다시 이용할 수 있습니다.

### 4. 제출 및 재심사

- 업체 정보 제출 시 인증 서류가 최소 1개인지 검증합니다.
- 임시 업체 정보를 심사 데이터로 확정하고 인증 대기 상태로 전환합니다.
- Admin 심사 목록 등록과 알림은 최종 제출 시 한 번만 수행합니다.
- 인증 대기 중에는 기존 정책대로 업체 정보와 인증 서류 수정을 잠급니다.
- 최초 미인증 및 인증 반려 상태에서는 경고 없이 자유롭게 수정한 뒤 제출할 수 있습니다.

### 5. 전체공고 및 로컬 실행 보완

- 사업자 재승인 후 자체 공고가 다시 노출될 때 크롤링 공고와 합쳐 전체공고 한 페이지가 최대 48개를 유지하도록 조회 범위를 수정했습니다.
- Windows worktree에서 Next.js가 상위 저장소를 workspace root로 잘못 선택해 라우트가 404가 되는 문제를 방지했습니다.
