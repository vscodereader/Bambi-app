## 요약

운영자 업소 관리에서 이미 승인된 업소를 다시 승인할 수 있던 UI를 교정하고, 구인자·운영자 화면의 이미지/PDF 사업자 인증 서류를 동일한 공용 파일 행으로 통일합니다.

서버 프로시저와 저장소 권한은 기존 계약을 그대로 사용하며 **서버·DB 변경, 마이그레이션, 신규 의존성이 없습니다.**

## 원인

- 운영자 승인 버튼의 비활성 조건이 mutation 처리 중 상태만 확인하고 현재 업소의 `verificationStatus`를 확인하지 않았습니다.
- 운영자 화면은 이미지에 채팅용 대형 미리보기, PDF에 파일 행을 사용해 같은 사업자 서류가 형식에 따라 크기와 조작 방식이 달랐습니다.
- 구인자 화면의 저장 완료 문서와 업로드 대기 문서도 별도 마크업을 사용해 원본 열기·다운로드 동작이 일치하지 않았습니다.

## 주요 변경

### 승인 완료 업소

- `verificationStatus === "verified"`이면 승인 버튼만 비활성화
- 반려 사유 입력과 반려 버튼은 기존 조건 유지
- 반려 업소 재승인과 변경사항 재제출 후 심사 흐름 유지

### 사업자 인증 서류 공용 행

- `BusinessDocumentFileRow`를 추가해 구인자·운영자 화면이 같은 컴포넌트 재사용
- 이미지/PDF 모두 파일 종류 아이콘, 말줄임 파일명, 형식·용량, 다운로드·삭제 액션 표시
- 파일명·아이콘 영역을 클릭하거나 키보드로 실행하면 원본을 새 탭에서 열도록 통일
- 운영자 화면의 채팅 전용 이미지 미리보기를 제거하고 기존 비공개 문서 열람·강제 다운로드 URL 유지
- 모바일 1열, 기존 업체 정보 화면의 데스크톱 기준인 `md` 이상에서 최대 2열 배치

### 업로드 대기 파일

- 업체 정보 제출 전 이미지/PDF도 저장 완료 문서와 같은 파일 행 사용
- 브라우저 객체 URL로 제출 전 원본 열기와 다운로드 제공
- 대기 파일 제거·교체·컴포넌트 언마운트 시 객체 URL 해제
- 휴지통 버튼은 기존 staged 목록 제거 동작을 그대로 호출
