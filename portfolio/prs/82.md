## 변경 사항

- 수집 공고 관리의 `수집됨` 행에 운영자 전용 상세 이미지 편집 경로를 추가했습니다.
  - 점 3개 메뉴의 `편집`에서 같은 탭 전용 페이지로 이동
  - 운영자·활성 공고 자격을 서버에서 검증
  - 저장 전 변경 폐기 확인과 저장 후 화면 유지
- 크롤링 원본과 운영자 편집본을 분리했습니다.
  - 원본 Base64는 보존하고 편집 문서·revision·마지막 편집자·편집 시각을 별도 저장
  - 기존 편집 문서의 높이·위치 필드 하위 호환
  - 원본 초기화와 이미지 0장 상태 저장 지원
- 여러 상세 이미지의 편집 기능을 추가했습니다.
  - 자유 비율 자르기와 네 모서리·상하좌우 8방향 조절
  - 모서리 비율 유지, 좌우 너비 전용, 상하 높이 전용 크기 조절
  - 반대 경계 고정과 조절 후 위치 유지
  - 내부 복사·붙여넣기, 삽입 위치 지정, 한 장 파일 추가, 삭제, 순서 변경, 다운로드, 실행 취소
  - 모바일 점 3개 메뉴와 우클릭 메뉴
- 저장된 이미지 편집 결과를 구직자 수집 공고 상세 화면에 반영했습니다.
  - 자르기·크기·순서·독립 높이·위치 반영
  - Base64 다중 이미지 리사이즈 중 전체 직렬화를 제거해 입력 지연 개선

### CMU02

검수 중 발견한 문제 공유합니다.

**이미지 높이가 약 7600~7800px 이상이면 편집 저장이 실패합니다.**

- 재현: 세로 높이 7600~7800px 이상인 상세 이미지를 편집(자르기/크기 조절 등)한 뒤 저장 → `Failed to fetch` 오류와 함께 저장 실패.
- 참고로 그보다 작은 이미지에서도 이미지 합계 용량이 크면 413(Request Body Too Large)이 발생했습니다. 서버가 `Fastify({ logger: true })` 기본 bodyLimit(1MiB)인데 저장 요청은 전체 이미지를 Base64 포함 JSON으로 보내는 구조라, 검증 상한(문서 16MB)에 한참 못 미치는 크기에서도 서버 파싱 전에 잘립니다. 높이 임계 증상도 같은 축(페이로드 크기)일 가능성이 있어 함께 확인 부탁드립니다.
