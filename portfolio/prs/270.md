## 요약

공고 등록 결제에 포인트를 사용하면 보유 포인트뿐 아니라 회원 등급 기준 포인트까지 감소해 등급이 내려가던 문제를 수정한다. 포인트몰이 이미 사용하는 "소비·환불은 등급에 중립" 규칙을 공고 결제 사용·환급에도 연결했다.

설계·계획: `docs/superpowers/plans/2026-08-28-job-payment-grade-retention.md`

## 원인

회원 등급은 전체 원장 잔액과 별도로 `등급 기준 포인트`를 계산한다. 기존 계산은 `point_shop_purchase`·`point_shop_refund`만 제외했다.

공고 결제는 다음 동적 reason을 기록하지만 등급 제외 계산에는 연결되지 않았다.

- `공고 등록 포인트 사용: {jobPostId}`
- `공고 취소 포인트 환급: {jobPostId}`
- `공고 취소 포인트 환급 완료(상한 소멸): {jobPostId}`

그 결과 20,000P 등급 회원이 공고 결제에 20,000P를 사용하면 보유 잔액과 등급 기준 합계가 모두 0P가 됐다. 포인트몰에서는 같은 소비를 해도 등급이 유지되어 기능별 정책도 서로 달랐다.

## 작업 내용

### 공통 등급 기준 합계

- `gradeBasisPointsSql`을 공통 SQL 표현식으로 추출했다.
- 여러 회원의 등급 배지(`getGradeBasisPoints`)와 본인 출석·포인트 요약(`attendance.getMine`)이 같은 계산식을 재사용한다.
- 포인트몰 구매·환불과 함께 공고 등록 사용·일반 환급·상한 소멸 환급 완료를 등급 기준 합계에서 제외한다.
- 보유 포인트 합계는 기존처럼 모든 실제 사용·환급 금액을 포함하므로 잔액 동작은 바뀌지 않는다.

### 기존 거래 호환

공고 ID가 reason 뒤에 붙는 기존 원장 형식을 접두사로 판별한다. 신규 거래만 고치는 방식이 아니므로 migration이나 backfill 없이 과거 공고 결제 거래를 가진 회원도 배포 후 재계산 시 정상 등급으로 복구된다.

### 원장 reason 생성 공통화

공고 생성·취소 경로가 `JOB_PAYMENT_POINT_REASONS`를 사용하도록 바꿨다. 원장 기록 형식과 등급 제외 판별 규칙이 서로 어긋나지 않는다.

## 동작 결과

- 공고 결제 사용: 보유 포인트 감소, 기존 등급·다음 등급 진행 기준 유지
- 공고 취소 환급: 보유 포인트 복원, 등급 기준 중복 상승 없음
- 상한으로 환급액이 0P인 완료 기록: 등급 영향 없음
- 포인트몰 구매·환불: 기존 동작 유지
- 가입·출석·커뮤니티 적립과 콘텐츠 회수: 기존처럼 등급 기준에 반영
