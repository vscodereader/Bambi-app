## 배경

운영자 사용자 관리에는 계정 상태·역할·신고·경고 정보는 있지만 회원이 현재 서비스를 이용 중인지 판단할 접속 상태가 없었다. 세션 존재나 장수명 연결만 기준으로 쓰면 화면을 방치해도 계속 온라인으로 남고, 채팅 연결만 보면 다른 화면 활동을 놓친다.

사용자 행동이 유발한 인증 API 요청을 마지막 인정 활동으로 기록하고, 운영자가 설정한 시간 동안 온라인으로 판정한다. 자동 polling·prefetch·SSE heartbeat·Socket 재연결은 활동에서 제외하며 마지막 유효 연결의 정상 종료는 가능한 경우 즉시 오프라인으로 반영한다.

설계·구현 계획: `docs/superpowers/plans/2026-09-04-user-online-presence.md`

## 확정 정책

- 대상: Web·Native의 구직자·구인자·법률자문·운영자. 계정이 없는 guest 제외
- 온라인: 최초 진입 또는 조회·검색·페이지 이동·등록·수정·삭제 등 사용자 행동이 유발한 인증 API 요청
- 오프라인: 마지막 인정 활동으로부터 운영자 설정 시간이 지난 시점. 기본 20분
- 자동 polling·prefetch·캐시 갱신, SSE heartbeat·재연결, Socket.IO 연결·타이핑은 활동에서 제외
- 여러 탭·기기 중 하나라도 유효하면 한 연결 종료만으로 계정 전체를 오프라인 처리하지 않음
- 마지막 유효 연결의 정상 종료·명시적 로그아웃·Native background는 즉시 오프라인. 종료 신호가 유실되면 설정 시간 만료로 최종 판정
- 탈퇴 계정은 항상 오프라인, 정지 계정은 실제 인증 활동이 있으면 온라인
- 전체 접속 이력은 보관하지 않고 최신 마지막 활동과 transient 연결만 저장

## 작업 내용

### DB·공용 정책

- `user.last_activity_at`, `user.presence_disconnected_at` 추가
- `bambi_site_settings.user_offline_after_minutes` 추가, 1 이상의 정수 DB check
- Web/Native 탭·기기별 `bambi_user_presence_connection` 추가: session FK, platform, 연결·lease 시각과 조회 index
- **Drizzle migration `0115_user-presence`** — 이 기능이 0115 번호 선점
- 공용 기본값 20분, 활동 기록 병합 10초, 연결 lease와 온라인 판정을 단일 서비스로 구성

### 활동 기록·연결 수명

- 공용 oRPC 활동 헤더를 통해 인증된 요청만 기록하고, 로그인 사용자도 호출하는 `publicProcedure` 공고·커뮤니티 API까지 포함
- Web은 최초 진입·클릭·제출·키보드 실행 뒤 1회 신호만 보내 자동 요청이 과거 행동을 주워가지 않게 처리
- Native는 active 상태 API를 기록하고 AppState 기반 연결 등록·해제·lease 갱신. lifecycle 요청은 활동에서 제외
- Web 알림 SSE를 connection lifecycle로 재사용하고 pagehide·SSE close·로그아웃에서 연결 해제
- 다중 연결 종료 판정은 사용자 단위 advisory lock으로 직렬화

### 서버 간 실시간 전파

- DB trigger가 사용자 활동·종료·설정 변경을 `pg_notify`로 발행
- 각 API 서버 인스턴스가 PostgreSQL `LISTEN`으로 받아 운영자 전용 `/sse/presence`에 fan-out
- 운영자 브라우저는 전체 사용자 목록을 polling하지 않고 대상 사용자만 즉시 갱신
- 시간 만료는 공용 클라이언트 시계로 최대 10초 오차 안에서 오프라인 전환
- SSE 재연결 시 사용자·설정 정본을 다시 읽어 유실 구간 복구

### 운영자 화면

- 사용자 관리: 체크박스와 이름 사이 `접속` 열, 체크박스와 같은 `size-4` 원, 온라인 우선·최근 활동순 정렬
- 상태 탭·이름/이메일/로그인 아이디 검색과 같은 첫 번째 행 오른쪽에 오프라인 기준 설정 배치
- 사용자 상세: 기존 계정 상태 옆 온라인/오프라인 배지, 계정 정보에 마지막 활동
- 출석 관리: 체크박스와 회원 사이 접속 열, 이름·아이디·오늘 출석을 한 줄로 표시
- 이름·소속 업소·이메일·아이디의 문자 수 기반 자르기를 제거하고 실제 열 폭 CSS 말줄임과 원문 설명 적용
- 사용자 관리·출석 관리 표의 기존 외곽 폭과 56px 데이터 행 높이 유지

**2. floating promise가 API 프로세스를 죽일 수 있음 — `packages/api/src/routers/bambi/attendance.ts:264`, `packages/api/src/routers/bambi/moderation.ts:2208`**

`const offlineAfterMinutesPromise = getUserOfflineAfterMinutes();`를 핸들러 진입부에서 만들고 `attendance.ts:365` / `moderation.ts:2288`에서야 await한다. 그 사이에 다른 `await`가 여러 개 끼어 있어, 핸들러가 붙기 전에 이 쿼리가 reject되면 `unhandledRejection`이 발생한다. `apps/server/src`·`packages/api/src` 어디에도 `process.on("unhandledRejection")`이 없어 Node 기본 동작(throw)으로 **500이 아니라 서버가 내려간다**. 운영자 목록 조회 중 일시적 DB 커넥션 리셋 한 번이면 재현된다. 인라인 await로 바꾸거나 생성 시점에 `.catch()`를 붙여야 한다.

**3. presence 기록 실패가 무관한 요청까지 실패시킴 — `packages/api/src/context.ts:104`**

**4. `sessionStorage` / `crypto.randomUUID` 무방비로 알림 스트림 동반 사망 — `apps/web/src/lib/bambi/user-activity-intent.ts:61`**

`getPresenceConnectionId()`는 `use-bambi-notification-stream.ts:123`의 `openStream()`에서 호출되고, 이는 `useEffect` 안에서 돈다. `crypto.randomUUID`는 비보안 origin(예: `http://<lan-ip>:3001` 테스트)에서 `undefined`이고, `sessionStorage` 접근은 스토리지가 차단된 환경(임베디드 웹뷰, 강한 프라이버시 설정)에서 throw한다. 이 throw가 effect를 탈출하면 presence뿐 아니라 **기존에 잘 동작하던 알림 벨·미읽음 카운트까지 함께 죽는다.** 둘 다 try/catch로 감싸고 인메모리 폴백 id를 쓰는 편이 안전하다.

**5. presence 이벤트마다 운영자 콘솔 전체 재계산 — `apps/web/src/lib/bambi/use-moderator-presence-stream.ts:61` + `apps/web/src/components/bambi/screens/moderator-context.tsx:1080`**

SSE 이벤트마다 `emit({ now, users })`가 돌고, `livePresence`는 `ModProvider`의 대형 `useMemo` 의존성이다. 이 memo는 `limit: 1000` 목록에서 `visibleUsers`를 파생하고 `moderator-users-table`의 클라이언트 정렬까지 이어진다. 서버는 사용자별 활동 write마다(사용자당 10초 스로틀뿐) `pg_notify`를 fan-out하므로, 동시 활동 사용자가 수십 명이면 초당 여러 번 1000행 전체 재계산 + 콘솔 전역 리렌더가 발생한다. presence 상태를 이 memo 밖으로 빼거나 행 단위로 map을 읽게 하면 무관한 사용자의 ping이 컨텍스트 전체를 다시 만들지 않는다.

### 🟢 LOW

**6. `automaticRequestDepth`가 전역이라 실제 활동 헤더가 유실됨 — `apps/native/src/lib/orpc.ts:18`**

카운터를 await 구간 전체에 걸쳐 증가시키므로, presence `connect`/`renew`/`disconnect`가 in-flight인 동안 발생한 진짜 사용자 요청도 활동 헤더를 잃는다. `renew`는 세션 내내 30초마다 돌기 때문에 실제 활동이 주기적으로 누락된다. 호출 지점에서 설정하는 요청 단위 플래그(oRPC context/header)면 해결된다.

**7. connect/disconnect 경합으로 유령 연결이 남음 — `apps/native/src/components/user-presence-lifecycle.tsx:23`**

`connected = true`가 `connect()` 완료 **후에만** 설정된다. connect가 in-flight인 동안 `AppState`가 background로 바뀌면 `disconnect()`는 `connected === false`를 보고 no-op하고, 이후 connect가 완료되어 행이 등록된다. 백그라운드 앱이 최대 90초 동안 살아 있는 lease를 쥐고 있어 다른 기기의 종료만으로는 계정이 오프라인이 되지 않는다.

**8. `getServerSnapshot`이 `now: 0`을 반환 — `apps/web/src/lib/bambi/use-moderator-presence-stream.ts:92`**

`isUserOnline`이 `0 - lastActivityAt.getTime() < window`를 계산하므로 항상 참이 되어, SSR/하이드레이션 시점에 활동 기록이 있는 모든 사용자가 온라인으로 렌더된다. 지금은 사용자·출석 목록이 클라이언트 페치라 하이드레이션 시점에 행이 없어 드러나지 않을 뿐, 이 데이터를 prefetch하거나 SSR하는 순간 잘못된 상태가 깜빡인다. 서버 스냅샷에서 `Date.now()`를 쓰거나 오프라인으로 단락시키는 편이 안전하다.
