## 개요

사이트 전역 다크모드 작업 중 발견한 색상과 무관한 UI 크기·여백·배치 문제 4건을 별도 브랜치로 분리해 정리했다. 운영자 사용자 관리 선택 열, 공용 헤더 검색 버튼, 모바일 신고창, 운영자 공고 검수 상세 카드만 다루며 색상·다크모드 토큰과 기능 동작은 변경하지 않는다.

## 변경 내용

### 1. 운영자 사용자 관리 선택 열

- 선택 열에 출석 관리의 기존 `w-10`·`p-2`·`flex justify-center` 패턴을 재사용해 헤더·행 체크박스의 고정 여백과 중앙 정렬을 통일
- 사용자 테이블의 전역 `px-1`보다 선택 열의 `!p-2`가 우선하도록 해당 열만 복원
- 이름 열 사이 `border-r`은 추가하지 않고 테이블 wrapper·전체 폭·행 높이·다른 열 구성은 유지

### 2. 공용 헤더 검색 버튼

- 검색 트리거의 별도 `className="size-10"` override 제거
- 기존 `size="icon-lg"`만 남겨 해/달·채팅·알림 등 다른 헤더 아이콘 버튼과 같은 공용 Button 크기 사용
- 검색 Dialog·단축키·검색 결과 처리와 구직자·구인자·운영자 호출부는 변경하지 않음

### 3. 모바일 신고창 밀도

- 모바일 `DialogContent`에 기존 `w-80`·`gap-3`·`p-4` 토큰 적용
- 신고 폼의 모바일 제목·항목 간격·padding·상세 입력 높이를 기존 spacing 토큰으로 한 단계 축소
- 사유 항목은 `min-h-11`로 최소 44px 터치 높이를 유지하고 취소·접수 버튼은 2열로 배치
- `md` 이상에서는 기존 크기·간격·입력 높이를 유지하며 신고 사유·상태·서버 제출 로직은 무변경

### 4. 운영자 공고 검수 상세 카드 폭

- 공통 셸 경계까지 확장돼 헤더 콘텐츠의 좌우 기준선을 넘어가던 `QueueDetail` 데스크톱 카드에 `lg:mx-6` 적용
- 기존 헤더 내부 여백과 같은 토큰을 재사용해 신규 임의 px 없이 카드 외곽선을 헤더 콘텐츠 축에 정렬
- `APP_CONTENT_WIDTH`·`APP_CONTENT_MAX_W`, 다른 운영자 페이지의 공통 폭, 모바일 전체 폭, 카드 내부 padding과 검수 동작은 유지
