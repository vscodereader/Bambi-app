## 배경

PR #291에서 사용자 온라인 상태 정본과 운영자 실시간 표시를 추가했지만, 일반 채팅 화면의 `대화 가능`은 차단·탈퇴 여부만 보고 항상 표시됐고 `실시간 연결`은 상대 상태가 아닌 현재 브라우저 Socket.IO 연결만 나타냈습니다. 이 때문에 상대 구인자 또는 구직자가 오프라인이어도 두 성공 뱃지가 함께 보였습니다.

또한 공고·채팅의 지역·세부지역·업종은 `경기 · 성남시 · 룸싸롱 · 퍼블릭`처럼 한 문자열로 이어져 정보 구분과 모바일 가독성이 떨어졌습니다.

설계·구현 계획: `docs/superpowers/plans/2026-09-04-chat-presence-response-metadata-badges.md`

## 변경

- **응답시간 정본**: `chat_response_activity`를 추가해 배포 후 성공한 텍스트·첨부·면접·연락처 대화 액션을 기록합니다. 기존 이력은 백필하지 않으며 방 단위 advisory lock, identity 순번, 안정적인 activity key로 동시 발신과 재시도를 직렬화·멱등 처리합니다.
- **최근 30일 평균**: 상대 연속 액션 묶음의 첫 시각부터 내 첫 응답까지를 한 표본으로 계산합니다. 표본 1건부터 평균을 내며 10분·30분·60분·응답 낮음 구간으로 반환합니다. 30일이 지난 표본과 미응답 묶음은 제외합니다.
- **정확한 채팅 상태**: 양쪽 사용자가 모두 온라인일 때만 `대화 가능`, 양쪽 온라인이면서 현재 Web Socket.IO까지 connected일 때만 `실시간 연결`을 표시합니다. 상대가 오프라인이면 `오프라인`과 선택적인 평균 응답 뱃지로 교체합니다.
- **참여자 실시간 presence**: PR #291의 PostgreSQL listener와 presence 정본을 재사용합니다. 변경 사용자 본인과 현재 유효한 채팅 상대의 개인 socket room에만 최소 상태를 전달하고, 차단·신고·나간 방에는 상대 상태를 전달하거나 API로 노출하지 않습니다.
- **만료·복구**: 원본 마지막 활동 시각 대신 다음 정본 재조회 시각만 내려줍니다. 시간 만료, 운영자 정책 변경, listener 재연결에서 목록과 현재 방을 다시 읽어 새로고침 없이 상태를 복구합니다.
- **공고 메타데이터 뱃지**: 일반·수집 공고 상세, 실제 공고 카드, 검색 결과, 공개 랜딩, 구인자 공고 관리, 채팅 헤더를 공용 `JobMetadataBadges`로 통일했습니다. 광역지역은 green, 세부지역은 sky, 업종·세부업종은 연한 primary, 평균 응답은 warning 토큰을 사용합니다.
- **모바일 배치**: 모바일 채팅 정보 카드에서 상태 뱃지를 `공고 조건` 제목 옆이 아니라 시급 바로 위에 배치해 제목 줄바꿈을 막았습니다.
- **범위 제한**: Native 화면과 `apps/native` 파일은 변경하지 않았습니다. Native가 기존 공용 API로 만든 대화 액션은 플랫폼 공통 개인 통계에 포함됩니다.
