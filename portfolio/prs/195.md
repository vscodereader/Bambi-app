## 무엇을 개선했나
운영자가 수집 공고를 연속으로 편집·삭제할 때마다 페이지와 화면 위치를 다시 찾아야 했고, 여러 공고도 행별로 하나씩 삭제해야 했다. 수집 공고 목록의 상태·페이지·스크롤을 보존하고, 현재 페이지 범위의 Gmail식 선택 삭제를 추가해 연속 관리 흐름을 개선했다.

## 변경 내용

### 페이지·화면 위치 복귀
- 수집 공고 상태와 페이지를 `jobStatus`·`jobPage` URL 파라미터로 관리
- 이미지 편집 링크에 검증된 복귀 상태·페이지를 전달하고 저장·취소·변경 버리기 모두 같은 목록으로 복귀
- 편집 진입 직전 스크롤 위치를 세션에 보존해 목록 데이터 준비 후 한 번 복원
- 목록의 이전·다음 및 상태 탭 URL 변경에 `scroll: false` 적용
- `lastSeenAt` 동률 시 `id desc` 보조 정렬을 적용해 재조회마다 행이 바뀌던 비결정적 정렬 제거

### 현재 페이지 일괄 삭제
- 제목 왼쪽에 행 체크박스와 현재 페이지 전체 선택 헤더 체크박스 추가
- 선택 범위는 현재 페이지 최대 10개이며 페이지·상태 탭 변경 시 초기화
- 하나 이상 선택했을 때만 빨간 `선택 삭제 (N)` 버튼 노출
- 한 번 확인한 뒤 선택한 1~10개를 transaction 안에서 원자적으로 `removed` 처리
- 존재하지 않거나 이미 삭제된 ID가 섞이면 일부만 처리하지 않고 전체 롤백
- 삭제됨 행은 선택 대상에서 제외하고 삭제됨 탭의 기존 복구 동작 유지
- 전체 탭에서는 삭제된 공고를 맨 뒤로 정렬해 뒤의 정상 공고가 현재 페이지를 즉시 최대 10개로 충전
- 마지막 페이지가 사라지면 직전 유효 페이지로 자동 보정

### 공개 목록·문서
- 삭제 후 공개 전체공고 캐시도 함께 무효화
- 기존 공개 목록의 최초 48개·더보기당 48개·마지막 묶음만 48개 미만 계약 유지
- 운영자 매뉴얼, 운영자·구직자 테스트 플로우, 구현 설계서 동기화
- DB 스키마·Drizzle migration 변경 없음
