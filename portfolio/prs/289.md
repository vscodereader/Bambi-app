## 개요

웹 채팅에서 연락처 공개·면접 확정을 누르면 즉시 처리되던 흐름에 확인창을 추가한다. 확인창의 확인은 공개·확정, 취소는 실제 거절이며, 오른쪽 위 X는 요청 대기 상태를 유지한 채 창만 닫는다.

Closes #288

## 작업 내용

- **공용 확인창**(`chat-action-confirmation.tsx`): 기존 shadcn/base-ui AlertDialog·버튼·스타일 토큰을 조합해 연락처와 면접 확인창을 공유한다. 전달받은 실제 메시지·면접 ID를 사용한다.
- **연락처 공개**: “정말로 연락처를 공개하시겠습니까?” / “공개하시면 상대방에게 연락처가 공개됩니다.” 표시. 확인은 기존 `respondContactReveal(reveal)`, 취소는 `respondContactReveal(decline)` 호출.
- **면접 확정**: “정말로 면접을 진행하시겠습니까?” / “면접 수락시 반드시 시간을 준수해주시기 바랍니다.” 표시. 확인은 기존 `setInterviewStatus(confirmed)`, 취소는 기존 거절과 동일한 `declined` 호출. 채팅 카드·데스크톱 오른쪽 패널·모바일 채팅 정보 패널에 함께 적용.
- **창 닫기**: X는 서버 호출 없이 확인 대상 상태만 비운다. 기존 요청은 대기 상태로 남고, 다시 공개·확정을 누르면 확인창이 열린다. 요청 카드의 직접 거절 및 이미 확정된 면접의 취소는 기존 동작을 유지한다.
- **요청 처리**: 제출 중 확인·취소·닫기를 비활성화하고, 실패하면 확인창을 유지한다. 기존 오류 표시·채팅 조회 갱신·예정된 면접 갱신을 재사용한다.
- **문서**: 구직자 매뉴얼에 확인·실제 거절·창만 닫기의 차이를 반영한다.
