# 운영자 쪽지 브라우저 테스트 플로우

대상: 운영자 쪽지 발송(`/moderator/messages`) · 회원 쪽지함(`/seeker/me/messages`) · 알림 연동.
전제: dev 서버(web, http://localhost:23001)가 이미 떠 있고 dev DB에 0112 마이그레이션 적용됨.
계정: `apps/server/src/seeds/bambi-dev.ts`의 시드 계정 사용(운영자·구직자·구인자·법률자문가).
비로그인 접근은 `/welcome`으로 리다이렉트되므로 각 시나리오는 로그인부터 시작한다.

## A. 운영자 발송

1. **진입**: 운영자 로그인 → 내비 "회원 관리 > 쪽지"(모바일은 더보기 시트)로 `/moderator/messages` 진입. 작성 카드·발송 이력 카드가 보인다.
2. **개별 발송**: 사용자 검색에 구직자 시드 이름 일부 입력 → 후보(최대 8행)에서 선택 → Badge로 추가됨 → 제목·본문 입력 → 발송 → "…에게 발송할까요?" 확인 다이얼로그 → 확인 → 성공 토스트("쪽지 N명에게 발송 완료") → 폼 리셋 → 발송 이력 최상단에 새 행(대상 "개별 지정", 읽음 0/1).
3. **역할 발송**: "구직자(법률자문 포함) 전체" 체크 → 발송·확인 → 이력 대상 "구직자 전체".
4. **혼합 발송**: 구인자 체크 + 구직자 1명 개별 선택 → 발송 → 이력에 정상 기록, 읽음 분모가 (구인자 전원 + 1) 이상.
5. **users 진입점**: `/moderator/users`에서 구직자 행 "쪽지" 버튼 → `/moderator/messages?to=<id>` 이동, 해당 사용자가 선택 목록에 프리셋됨.
6. **발송 유효성**: 대상이 하나도 없으면 발송 버튼 disabled. 제목 또는 본문이 비면 발송 불가.
7. **발송 상세**: 이력 행 클릭 → Dialog에 본문 + 수신자별 읽음/안읽음 목록. 헤드라인 수신자 수가 이력의 분모와 일치.

## B. 수신자 (구직자 기준, 13~14에서 타 역할 반복)

8. **알림 도착**: A-2 발송 직후 구직자 로그인 → 헤더 벨 배지 증가, 알림함에 "운영자 쪽지가 도착했어요"(본문=쪽지 제목).
9. **딥링크**: 그 알림 클릭 → `/seeker/me/messages` 착지.
10. **읽음 처리**: 내 정보 → "쪽지함" 메뉴(안읽음 배지 수 표시) → 목록에서 안읽음 표시("새 쪽지") 확인 → 행 클릭 → 상세 Dialog(제목·본문·발송 시각) → 닫은 뒤 안읽음 표시·배지 감소. 운영자 발송 이력의 읽음 수가 1 증가했는지 교차 확인.
11. **보관**: 상세에서 보관 → "받은 쪽지" 탭에서 사라지고 "보관함" 탭에 존재 → 보관 해제 → 받은 쪽지로 복귀.
12. **삭제**: 삭제 → 확인 다이얼로그("쪽지를 삭제할까요?") → 목록에서 사라짐. 운영자 발송 이력의 수신·읽음 통계는 그대로(소프트 삭제).
13. **구인자 수신**: 구인자 로그인 → A-4 쪽지가 쪽지함에 보이고 알림도 도착.
14. **법률자문가 수신**: 법률자문가 로그인 → A-3(구직자 전체) 쪽지가 쪽지함에 보인다.
15. **운영자 메뉴 숨김**: 운영자 계정으로 `/seeker/me` → 메뉴·허브 카드에 "쪽지함" 항목이 없다.

## C. 엣지 케이스

16. **실시간 배지**: 구직자로 `/seeker/me`(쪽지함 메뉴 보이는 화면)를 열어둔 채, 다른 브라우저 컨텍스트에서 운영자가 그 구직자에게 발송 → 새로고침 없이 벨 배지·쪽지함 메뉴 배지가 갱신된다(SSE 무효화).
17. **운영자 수신 차단**: 개별 지정 검색에 운영자 계정 이름 입력 → 후보에 나오지 않는다. `/moderator/users`의 운영자 행에는 "쪽지" 버튼이 없다.
18. **입력 상한·이스케이프**: 제목 100자·본문 2000자 초과 입력이 막힌다(maxLength 또는 발송 거부). 본문에 `<script>alert(1)</script>` 포함 발송 → 수신 상세에서 문자 그대로 렌더(스크립트 미실행), 줄바꿈 유지.
19. **발송 이력 더 보기**: 이력이 20건 넘는 상태(테스트 중 발송 누적 활용)에서 "더 보기" 버튼으로 다음 페이지 로드. 20건 이하라 확인 불가면 스킵하고 보고에 명시.
20. **모바일 반응형**: 375px 뷰포트에서 쪽지함(탭·목록·상세)·운영자 패널(작성·이력 세로 스택)·더보기 시트 "쪽지" 항목이 깨짐 없이 동작.
21. **빈 상태**: 쪽지가 없는 계정의 받은 쪽지/보관함 탭에 각각 "도착한 쪽지가 없어요"/"보관한 쪽지가 없어요".

## 판정 기준

- 각 항목은 실제 화면 조작으로 확인하고 통과/실패/스킵(사유)을 기록한다.
- 실패 시 콘솔 에러·네트워크 응답을 함께 수집한다. 코드 수정은 하지 않는다.
