## 판정의 전제 — 먼저 이것부터 확인

dev DB의 사이트 설정에 사업자 정보가 **비어 있으면** `BAMBI_COMPANY`의 `TODO_` 폴백이 나오는 것이 정상 동작이다. 그 상태에서는 A-1을 판정할 수 없다. 따라서 다음 3자를 구분해야 한다.

| 초기 HTML | JS 렌더 후 화면 | 판정 |
|---|---|---|
| 실값 | 실값 | **통과** — SSR 주입 동작 |
| `TODO_` | 실값 | **실패** — 주입이 안 됨(수정 전 증상) |
| `TODO_` | `TODO_` | **판정 불가** — dev DB에 값 자체가 없음. 이 경우 SKIP하고 보고에 명시 |

초기 HTML은 `fetch(url, {cache:'no-store'})`로 **문서 응답 원문**을 받아 확인한다(화면 렌더 결과가 아니다).

## 판정·보고 규칙

- 각 ID를 통과/실패/스킵(사유)으로 기록한다. 실패는 재현 절차·기대·실제·근거를 남긴다.
- **코드는 수정하지 않는다.** 발견만 보고한다.
- 공고를 새로 등록하거나 검수 상태를 바꾸지 않는다 — 문구는 화면 진입만으로 확인된다.
- 로그인은 사람이 한다(비밀번호 입력 금지). H 구간은 필요한 역할로 로그인된 뒤에 실행한다.
