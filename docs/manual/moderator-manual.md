## 1. 이 매뉴얼과 운영자 역할

밤비는 아르바이트 구인·구직을 연결하는 플랫폼입니다. 운영자는 이 플랫폼에서 오가는 공고, 후기, 채팅, 사용자, 업소 정보를 점검해 서비스가 안전하고 신뢰할 수 있게 유지하는 역할을 맡습니다.

운영자가 콘솔에서 주로 하는 일은 다음과 같습니다.

- **공고 검수**: 게시 전 대기 중인 공고를 확인해 게시할지 반려할지 결정합니다.
- **신고 처리**: 사용자가 접수한 신고(공고·채팅방·채팅 메시지·후기·사용자 대상)를 검토하고 조치합니다.
- **업소 승인**: 구인자가 제출한 업소 인증 서류를 확인해 승인하거나 반려합니다.
- **후기 관리**: 후기를 게시·복원하거나 숨깁니다.
- **사용자 관리**: 문제 사용자에게 경고·정지·차단 등 제재를 적용합니다.
- **사이트 정보 관리**: 서비스 푸터에 노출되는 사업자 정보와 무통장입금 계좌를 관리합니다.
- **광고 상품 관리**: 구인자가 공고를 홍보하는 데 쓰는 유료 광고의 노출 위치와 상품·가격을 등록·관리합니다.

이 매뉴얼은 실제 화면에 보이는 메뉴명·버튼명·한글 라벨만 사용합니다. 화면과 표현이 일치하므로, 안내된 이름 그대로 화면에서 찾으시면 됩니다.

## 2. 운영자 콘솔 접속

### 접속 조건

- 운영자 콘솔은 **운영자 권한이 부여된 계정으로 로그인**해야만 들어갈 수 있습니다.
- 로그인하지 않은 상태로 콘솔 주소에 접근하면 시작(환영) 화면으로 이동됩니다.
- 운영자가 아닌 일반 계정(구직자·구인자)으로 접근하면 각자의 홈 화면으로 자동 이동되며, 콘솔은 열리지 않습니다.

즉, 콘솔 화면이 열린다는 것 자체가 현재 계정이 운영자 권한을 가지고 있다는 뜻입니다.

### 화면 구성과 이동

콘솔에 들어오면 화면 위쪽(또는 모바일에서는 아래쪽 탭)에 메뉴가 보입니다. 운영자 콘솔의 주요 메뉴는 다음과 같습니다.

- **검수 큐**: 게시 대기 중인 공고 검수
- **신고**: 접수된 신고 처리
- **사용자**: 사용자 계정 관리·제재
- **업소 승인**: 업소 인증 심사
- **후기 관리**: 후기 게시·숨김 관리
- **광고 상품**: 광고 노출 위치·상품·가격 관리
- **사이트 정보**: 푸터 사업자 정보·무통장입금 계좌 편집
- **채용정보**: 일반 사용자가 보는 채용 목록 화면(운영자가 실제 사용자 화면을 확인할 때 사용)

화면 오른쪽 위에는 현재 운영자 모드임을 알리는 **운영자 모드** 표시가 항상 떠 있습니다.

> 참고: 넓은 화면(PC)에서는 위쪽 메뉴 막대에 위 메뉴가 나열되며, 승인 관리·광고·결제 등은 묶음 메뉴로 펼쳐집니다. 좁은 화면(모바일)에서는 아래쪽 탭에 검수·신고·사용자·후기·광고 상품이 표시되고, 나머지 메뉴(업소 승인·결제 관리·**사이트 정보** 등)는 오른쪽 끝 **더보기** 탭을 눌러 열리는 목록에서 이동합니다. 더보기를 다시 누르면(표기가 **닫기**로 바뀝니다) 목록이 닫힙니다.

## 3. 화면별 업무 안내

### 3.0 콘솔 요약 현황(상단 헤더)

**언제 보나요**

검수 큐·신고·사용자 등 목록 화면 위쪽에는 항상 **운영자 콘솔** 제목과 함께 현재 처리량을 요약한 숫자 세 개가 표시됩니다. 하루 업무를 시작할 때 밀린 일이 얼마나 있는지 한눈에 파악하는 용도입니다.

- **검수 대기**: 게시를 기다리는 공고 수(검수 큐에 남아 있는 건수)
- **신고 대기**: 아직 처리하지 않은 신고 수
- **경고 사용자**: 현재 경고 상태인 사용자 수

이 숫자는 실제 처리 현황에 따라 자동으로 갱신됩니다. 별도의 조작은 없으며, 각 숫자가 가리키는 화면으로 이동해 실제 처리를 진행하시면 됩니다.

---

### 3.1 검수 큐

**언제 사용하나요**

구인자가 올린 공고 중 **아직 게시되지 않고 검수를 기다리는 공고**를 확인하고, 게시할지 반려할지 결정할 때 사용합니다.

**목록에서 보이는 정보**

각 공고 줄에는 업소명, 업종, 위험도 배지(위험: 높음/중간/낮음), 자동으로 잡힌 감지 문구, 접수 시각과 공고 번호가 표시됩니다.

목록 위에는 두 개의 선택 상자가 있습니다.

- **상태 필터**: 전체 상태 / 높은 위험 / 중간 위험 / 낮은 위험 중에서 골라 위험도별로 걸러 볼 수 있습니다.
- **정렬**: 회신순(먼저 접수된 공고부터) / 최신순 / 위험도순 중에서 정렬 방식을 바꿀 수 있습니다.

**한 건씩 처리하는 절차**

1. 목록에서 검수할 공고 줄을 누릅니다.
2. **공고 검수** 화면이 열리면 제목·업소·지역·급여·접수 시각을 확인합니다.
3. **자동 필터가 감지한 신호** 영역에서 시스템이 표시한 위험 신호(예: 위험 표현 감지, 블록 위험어, 공고 구성 등)를 확인합니다.
4. **공고 본문**에서 감지된 표현이 색으로 강조되어 있으니, 실제 문맥을 읽어 문제 여부를 판단합니다.
   - 판단 기준 안내가 화면 하단에 표시됩니다: 성적 서비스 암시·강요·외부 연락 유도는 반려, 단순 오해 소지는 승인 후 안내합니다.
5. 문제가 없으면 **승인 후 게시**를 누릅니다. 공고가 즉시 게시됨 상태가 되고 목록에서 사라집니다.
6. 문제가 있으면 **반려**를 누릅니다.
   - **반려 사유 선택** 창이 뜨면 사유(성적 서비스 암시 표현 / 강요·착취 의심 조건 / 외부 연락 유도 / 허위·과장 정보 / 기타 정책 위반) 중 하나를 고르고 **반려하기**를 누릅니다.
   - **선택한 사유는 구인자에게 그대로 전달**됩니다. 신중하게 선택하세요.

**여러 건을 한 번에 처리하는 절차(일괄 처리)**

1. 목록에서 각 공고 줄 왼쪽의 선택 칸을 눌러 처리할 공고를 여러 개 선택합니다.
2. 화면 아래에 나타나는 처리 막대에서 **반려 / 보류 / 승인** 중 하나를 누릅니다.
   - **승인**: 선택한 공고를 모두 게시합니다.
   - **반려**: 선택한 공고를 모두 반려합니다.
   - **보류**: 선택한 공고를 목록에서 잠시 내려 보류합니다.
3. **처리 사유**를 입력하는 창이 뜹니다. 기본 문구가 채워져 있으며, 필요하면 수정합니다. (사유는 두 글자 이상 입력해야 합니다.)
4. **적용**을 누르면 처리됩니다. 처리 후 성공·실패 건수가 안내됩니다.

**처리하면 무슨 일이 일어나나요**

- 승인한 공고는 게시됨 상태가 되어 일반 사용자에게 노출됩니다.
- 반려한 공고는 반려 상태가 되고, 선택·입력한 반려 사유가 구인자에게 전달됩니다.
- 모든 처리는 기록으로 남습니다(아래 [처리 원칙과 주의사항](#5-처리-원칙과-주의사항) 참고).

### 3.2 신고 처리

**언제 사용하나요**

사용자가 접수한 신고를 검토하고 조치할 때 사용합니다. 신고 대상은 공고, 채팅방, 채팅 메시지, 후기, 사용자입니다.

**목록에서 보이는 정보**

- 아직 처리하지 않은 신고가 위쪽에, 이미 처리한 신고는 아래 **처리 완료** 구역에 흐리게 표시되며 **완료** 표시가 붙습니다.
- 각 줄에는 중요도 표시(심각/주의/참고), 신고 사유, 접수 시각, 신고 대상과 신고자, 신고 내용 요약이 보입니다.
- 신고자는 표시명(없으면 이메일)과 역할(구직자/구인자/운영자)로, 피신고 대상은 유형에 맞는 이름과 역할로 표시됩니다. 사용자 대상은 표시명과 역할, 공고는 공고 제목과 "공고", 채팅방은 연결된 공고 제목과 "채팅방"으로 보입니다. 후기·채팅 메시지처럼 이름을 특정하기 어려운 대상은 대상 번호를 축약(예: `#a1b2c3d4`)해 표기하고 역할 자리에 유형(후기·채팅 메시지 등)을 표시합니다.

**처리 절차**

1. 목록에서 신고 줄을 누르면 **신고 검토** 화면이 열립니다.
2. 상단의 두 상자에서 피신고 대상과 신고자를 확인합니다. 각 상자에는 이름(실명·표시명, 없으면 이메일이나 대상 번호 축약)과 역할이 함께 표시됩니다.
3. 신고 대상 유형에 맞춰 아래 정보를 확인합니다(유형별 안내는 다음 항목 참고).
4. 판단이 서면 아래 조치 중 하나를 선택합니다.
   - **기각**: 정책 위반으로 보기 어려운 경우 신고를 종료합니다.
   - **제재 적용**: 사용자가 대상인 신고에서 조치가 필요할 때 누릅니다. **제재 수단 선택** 창에서 경고 보내기 / 이용 정지(7일) 중 하나를 고르면, 이어서 **사유 작성 창**이 열립니다. 기본 문구가 미리 채워져 있으니 상황에 맞게 수정한 뒤(두 글자 이상) 확정합니다. (사유 작성 창에서 **취소**를 누르면 제재 수단 선택으로 돌아갑니다.)
   - **조치 완료**: 사용자가 아닌 대상(공고·후기·채팅 등) 신고는 사용자 제재 대신 **조치 완료**로 마무리합니다. 해당 대상의 사용자 제재가 필요하면 **사용자 관리** 화면에서 진행합니다.
5. 이미 처리된 신고를 열면 **이미 처리된 신고예요** 안내가 표시되고, 별도 조치 버튼은 나타나지 않습니다.

**신고 대상 유형별로 확인·조치할 수 있는 것**

- **공고 신고**: 신고된 공고의 제목, 업소명, 현재 상태, 공고 본문 일부, (반려된 공고라면) 반려 사유를 확인할 수 있습니다.
- **후기 신고**: 신고된 후기의 별점, 현재 상태, 본문을 확인할 수 있습니다.
- **사용자 신고**: 신고된 사용자의 표시명, 역할, 계정 상태, 전화 인증 여부(인증 완료/미인증)를 확인할 수 있습니다.
- **채팅방 신고**: 신고된 대화방의 연결 공고 제목과 현재 상태(정상/차단됨)를 확인하고, **최근 메시지**를 열람할 수 있습니다. 아래에서 사유를 두 글자 이상 입력한 뒤 **방 차단**(또는 이미 차단된 방이면 **차단 해제**)을 눌러 대화방을 차단하거나 해제할 수 있습니다.
- **채팅 메시지 신고**: 신고된 메시지 내용과 첨부 정보를 대화 형태로 확인할 수 있습니다.

**처리하면 무슨 일이 일어나나요**

- 기각한 신고는 종료 처리되어 처리 완료 구역으로 내려갑니다.
- 채팅방을 차단하면 해당 대화방이 차단됨 상태가 되고, 차단 해제 시 정상으로 돌아옵니다.
- 모든 조치는 사유와 함께 기록으로 남습니다.

### 3.3 업소 승인

**언제 사용하나요**

구인자가 제출한 **업소 인증 서류를 심사**할 때 사용합니다. 인증이 완료된 업소만 정상적인 구인 활동을 할 수 있으므로, 제출된 정보를 확인해 승인 또는 반려합니다.

**화면 구성**

- 위쪽 탭으로 상태별로 걸러 볼 수 있습니다: 전체 / 대기 / 승인 / 반려 / 미제출. (처음 들어오면 **대기** 상태가 선택되어 있습니다.)
- 각 업소 카드에는 업소명, 현재 인증 상태 배지(미제출/승인 대기/승인 완료/반려), 담당자 이메일과 사업자 등록번호, 대표자와 개업일자, 국세청 확인 결과, (반려된 적이 있으면) 반려 사유가 표시됩니다.
- **국세청 확인**은 구인자가 정보를 제출할 때 국세청에 조회한 결과입니다.
  - **국세청 확인 완료** — 사업자 등록번호·대표자·개업일자가 국세청 등록 정보와 일치했다는 뜻이며, 옆에 사업자 상태(계속사업자)와 확인한 시각이 함께 표시됩니다.
  - **국세청 미확인** — 조회를 하지 못한 채 접수된 제출입니다. 정보가 틀렸다는 뜻은 아니지만 대조가 안 된 상태이므로, **사업자등록증을 수동으로 확인**한 뒤 승인 여부를 정해 주세요.

**처리 절차**

1. **대기** 탭에서 심사할 업소를 확인합니다.
2. 업소명·이메일·사업자 등록번호·대표자·개업일자 등 제출 정보와 국세청 확인 결과를 검토합니다. **국세청 미확인**이면 사업자등록증을 직접 대조합니다.
3. 서류에 문제가 없으면 **승인**을 누릅니다. 업소 상태가 승인 완료로 바뀝니다.
4. 서류에 문제가 있으면, 카드 안의 사유 입력란에 반려 사유를 적은 뒤 **반려**를 누릅니다.
   - 반려 사유는 **두 글자 이상** 입력해야 **반려** 버튼이 활성화됩니다.
   - 입력한 반려 사유는 기록으로 남고, 해당 업소 카드에 반려 사유로 표시됩니다.
5. 처리가 끝나면 "처리했어요" 안내가 표시되고 목록이 갱신됩니다.

**처리하면 무슨 일이 일어나나요**

- 승인한 업소는 승인 완료 상태가 됩니다.
- 반려한 업소는 반려 상태가 되며, 입력한 사유가 함께 기록·표시됩니다.

### 3.4 후기 관리

**언제 사용하나요**

작성된 후기를 점검해 **게시 상태를 조정**할 때 사용합니다. 부적절한 후기를 숨기거나, 숨겼던 후기를 다시 게시할 때 사용합니다.

**화면 구성**

- 위쪽 탭으로 상태별로 걸러 볼 수 있습니다: 전체 / 게시됨 / 검수 대기 / 숨김.
- 각 후기 카드에는 별점, 현재 상태 배지(게시됨/검수 대기/숨김), 작성 시각, 연결된 공고 제목, 업소명, 작성자(익명이면 "익명"), 후기 본문이 표시됩니다.

**처리 절차**

1. 상태 탭에서 점검할 후기를 찾습니다.
2. 후기 내용을 확인합니다.
3. 조치를 선택합니다.
   - 게시하려면(또는 숨겼던 후기를 되살리려면) **게시** 또는 **게시 복원**을 누릅니다.
   - 부적절하면 **숨김**을 누릅니다.
   - (이미 게시된 후기에는 숨김만, 이미 숨긴 후기에는 게시 복원만 표시됩니다.)
4. 조치를 누르면 카드 안에 **사유 입력란**이 나타납니다. 사유를 두 글자 이상 입력합니다.
5. **확정**을 누릅니다. "후기 상태를 변경했어요" 안내가 표시됩니다.
6. 잘못 눌렀다면 **취소**로 되돌릴 수 있습니다.

**처리하면 무슨 일이 일어나나요**

- 게시(복원)한 후기는 게시됨 상태가 되어 노출됩니다.
- 숨긴 후기는 숨김 상태가 되어 노출되지 않습니다.
- 입력한 사유는 기록으로 남습니다.

### 3.5 사용자 관리

**언제 사용하나요**

문제가 되는 사용자 계정을 확인하고 **경고·정지 등 제재를 적용**할 때 사용합니다.

**목록에서 보이는 정보**

각 사용자 줄에는 이름, 현재 계정 상태 배지(정상/경고/정지), 역할(구직자/구인자/운영자), 누적 신고 건수, 경고 횟수가 표시됩니다.

**한 명씩 처리하는 절차**

1. 목록에서 사용자 줄을 누르면 **사용자 상세** 화면이 열립니다.
2. 이름·역할·가입일·현재 상태와 함께 누적 신고, 경고 횟수, 계정 관련 안내(전화 인증 여부 등)를 확인합니다.
3. **제재 적용** 영역에서 조치를 선택합니다.
   - **경고 보내기**: 정책 안내와 함께 경고를 1회 누적합니다.
   - **이용 정지 (7일)**: 일정 기간 동안 공고·채팅 이용을 막습니다.
4. 조치를 고르면 **사유 작성 창**이 열립니다. 기본 문구가 미리 채워져 있으며, 상황에 맞게 수정할 수 있습니다. (사유는 두 글자 이상 입력해야 합니다.)
5. **경고 보내기**(또는 **이용 정지**) 버튼을 눌러 확정하면 조치가 적용되고, 처리 결과가 짧게 안내됩니다. 잘못 눌렀다면 **취소**로 되돌릴 수 있습니다.

**이용 정지를 해제하고 정상으로 되돌리는 절차**

**이용 정지** 상태인 사용자의 상세 화면에만 제재 적용 영역 위에 **계정 상태 복구** 영역이 표시됩니다. (정상·경고 상태인 사용자에게는 나타나지 않습니다.)

경고는 별도 해제 절차가 필요하지 않습니다. 사용자가 경고 안내 배너를 직접 X로 닫는 방식이며, 운영팀이 새 경고를 보내면 사용자에게 배너가 다시 표시됩니다.

1. 목록에서 정지 상태인 사용자 줄을 눌러 **사용자 상세** 화면을 엽니다.
2. **계정 상태 복구** 영역에서 현재 이용 정지 상태임을 확인합니다.
3. 제재 사유가 해소되어 계정을 되돌려도 된다고 판단되면 **정상으로 복구**를 누릅니다.
4. 계정 상태가 정상으로 바뀌고, 처리 결과가 짧게 안내됩니다. 그동안 쌓인 경고 횟수는 그대로 유지됩니다.

**여러 명을 한 번에 처리하는 절차(일괄 처리)**

1. 목록에서 사용자 줄 왼쪽의 선택 칸으로 여러 명을 선택합니다.
2. 화면 아래 처리 막대에서 **경고** 또는 **정지**를 누릅니다.
3. **처리 사유**를 두 글자 이상 입력하고 **적용**을 누릅니다. 처리 후 성공·실패 건수가 안내됩니다.

**처리하면 무슨 일이 일어나나요**

- 경고를 보내면 사용자가 경고 상태가 되고 경고 횟수가 1 올라갑니다.
- 이용 정지를 적용하면 해당 사용자의 계정 상태가 바뀌어 활동이 제한됩니다.
- 모든 제재는 사유와 함께 기록으로 남습니다.

### 3.6 사이트 정보

**언제 사용하나요**

서비스 화면 맨 아래(푸터)에 노출되는 **사업자 정보**와, 구인자 결제 안내에 노출되는 **무통장입금 계좌**를 관리할 때 사용합니다. 상단(또는 모바일 메뉴)의 **사이트 정보** 메뉴로 들어갑니다.

**화면 구성**

주요 카드는 다음과 같습니다.

- **푸터 사업자 정보**: 서비스 소개 문구, 상호(운영 주체), 대표자, 사업자등록번호, 고객문의 이메일, 사업장 주소.
- **개인정보 처리방침 연락처**: 개인정보 처리방침 페이지에 노출되는 결제대행사·문자발송사 수탁사명과 개인정보 관리부서의 전화·메일.
- **무통장입금 계좌**: 결제 안내에 노출할 계좌 목록(은행명·계좌번호·예금주)을 행 단위로 편집.

**푸터 사업자 정보 편집 절차**

1. 각 입력란에 값을 채웁니다. **비워 두면 회색 안내 문구로 표시된 기본값이 대신 노출**됩니다. 값을 지우면 해당 항목은 기본값으로 되돌아갑니다.
2. 고객문의 이메일은 이메일 형식을 검사합니다. 형식이 맞지 않으면 저장되지 않고 "올바른 이메일 형식이 아닙니다." 안내가 표시됩니다.
3. **저장**을 누르면 "사이트 정보를 저장했어요." 안내가 뜨고, 저장한 값이 곧바로 서비스 푸터에 반영됩니다.

**개인정보 처리방침 연락처 편집 절차**

1. 결제대행사(수탁사명)·문자발송사(수탁사명)·관리부서 전화·관리부서 메일 네 항목을 입력합니다. 각 항목을 **비워 두면 회색 안내 문구로 표시된 기본값이 대신 노출**됩니다.
2. 관리부서 메일은 이메일 형식을 검사합니다. 형식이 맞지 않으면 저장되지 않고 "올바른 이메일 형식이 아닙니다." 안내가 표시됩니다.
3. **저장**을 누르면 "개인정보 처리방침 연락처를 저장했어요." 안내가 뜨고, 저장한 값이 개인정보 처리방침 페이지의 위탁사명·관리부서 연락처에 반영됩니다.

**무통장입금 계좌 편집 절차**

1. **계좌 추가**를 눌러 행을 추가하고 은행명·계좌번호·예금주를 입력합니다. 세 항목 모두 필수이며, 세 항목이 전부 비어 있는 행은 저장 시 자동으로 제외됩니다. 계좌는 최대 10개까지 등록할 수 있습니다.
2. 필요 없는 계좌는 해당 행의 **삭제**로 뺍니다.
3. **계좌 저장**을 누르면 "무통장입금 계좌를 저장했어요." 안내가 표시됩니다.

**처리하면 무슨 일이 일어나나요**

- 여기서 저장한 계좌는 **구인자의 공고 결제 화면과 광고 관리의 "입금 안내"에 그대로 노출**됩니다. 등록된 계좌가 없으면 결제 안내는 고객센터 문의 문구로 대체되므로, 계좌 정보를 항상 최신 상태로 유지하세요.
- 현재 신용카드 결제는 "준비중"으로 안내되어 유료 공고는 신용카드로 제출할 수 없습니다. 유료 결제는 무통장입금으로 이뤄지며, 입금 확인 후 공고 게시 처리는 **결제 관리** 화면에서 진행합니다.
- **프리미엄 배너 광고는 전체 10자리로 제한됩니다.** 결제 관리(또는 검수 상세의 결제 패널)에서 프리미엄 배너 공고를 **결제완료 처리**할 때, 이미 10자리가 모두 노출 중이면 승인이 거부되고 "정원이 가득 차 승인할 수 없다"는 안내가 표시됩니다. 앞선 광고가 만료돼 자리가 나면 다시 결제완료 처리할 수 있습니다. 일괄 결제완료 처리 시에는 정원 안에 드는 건만 성공하고 초과분은 실패로 집계되며(성공·실패 건수와 사유 안내), 실패한 건은 자리가 난 뒤 다시 처리하세요. (정원 승인은 무통장입금 도착 순서대로 처리하면 되며, 대기열 순서를 강제하지는 않습니다.)

### 3.7 광고 상품 관리

**언제 사용하나요**

구인자가 공고를 홍보하는 데 쓰는 유료 광고 상품을 관리할 때 사용합니다. 광고가 노출되는 위치와, 그 위치에서 판매하는 상품·가격을 등록·수정하고 켜고 끌 수 있습니다. 상단(또는 모바일 **더보기** 메뉴)의 **광고 상품** 메뉴로 들어갑니다.

**화면 구성**

- 상단의 **위치 추가**로 새 노출 위치를 만듭니다. 각 위치 카드에는 위치 이름, 유형 배지(배너/리스팅), 노출 켜기/끄기 스위치, 수정·삭제 버튼이 있습니다.
- 위치 카드 안에는 그 위치에서 판매하는 광고 상품이 나열됩니다. 각 상품에는 상품명, 노출 켜기/끄기 스위치, 수정·삭제 버튼과 함께 이용 기간별 가격이 표시됩니다.
- **이 위치에 상품 추가**로 해당 위치에 새 상품을 등록합니다.

**상품 등록·수정과 가격 옵션별 할인율**

상품 등록/수정 화면에서는 상품명·한 줄 소개·노출 영역·서비스 내용과 함께 **가격 옵션(이용기간 · 금액 · 할인율)**을 설정합니다.

1. 가격 옵션마다 이용 기간(일)·금액(원)·**할인율(%)**을 입력합니다. **가격 옵션 추가**로 기간별 옵션을 늘릴 수 있으며, 같은 이용 기간은 중복으로 등록할 수 없습니다.
2. 할인율은 **0~100 사이 정수**입니다. 비워 두거나 0이면 할인 없이 원가만 노출됩니다.
3. 할인율을 넣으면 구인자 화면에서 해당 기간 옵션이 **원가 취소선 + 할인가 + "N% 할인"** 형태로 표시됩니다. 할인가는 10원 단위로 내림합니다.

## 4. 상태·뱃지 용어 사전

화면 곳곳에 나오는 한글 라벨의 의미를 정리했습니다.

### 공고 상태

| 라벨 | 의미 |
| --- | --- |
| 작성 중 | 구인자가 아직 작성 중인 공고 |
| 검수 대기 | 게시 전 운영자 검수를 기다리는 공고 |
| 게시됨 | 검수를 통과해 노출 중인 공고 |
| 숨김 | 노출에서 내려간 공고 |
| 반려 | 검수에서 반려된 공고 |

### 후기 상태

| 라벨 | 의미 |
| --- | --- |
| 게시됨 | 노출 중인 후기 |

## 5. 처리 원칙과 주의사항

- **모든 조치에는 사유가 필요합니다.** 공고 일괄 처리, 신고 조치, 후기 상태 변경, 채팅방 차단, 사용자 제재(개별·일괄) 등에서 사유 입력이 요구되며, 사유는 **두 글자 이상** 입력해야 처리가 진행됩니다.
- **모든 조치는 기록으로 남습니다.** 운영자가 누른 승인·반려·제재·차단 등은 사유와 함께 감사 기록으로 저장됩니다. 화면의 사유 입력란에도 "조치 사유는 감사 로그에 남아요"라고 안내됩니다. 조치는 되돌리기 번거로운 결과를 남길 수 있으므로 신중하게 판단하세요.
- **공고 반려 사유는 구인자에게 전달됩니다.** 검수 큐에서 반려할 때 고른 사유는 구인자에게 그대로 전해지므로, 오해가 없도록 정확한 사유를 선택하세요.
- **일괄 처리 결과를 확인하세요.** 여러 건을 한 번에 처리하면 성공·실패 건수가 안내됩니다. 실패한 건이 있으면 개별적으로 다시 확인하세요.
- **처리 전 대상 정보를 충분히 확인하세요.** 특히 신고 처리와 사용자 제재는 대상에게 직접적인 영향을 주므로, 신고 상세와 대상 맥락(공고 본문, 최근 메시지, 계정 상태 등)을 확인한 뒤 조치합니다.

## 6. 자주 묻는 질문

**Q. 검수 큐에 어떤 공고가 올라오나요?**
게시 전 검수를 기다리는 공고가 올라옵니다. 승인하면 게시되고, 반려하면 구인자에게 반려 사유가 전달됩니다.

**Q. 반려한 공고의 사유는 어디로 가나요?**
반려 시 선택한 사유가 구인자에게 그대로 전달됩니다. 또한 해당 공고에 반려 사유로 표시됩니다.

**Q. 신고를 잘못 눌러 처리했습니다. 취소할 수 있나요?**
후기 상태 변경 등 일부 화면에서는 사유 입력 단계에서 **취소**로 되돌릴 수 있습니다. 다만 이미 확정된 조치는 기록으로 남으므로, 필요하면 반대 조치(예: 숨김 → 게시 복원, 차단 → 차단 해제)로 상태를 되돌립니다.

**Q. 채팅방 신고는 어떻게 처리하나요?**
신고 검토 화면에서 해당 대화방의 최근 메시지를 확인한 뒤, 사유를 입력하고 방 차단 또는 차단 해제를 적용합니다.

**Q. 사유를 입력했는데 처리 버튼이 눌리지 않습니다.**
사유는 두 글자 이상 입력해야 처리가 활성화됩니다. 공백만 입력한 경우에도 처리되지 않으니 실제 사유를 적어 주세요.

**Q. 요약 현황의 숫자는 어떻게 갱신되나요?**
검수·신고·제재를 처리하면 상단의 검수 대기·신고 대기·경고 사용자 숫자가 자동으로 반영됩니다. 별도로 새로고침할 필요는 없습니다.

**Q. 모바일에서 후기 관리 화면은 어디 있나요?**
좁은 화면(모바일)의 아래쪽 탭에 검수·신고·사용자·후기·광고 상품이 표시됩니다. **후기** 탭에서 이용하세요. (업소 승인·사이트 정보 등은 오른쪽 끝 **더보기** 탭에서 찾을 수 있습니다.)
