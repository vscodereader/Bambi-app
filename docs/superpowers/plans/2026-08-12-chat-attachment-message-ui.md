# 채팅 사진·PDF 메시지 UI 및 동시 전송 개선 설계

## 작업 기준

- 최신 `origin/develop`의 `9014e654`에서 생성한 `fix/chat-attachment-message-ui` 브랜치에서 진행한다.
- 기존 `fix/test-site-qa-issues` PR의 변경과 분리해 새 이슈와 새 PR로 올린다.
- 구직자와 구인자가 공통으로 사용하는 채팅 화면에 동일하게 적용한다.
- 새로운 혼합 메시지 종류를 만들지 않는다. 기존 문자 메시지와 첨부 메시지 구조를 재사용한다.
- 허용 첨부 유형은 현재와 동일하게 이미지(JPEG·PNG·WebP)와 PDF만 유지한다.
- DB 스키마 변경과 Drizzle migration은 필요하지 않다.

## 목표

1. 이미지 메시지를 색상 말풍선과 파일 정보 카드에서 분리하고, 카카오톡처럼 이미지 자체와 전송 시간만 표시한다.
2. PDF 메시지를 shadcn `Attachment` 예시의 정보 구조를 따르는 밝은 테마 카드로 표시한다.
3. 첨부파일과 문자를 함께 전송하면 이미지 또는 PDF 메시지를 먼저, 문자 메시지를 다음에 각각 별도 저장한다.
4. 첨부 메시지와 문자 메시지는 하나의 서버 요청과 DB 트랜잭션으로 저장해 둘 다 성공하거나 둘 다 실패하게 한다.
5. 새 UI는 신규 메시지뿐 아니라 기존에 저장된 모든 이미지·PDF 메시지에도 적용한다.

## 확정 요구사항

### 이미지 메시지

- 보낸 이미지는 채팅창 오른쪽, 받은 이미지는 왼쪽에 정렬한다.
- 발신·수신 이미지 모두 기존 coral 또는 secondary 말풍선 배경을 제거한다.
- 파일명, MIME 형식, 용량 정보는 이미지 아래에 표시하지 않는다.
- 원본 종횡비를 유지하며 잘라내지 않는다.
- 데스크톱 최대 너비는 약 `320px`, 모바일은 `60vw`와 `240px` 중 작은 값으로 제한한다.
- 세로로 긴 이미지는 종횡비를 유지하면서 데스크톱 `70vh`, 모바일 `50vh`를 넘지 않도록 `object-contain`으로 표시한다.
- 이미지를 누르면 현재 동작을 유지해 `target="_blank"`로 원본을 연다. 데스크톱과 모바일 모두 브라우저 새 탭 방식이다.
- 이미지의 전송 시간은 이미지 바깥쪽 하단에 표시한다.

### PDF 메시지

- PDF는 shadcn `Attachment`의 정보 배치 방식을 따른다.
  - 왼쪽: 파일 아이콘
  - 가운데 위: 파일명
  - 가운데 아래: `PDF · 37 KB` 형식의 종류와 용량
  - 오른쪽: 다운로드 아이콘 버튼
- 사이트의 현재 밝은 테마와 기존 색상 토큰을 재사용한다. 예시 화면의 검은색 배경을 복제하지 않는다.
- 기존 coral 또는 secondary 말풍선 배경을 제거한다.
- 긴 파일명은 한 줄 말줄임표로 표시하고 `title` 속성으로 전체 파일명을 제공한다.
- 카드 전체를 누르거나 오른쪽 다운로드 버튼을 누르면 모두 파일을 내려받을 수 있게 한다.
- 전송 시간은 카드 내부나 아래가 아니라 카드 바깥쪽 하단에 표시한다.

### 정렬과 시간

- 내가 보낸 이미지·PDF는 오른쪽 정렬, 상대가 보낸 이미지·PDF는 왼쪽 정렬한다.
- 시간은 문자 말풍선과 첨부물 내부·옆이 아닌 바로 아래에 표시한다.
- 같은 발신자가 같은 분에 끊기지 않고 연속 전송한 구간의 마지막 메시지에만 시간을 표시한다. 상대가 중간에 전송하면 같은 분이어도 새 구간으로 나눈다.
- 데스크톱과 모바일 모두 `오후 12:29` 형식을 사용한다.
- 날짜가 바뀌면 모바일은 둥근 날짜 칩, 데스크톱은 연한 primary 색상의 선과 날짜 칩으로 구분한다.
- 일반 문자 말풍선과 기존 발신·수신 방향은 유지한다.
- 모바일 수신 메시지의 기존 아바타와 발신자 이름 그룹 규칙은 유지하되, 첨부물 자체에는 말풍선 배경을 씌우지 않는다.

### 첨부파일과 문자 동시 전송

- 전송 순서는 `이미지 또는 PDF 메시지 → 문자 메시지`로 고정한다.
- 새로운 `mixed` 같은 메시지 종류를 추가하지 않는다.
- 첨부 메시지는 기존 `chatMessage + chatAttachment`, 문자는 기존 `chatMessage` 행으로 각각 저장한다.
- `sendMediaMessage` 입력에 선택적인 문자 본문과 별도 문자 메시지 ID를 받을 수 있도록 확장한다.
- 서버는 하나의 DB 트랜잭션에서 다음 순서로 처리한다.
  1. 첨부용 `chatMessage` 생성
  2. `chatAttachment` 생성
  3. 문자가 있으면 별도 `chatMessage` 생성
  4. 채팅방 갱신 및 각 메시지 동기화 이벤트 등록
- 어느 DB 작업이라도 실패하면 트랜잭션 전체를 되돌린다.
- 파일은 메시지 요청 전에 서명 URL로 외부 저장소에 업로드되므로 DB 저장 실패 시 미사용 객체가 남을 가능성은 현재 구조의 한계로 문서화한다. 사용자 채팅에는 부분 메시지를 표시하지 않는다.
- 재시도 중 중복 전송을 막기 위해 첨부 메시지 ID와 문자 메시지 ID를 클라이언트가 각각 생성해 요청에 포함한다.
- 첨부만 전송하면 현재 `sendMediaMessage` 동작을 그대로 사용하고 문자 메시지를 추가 생성하지 않는다.
- 문자만 전송하면 현재 `sendMessage` 동작을 그대로 사용한다.
- 첨부와 문자를 함께 전송할 때 성공 응답을 받은 후에만 입력창과 첨부 초안을 비운다.

## 구현 범위

### `apps/web/src/components/bambi/chat-attachment-preview.tsx`

- 이미지와 PDF 렌더링을 명확히 분리한다.
- 이미지 링크에서 카드 테두리, 배경, 파일 메타데이터 영역을 제거한다.
- 이미지에 원본 비율, 반응형 최대 너비·높이, `object-contain`을 적용한다.
- PDF를 밝은 테마의 shadcn Attachment 구조로 재구성한다.
- PDF 형식 표시는 MIME 전체 문자열 대신 사용자 친화적인 `PDF`를 사용한다.
- 다운로드 아이콘 버튼을 추가하되 카드 전체 링크와 중첩 인터랙션이 잘못 동작하지 않도록 카드 컨테이너에서 클릭·키보드 동작을 구성한다.

### `apps/web/src/components/bambi/screens/seeker-chat-room-responsive.tsx`

- `ChatMessageBubble`에서 첨부 유무와 종류에 따라 일반 문자 말풍선과 첨부 레이아웃을 분기한다.
- 이미지·PDF는 `MessageContent`의 색상 말풍선 밖에서 렌더링하고 시간도 별도 인접 요소로 배치한다.
- 발신은 `flex-row-reverse`, 수신은 기본 방향을 사용해 첨부물과 시간을 좌우 정렬한다.
- 기존 메시지 조회 결과도 같은 컴포넌트를 사용하므로 과거 첨부 메시지까지 새 UI가 적용된다.
- 첨부와 문자가 함께 있으면 업로드 완료 후 확장된 `sendMediaMessage` 요청 한 번으로 두 메시지를 전송한다.
- 성공 후에만 문자와 첨부 초안을 초기화하고, 실패하면 둘 다 입력 상태에 남겨 재시도할 수 있게 한다.

### `packages/api/src/routers/bambi/chats.ts`

- `sendMediaMessageInput`에 선택적 `body`와 `textMessageId`를 추가한다.
- 본문은 기존 일반 메시지와 동일하게 공백 제거 후 1~2,000자로 검증한다.
- 첨부 메시지와 선택적 문자 메시지를 하나의 트랜잭션에서 별도 행으로 생성한다.
- 첨부 메시지가 먼저 정렬되도록 생성 순서와 클라이언트 메시지 ID를 유지한다.
- 두 메시지 모두 기존 동기화 큐와 채팅방 갱신 경로를 사용한다.
- 동일 ID 재시도 시 기존 행을 확인해 중복 첨부 또는 중복 문자가 생기지 않도록 기존 idempotency 규칙을 확장한다.

## 제외 범위

- 이미지와 문자를 한 행에 저장하는 혼합 메시지 모델
- 여러 이미지 또는 여러 파일의 동시 첨부
- DOCX, XLSX, ZIP 등 PDF 이외 일반 파일 허용
- 이미지 팝업·라이트박스 신규 개발
- 이미지 편집, 압축 또는 썸네일 생성
- 첨부파일 보관 정책 및 미사용 저장소 객체 정리 작업
- 기존 DB 데이터 변환 또는 migration

## 검증 계획

불필요한 전체 테스트는 실행하지 않고 변경 위험에 직접 관련된 범위만 확인한다.

1. API 단위 검증
   - 첨부만 전송하면 첨부 메시지 한 개가 생성된다.
   - 첨부와 문자를 함께 보내면 첨부 메시지 다음 문자 메시지가 각각 생성된다.
   - 문자 생성이 실패하면 첨부 메시지와 첨부 레코드도 남지 않는다.
   - 동일 메시지 ID로 재시도해도 중복 행이 생기지 않는다.
2. UI 수동 검증
   - 발신·수신 이미지가 말풍선 없이 좌우에 맞게 표시된다.
   - 이미지가 원본 비율을 유지하고 데스크톱 320px, 모바일 약 70vw 한도를 넘지 않는다.
   - 세로 이미지가 화면 높이를 과도하게 차지하지 않는다.
   - 이미지 클릭 시 데스크톱과 모바일에서 새 탭으로 원본이 열린다.
   - PDF 카드의 아이콘, 파일명, 형식·용량, 다운로드 버튼과 외부 시간이 올바르게 보인다.
   - 긴 PDF 파일명은 말줄임되고 데스크톱 hover 시 전체 제목이 표시된다.
   - 카드와 다운로드 버튼 모두 다운로드 동작을 수행한다.
   - 이미지·PDF와 문자를 함께 보내면 첨부가 먼저, 문자가 다음에 표시되고 각각 시간이 보인다.
   - 실패 시 첨부만 또는 문자만 부분적으로 채팅에 나타나지 않는다.
   - 구직자와 구인자 화면에서 동일하게 동작한다.
3. 정적 검증
   - 변경 파일 Biome 검사
   - web 및 API TypeScript 검사
   - `git diff --check`

## 이슈·PR 작성 기준

- 구현과 검증 완료 후 기존 저장소의 CMU02 이슈·PR 구조와 문체를 확인한다.
- 새 이슈에 UI 변경, 동시 전송 원자성, 적용 범위와 검증 조건을 기록한다.
- PR은 Draft가 아닌 리뷰 가능한 상태로 생성하며 `Closes #이슈번호`를 포함한다.
- PR 전 최신 `develop`을 다시 반영해 충돌 여부를 확인한다.
- 사용자가 직접 커밋·푸시하므로 별도 요청 없이는 임의로 커밋하거나 푸시하지 않는다.
- 최종 PR 머지는 동기가 수행한다.
