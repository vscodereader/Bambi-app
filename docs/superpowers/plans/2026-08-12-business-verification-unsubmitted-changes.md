# 사업자 인증 변경사항 미제출 설계

## 목표

인증 완료 업체가 업체 정보 또는 인증 서류를 수정하더라도 즉시 운영자 심사 큐로 보내지 않는다. 첫 변경 시 `변경사항 미제출` 상태로 전환하고, 사용자가 `업체 정보 제출`을 누른 시점에만 `인증 대기`로 전환하여 운영자 알림을 한 번 발송한다.

## 상태 전이

- `none`: 최초 미인증. 자유롭게 입력·서류 변경 후 제출하면 `pending`.
- `verified`: 인증 완료. 텍스트 또는 서류 변경을 확인하면 `changes_unsubmitted`.
- `changes_unsubmitted`: 변경사항 미제출. 임시 정보 자동 저장, 서류 추가·삭제 허용, 운영자 심사 목록 제외.
- `pending`: 인증 대기. 텍스트와 서류 변경 잠금.
- `rejected`: 인증 반려. 자유롭게 수정 후 재제출하면 `pending`.

## 데이터 모델

`employer_verification_status` enum에 `changes_unsubmitted`를 추가한다. `employer_organization_profile`에 다음 임시 필드를 추가한다.

- `draft_display_name`
- `draft_business_registration_number`
- `draft_representative_name`
- `draft_business_start_date`

인증 완료 상태의 첫 변경 시 기존 승인 값을 임시 필드에 복사한다. 텍스트 입력은 임시 필드에 debounce 자동 저장한다. 제출 시 임시 값을 본 필드로 옮기고 임시 필드를 비운 뒤 `pending`으로 전환한다. 창을 닫거나 다시 접속해도 임시 값과 상태가 복원된다.

## 서류 변경

- 인증 완료 및 변경사항 미제출 상태에서 추가·삭제 때마다 AlertDialog를 표시한다.
- 파일 추가는 형식·용량 검증 후 실제 업로드 직전에 확인한다.
- 확인한 변경만 저장하고 `changes_unsubmitted`로 전환한다.
- `pending`에서는 추가·삭제를 모두 잠근다.
- `none`과 `rejected`에서는 경고 없이 변경한다.
- 변경사항 미제출에서는 마지막 서류 삭제를 허용하되 제출 시 최소 한 개를 검사한다.

## 이용 제한

`changes_unsubmitted`는 인증되지 않은 상태로 취급한다.

- 기존 공개 공고와 광고는 공개 피드에서 제외한다. DB 공고 상태 자체는 보존하여 재승인 후 다시 노출한다.
- 신규 공고 등록·수정 및 광고·끌어올리기 구매를 거절한다.
- 업체가 참여한 기존 채팅방은 읽기만 허용하며 양쪽 참여자의 문자·이미지·PDF 전송을 거절한다.
- 운영자 심사 목록에는 `pending`만 포함한다.

## 화면과 경고

- 사업자 인증 제목 아래에 인증 완료 상태의 사전 안내 Alert를 표시한다.
- 변경사항 미제출 상태에서는 제출 필요와 제한 사항을 강조하는 Alert로 교체한다.
- 내부 링크, 상단·하단 메뉴 및 브라우저 뒤로가기는 커스텀 AlertDialog로 막고 확인 시 제출 버튼으로 스크롤·포커스한 뒤 primary 링을 3회 강조한다.
- 새로고침, 탭 닫기, 주소창 직접 이동은 `beforeunload` 브라우저 기본 확인창을 사용한다.
- 제출 성공 전에는 이탈 방지를 유지하며 실패하면 상태와 임시 값도 유지한다.

## 제출

- 서류가 한 개 이상인지 검사한다.
- 임시 정보의 필수값과 사업자등록정보 진위 확인을 수행한다.
- 임시 값을 본 필드로 확정하고 `pending`으로 전환한다.
- 이 시점에만 운영자 알림을 한 번 발송한다.
- 제출 후 입력과 서류 변경을 잠근다.
