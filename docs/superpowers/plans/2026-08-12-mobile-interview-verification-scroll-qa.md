# 모바일 면접·사업자 정보·오버레이 스크롤 QA 설계

## 배경

테스트 사이트의 모바일 실기기 검증에서 다음 문제가 확인됐다.

1. 구직자가 확정한 면접을 다시 취소해도 구인자 화면의 `예정된 면접` 캐시에 확정 카드가 남는다.
2. 인증 완료 업체의 텍스트 정보는 입력할 때마다 변경 경고가 열려 편집을 방해한다.
3. 채팅방의 `공고 보기` 모바일 패널이 처음 열렸을 때 내부 스크롤이 되지 않거나, 닫은 뒤 채팅 스크롤이 잠긴다.
4. 예정된 면접의 후기 작성 영역도 사용자 액션 뒤 새로고침 전까지 스크롤이 잠기는 경우가 있다.

## 확정 요구사항

### 취소된 면접

- 구직자가 확정 후 취소하면 구인자와 구직자 양쪽의 예정된 면접 목록에서 해당 일정만 즉시 제거한다.
- 같은 채팅방의 다른 확정 일정은 유지한다.
- DB의 면접 일정과 채팅방 면접 이력은 `canceled` 상태로 보존한다.
- 취소 알림의 목적지는 기존 정책대로 `예정된 면접` 화면을 유지한다.

### 사업자 정보 변경 확인

- 최초 미인증 및 반려 상태에서는 텍스트 입력·수정·제출 시 변경 확인창을 표시하지 않는다.
- 인증 완료 및 변경사항 미제출 상태에서는 업체명, 사업자등록번호, 대표자 성명, 개업일자를 편집하는 동안 확인창을 표시하지 않는다.
- 인증 완료 상태의 텍스트 변경값은 임시 데이터로 자동 저장하고 변경사항 미제출 상태로 전환한다.
- 텍스트 변경 후 `업체 정보 제출`을 눌렀을 때만 다음 최종 확인창을 표시한다.
  - 제목: `업체 정보를 변경하시겠습니까?`
  - 설명: `업체 정보를 제출하면 인증 대기 상태로 전환되며, 운영자 승인 전까지 기존 공고와 광고가 비공개 처리되고 채팅 송수신이 제한됩니다.`
  - 버튼: `취소`, `변경사항 제출`
- 취소하면 입력한 임시 값은 유지하고, 확인하면 기존 제출 API를 호출해 인증 대기로 전환한다.
- 사업자 인증 서류 추가·삭제의 개별 경고와 처리 흐름은 변경하지 않는다.

### 모바일 스크롤

- 채팅방 `공고 보기` Sheet 내부는 처음 열 때부터 세로 스크롤 가능해야 한다.
- Sheet가 열려 있는 동안 배경 채팅의 스크롤 차단은 유지한다.
- Sheet를 닫으면 채팅 메시지 영역을 새로고침 없이 즉시 스크롤할 수 있어야 한다.
- 예정된 면접 아코디언 및 후기 작성 영역도 확장 직후부터 페이지에서 스크롤 가능해야 한다.
- 구직자와 구인자 모바일 화면에 동일하게 적용한다.

## 원인 분석

### 면접 목록

서버의 `listMyUpcomingInterviews`는 이미 `proposed`, `confirmed`, `completed`만 조회하므로 `canceled` 데이터는 목록 대상이 아니다. 문제는 채팅방에서 상태 변경 성공 후 채팅방 쿼리만 갱신되고 `listMyUpcomingInterviews` 캐시가 무효화되지 않아, 이미 열렸던 예정 면접 화면에 이전 `confirmed` 결과가 남는 클라이언트 캐시 불일치다.

### 사업자 정보

인증 완료 상태의 텍스트 필드 변경을 감지하는 effect가 변경 즉시 AlertDialog를 열고 있다. 문서 변경처럼 실행 전 승인이 필요한 작업과, 여러 필드를 자유롭게 편집한 뒤 한 번 제출하는 텍스트 폼의 UX가 같은 확인 흐름을 공유한 것이 원인이다.

### 모바일 스크롤

모바일 채팅 화면이 마운트될 때 `document.body.style.overflow = "hidden"`을 직접 설정하면서 Base UI의 Sheet/Dialog도 자체적으로 body scroll lock을 관리한다. 두 잠금 주체가 겹친 상태에서 오버레이가 열리고 닫히면 한쪽이 이미 잠긴 `hidden` 값을 이전 상태로 기억해 다시 복원할 수 있다. 그 결과 오버레이가 닫혀도 body 잠금이 남고, 새로고침으로 모든 잠금 주체가 초기화된 뒤에야 스크롤이 복구된다.

## 구현 설계

### 1. 면접 상태 갱신

- `seeker-chat-room-responsive.tsx`의 면접 상태 변경 성공 처리에서 다음 쿼리를 함께 무효화한다.
  - 현재 채팅방 상세
  - 채팅방 목록
  - `listMyUpcomingInterviews`
- 서버의 상태 전환과 알림 대상·목적지는 변경하지 않는다.
- 예정 면접 API가 canceled 상태를 반환하지 않는 현재 필터를 회귀 테스트로 고정한다.

### 2. 사업자 텍스트 제출 확인

- 필드 변경 effect에서는 AlertDialog를 열지 않는다.
- 인증 완료 또는 변경사항 미제출 상태에서 텍스트 값이 달라지면 debounce된 draft 저장을 수행한다.
- 폼 제출 시 검증을 먼저 수행한다.
- 최초 미인증·반려는 바로 제출한다.
- 인증 완료에서 시작한 변경 또는 변경사항 미제출은 최종 제출 AlertDialog를 열고, 확인 버튼에서 제출 mutation을 호출한다.
- 확인창 취소는 필드 값을 초기화하지 않는다.
- 문서 업로더의 추가·삭제 AlertDialog는 수정하지 않는다.

### 3. 스크롤 잠금 단일화

- 모바일 채팅 컴포넌트가 직접 관리하는 body overflow 잠금을 제거해 오버레이 잠금 소유권을 Base UI에 일원화한다.
- 채팅 화면 자체는 고정 높이 컨테이너와 메시지 영역 `overflow-y-auto`로 유지하므로 배경 문서 스크롤을 별도로 막을 필요가 없다.
- Sheet 콘텐츠에 `min-h-0`, 명시적인 viewport 높이 및 내부 `overflow-y-auto`를 적용한다.
- 예정 면접 페이지의 바깥 레이아웃이 모바일에서 축소 가능한 flex child가 되도록 `min-h-0`/overflow 경계를 점검하고 필요한 최소 클래스만 추가한다.
- 공통 Dialog/Sheet 전역 구현은 다른 화면 회귀 위험이 있으므로, 공통 컴포넌트 결함이 재현되는 경우에만 좁은 수정과 회귀 테스트를 추가한다.

## 데이터베이스 및 API

- 신규 상태나 컬럼이 필요하지 않으므로 Drizzle migration은 만들지 않는다.
- 취소 면접 데이터는 기존 `canceled` 상태로 보존한다.
- 알림 링크 정책과 API 응답 형태는 변경하지 않는다.

## 검증 계획

불필요한 전체 테스트는 실행하지 않고 변경 범위에 맞춰 다음만 확인한다.

1. 면접 조회/상태 갱신 관련 대상 테스트
2. 사업자 정보 폼의 텍스트 확인창 조건 테스트
3. 채팅 모바일 Sheet와 body overflow 중복 잠금 방지 정적 테스트
4. 예정 면접 모바일 스크롤 컨테이너 테스트
5. 변경 파일 Biome
6. web 및 API TypeScript
7. `git diff --check`
