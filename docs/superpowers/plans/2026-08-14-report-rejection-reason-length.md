# 신고 처리 사유 길이 및 실패 동작 개선 계획

## 목적

- 운영자 공통 사유 입력창에서 서버 제한과 동일하게 최대 500자까지만 입력되도록 한다.
- 현재 입력 글자 수를 표시해 운영자가 제한을 미리 알 수 있게 한다.
- 신고 기각·처리 API가 성공한 뒤에만 사유 창을 닫고 신고 목록으로 이동한다.
- 실패 시 입력 내용과 사유 창을 유지하고 명확한 오류 문구를 표시한다.
- 로그인 직후 목적 페이지가 완전히 준비되기 전에 팝업이 중복 노출되는 현상을 막는다.
- 같은 사용자가 처리 대기 중인 동일 대상을 다시 신고하면 대상별 안내를 표시한다.
- 커뮤니티 신고의 실제 대상 조치와 신고 완료 처리를 하나의 운영 흐름으로 연결한다.

## 구현 범위

1. 공통 `ReasonConfirmSheet` textarea에 `maxLength={500}`과 `현재 글자 수 / 500` 표시를 추가한다.
2. 신고 상태 변경 함수를 비동기로 전환해 성공 여부를 호출자에게 반환한다.
3. 신고 상세 화면은 성공 결과를 확인한 경우에만 사유 창을 닫고 목록으로 이동한다.
4. 실패 시 다음 문구를 표시한다.
   - `사유가 500자를 넘어 신고 상태를 API에 반영하지 못했어요. 사유는 500자 이내로 입력해 주세요.`
5. 위 동작을 고정하는 전용 웹 정적 테스트를 추가한다.
6. 팝업은 인증 화면과 로그인 이동 중에는 숨기고, 목적 페이지의 문서 로딩과 렌더링이 끝난 뒤 표시한다.
7. 같은 신고자·대상의 `open`/`reviewing` 신고가 있으면 새 신고를 성공 처리하지 않고 글·댓글·채팅방·공고별 중복 안내를 반환한다.
8. `resolved`/`dismissed` 신고만 있거나 신고자가 다르면 새 신고를 허용한다.
9. 커뮤니티 신고 상세은 신고 내용을 조치 사유 위에 표시하고, 2자 이상의 사유가 있어야 숨김·삭제를 실행할 수 있게 한다.
10. 커뮤니티 글·댓글 상태 변경이 성공하면 같은 사유로 신고도 자동 완료하고 목록으로 이동한다.
11. 커뮤니티 신고에서는 실제 대상을 변경하지 않는 별도 `조치 완료` 버튼을 숨긴다.

## 제외 범위

- API 스키마와 데이터베이스 변경
- 신고 처리 정책 및 최소 2자 제한 변경
- 다른 운영자 화면의 디자인 변경
