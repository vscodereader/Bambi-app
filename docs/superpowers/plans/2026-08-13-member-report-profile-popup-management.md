# 멤버 초대·신고·프로필·페이지별 팝업 관리 설계

## 목표

구인자 멤버 초대 사유 검증, 구직자 신고 내역 상세화, 운영자 콘텐츠 보호와 채팅 첨부 확인, 광고 옵션 접기, 전역 프로필 사진, 페이지별 팝업 노출을 하나의 통합 변경으로 제공한다.

## 기준 브랜치와 작업 단위

- 기준: `origin/develop` `724fae7e` (2026-08-13 최종 동기화)
- 브랜치: `feat/member-report-profile-popup-management`
- 하나의 설계서·이슈·PR로 진행한다.
- 사용자가 직접 커밋하고 푸시한다.
- DB 변경이 필요하면 기존 필드 존재 여부를 먼저 확인하고, 없을 때만 다음 번호의 Drizzle migration을 추가한다.

## 1. 멤버 초대 사유

- 입력 순서: 이메일 → 권한 → 팀 → 초대 사유 → 초대 버튼.
- 초대 사유는 앞뒤 공백 제거 후 10~200자 필수다. 한글·영문·공백·특수문자를 모두 글자로 센다.
- 10자 미만 또는 200자 초과이면 초대 버튼을 비활성화하고 API도 요청을 거절한다.
- 입력창은 공백 없는 긴 한글·영문도 카드 밖으로 넘치지 않고 줄바꿈한다.
- 반려 초대 재제출에도 같은 검증을 적용하며 기존 사유를 기본값으로 복원한다.
- 최초 초대와 재제출, 모바일과 데스크톱에 동일하게 적용한다.

## 2. 신고 작성과 내 신고 내역

### 신고 작성

- 공고·채팅방·커뮤니티 글·댓글의 모든 신고창에 `신고 접수` 옆 `신고 취소` 버튼을 제공한다.
- 신고 취소는 접수 전 다이얼로그를 닫는 동작이며 입력값은 폐기한다. 접수 후 철회 기능은 만들지 않는다.
- 관리자(`admin`, `moderator`)가 작성한 글·댓글·공지사항은 신고 버튼을 숨긴다.
- 직접 API 호출 등 우회 신고도 서버에서 거절한다.
- 차단 안내는 AlertDialog로 제목 `신고할 수 없습니다`, 설명 `관리자가 작성한 글이나 댓글에는 신고할 수 없습니다.`, 단일 `확인` 버튼을 사용한다.

### 신고 스냅샷

- 신규 신고는 신고 당시 대상 정보를 스냅샷으로 저장한다.
- 공고: 공고 제목, 업소명, 급여 단위와 금액, 대상 URL.
- 채팅방: 연관 공고 제목과 업소명만 저장하고 채팅방 링크·대화·참여자는 사용자 신고 내역에 노출하지 않는다.
- 커뮤니티 글·댓글: 원문과 대상 종류, 작성일을 저장한다. 댓글 신고에는 게시글 제목을 표시하지 않는다.
- 기존 신고는 원본이 남아 있으면 현재 정보로 보완하고, 원본도 없으면 `삭제되었거나 확인할 수 없는 대상입니다`를 표시한다.

### 내 신고 내역 UI

- 각 신고 카드만 독립 아코디언으로 동작하며 여러 카드를 동시에 펼칠 수 있다.
- 상태는 현재 존재하는 모든 상태를 그대로 표시한다.
- 공고 신고 상세은 제목·업소명·급여를 표시하고 클릭하면 공고로 이동한다. 삭제·비공개이면 `현재 확인할 수 없는 공고입니다`를 안내한다.
- 채팅 신고 상세은 공고 제목·업소명만 표시하며 이동하지 않는다.
- 글·댓글 상세은 `원글:` 또는 `원 댓글:` 뒤 원문을 12자 초과 시 앞 12자와 `...`로 표시하고, 대상 종류와 `YYYY.MM.DD`를 표시한다.
- 운영자가 처리 사유를 입력한 모든 처리 결과는 카드 안의 별도 아코디언으로 사유를 표시한다.
- 데스크톱과 모바일의 정보 구조는 같고 너비·여백만 반응형으로 조절한다.

## 3. 운영자 작성자 표시와 채팅 신고 첨부

- 커뮤니티 글 목록, 상세, 댓글, 답글과 운영자 본인의 이름 옆에 primary 계열 `운영자` 뱃지를 표시한다.
- 기존 업소 뱃지와 시각적으로 구분한다.
- 운영자 신고 상세의 채팅 내역 화면 하단에 모든 지원 첨부를 전송 순서대로 하나의 흰색 가로 스크롤 영역에 모은다.
- 이미지는 실제 작은 썸네일만 표시하고 아이콘을 사용하지 않는다. 클릭하면 기존 원본 새 탭 열기를 재사용한다.
- PDF는 기존 PDF 아이콘과 다운로드 동작을 재사용한다.
- 이미지 한 장이어도 같은 가로 스크롤 컨테이너를 사용한다.
- 영상·GIF는 이번 범위에서 제외하고 기존 표시를 유지한다.

## 4. 끌어올리기 옵션 아코디언

- 운영자 광고상품 관리에서 `끌어올리기`, `끌어올리기 횟수권`, `자동 끌어올리기` 세 카드만 독립 아코디언으로 변경한다.
- 최초 진입 시 모두 접힌 상태다.
- 여러 카드를 동시에 펼칠 수 있다.
- 나머지 광고상품에는 적용하지 않고, 내부 입력값·저장 동작은 유지한다.
- 모바일과 데스크톱 모두 적용한다.

## 5. 프로필 사진

- 최신 스키마와 업로드 API에 기존 프로필 필드가 있으면 재사용하고 없을 때만 Drizzle migration을 추가한다.
- 구직자·구인자·운영자 계정마다 프로필 사진 하나를 저장한다.
- 업소 직원이 작성한 콘텐츠에는 업소 대표 프로필 사진을 공통 사용한다.
- 계정 설정의 휴대폰 재인증 아래에 프로필 사진 설정을 추가한다.
- JPG·PNG·WebP만 허용하고 GIF는 거절하며 최대 5MB다.
- 원본을 유지하고 화면에서는 중앙 기준 정사각형 `object-cover`로 표시한다. 별도 자르기 UI는 제공하지 않는다.
- 삭제하여 기본 프로필로 복원할 수 있다. 기본 프로필은 `UserRound` 아이콘을 사용한다.
- 적용 위치: 내 정보 카드, 커뮤니티 글·댓글·답글, 채팅 메시지·채팅방 목록, 신고 내역과 운영자 신고 화면, 공고 상세의 업소 정보.
- 공고 목록 썸네일은 변경하지 않는다.
- 공고 상세 정보 순서는 공고 제목 → `[업소 대표 프로필] 업소명 · 실제 등록자 표시 이름` → 지역·업종 등 기존 정보다.
- 표시 제목 앞에 업소명이 정확히 포함되면 해당 부분을 제거한다. 제거 후 빈 제목이면 원래 제목을 유지한다.

### 커뮤니티 익명 작성과 기본 이미지

- 구직자가 `자유수다`, `밤문화 이야기`, `중고거래`, `무료 법률 자문`에 글을 작성할 때 작성인 아래에 `익명` 체크박스를 제공한다.
- 익명을 선택하지 않으면 작성인은 계정 설정의 현재 표시 이름을 서버에서 사용하며 입력창은 수정할 수 없다.
- 익명을 선택하면 작성인 입력창을 열어 글별 닉네임을 1~30자로 입력할 수 있다.
- 익명 글은 계정 프로필 사진을 노출하지 않고 사람 아이콘 기본 프로필을 표시한다.
- 일반 글은 작성자의 현재 프로필 사진을 표시하고, 사진이 없으면 글자 이니셜 대신 사람 아이콘을 표시한다.
- 익명 여부는 서버에서 허용 역할·게시판을 검증하고 게시글에 저장한다.
- 본인인증을 마친 비회원은 허용된 게시판에서 글을 작성할 수 있다.
- 비회원 작성인은 항상 `비회원`으로 표시하고 입력창을 비활성화한다. 클라이언트가 다른 값을 보내더라도 서버가 `비회원`으로 강제한다.
- 비회원 게시글에는 회원 프로필 사진을 연결하지 않고 사람 아이콘 기본 프로필을 표시한다.
- 웹에서 발급한 게스트 토큰과 API 서버에서 검증하는 토큰은 동일한 `BAMBI_GUEST_TOKEN_SECRET`을 사용해야 한다.
- 운영자 게시글에는 작성자 역할 뱃지를 표시하지 않는다. 댓글의 운영자 뱃지는 유지한다.
- 운영자가 작성한 게시글과 댓글에는 신고 버튼을 표시하지 않는다.
- 비회원 게시글 상세도 회원 상세와 같은 작성자 프로필·공지 배지 구조를 사용하고 추천 버튼을 본문 중앙에 배치한다.
- 운영자가 신고를 기각할 때 2~500자의 기각 사유를 입력하며, 신고자 내 신고 내역의 채팅방·공고·게시글·댓글 상세 영역에 해당 사유를 표시한다.
- 팝업 위치는 버튼 묶음 대신 드롭다운 한 개로 시작하고 `위치 추가`로 중복되지 않는 위치 선택 행을 늘린다.
- 팝업 위치에서 이용 가이드·이용약관·개인정보 처리방침·알림과 일반 커뮤니티 목록·게시판·게시글 상세 항목을 제거한다.
- 역할 선택에서 이미 회원 유형을 구분하므로 위치 라벨의 회원 유형 접미사를 제거한다.
- 커뮤니티 팝업 위치는 자유수다·밤문화 이야기·중고거래·무료법률자문의 게시판 목록 화면 네 곳만 제공하고 게시글 상세에서는 표시하지 않는다.
- 게시글 INSERT가 DB 오류로 실패하면 해당 시도의 1분 작성 제한 예약을 반환해 사용자가 즉시 재시도할 수 있게 한다. 성공한 INSERT만 제한 횟수를 소비한다.

### 채팅 기본 이미지

- 신규·기존 채팅방 모두 채팅방 목록과 상대방 말풍선 프로필에 사용자 사진이나 글자 이니셜 대신 말풍선 아이콘을 표시한다.

### 내 정보 프로필 카드 이동

- 내 정보 좌측 프로필 카드 전체를 클릭하거나 키보드로 활성화하면 계정 설정으로 이동한다. 기존 계정 설정 메뉴·버튼 이동은 유지한다.

### 1:1 문의 작성과 프로필

- 1:1 문의 본문 작성기에서는 클립보드의 블록 HTML을 그대로 붙이지 않고 평문을 현재 커서 위치에 삽입한다. 복사한 단어를 반복해서 붙이면 불필요한 새 문단이 생기지 않는다.
- 문의 원문에는 문의자 닉네임과 프로필 사진을 함께 표시한다.
- 문의자 추가 메시지와 운영자 답글에는 각각 실제 작성자의 닉네임·프로필 사진을 함께 표시한다.
- 프로필 사진이 없으면 공통 사람 아이콘을 사용한다.

## 6. 페이지별 팝업

- 기존 팝업 이미지, 클릭 링크, 시작·종료 일시, 게시 구분과 팝업 개수 정책은 유지한다.
- 종료 일시 아래에 여러 페이지를 선택할 수 있는 팝업 위치 콤보박스를 추가한다.
- Admin 선택창에는 경로를 숨기고 역할을 붙인 페이지 이름만 표시한다.
- `공통`: 양쪽에서 접근 가능한 페이지 목록.
- `개인회원`: 공통 페이지를 포함한 모든 구직자 페이지 목록.
- `업소회원`: 공통 페이지를 포함한 모든 구인자 페이지 목록.
- 메인 페이지도 선택할 수 있다. 운영자 전용 페이지는 제외한다.
- 동적 URL은 개별 ID가 아니라 `구직자 공고 상세`, `구직자 채팅방`, `커뮤니티 게시글 상세` 같은 페이지 종류 단위로 선택한다.
- 팝업은 선택한 페이지에서만 나타나며 다른 페이지로 이동하면 사라진다.
- 동일 페이지의 여러 활성 팝업은 기존 팝업 개수 설정과 순서 정책을 유지한다.
- 기존 팝업 데이터는 메인 전용 대상으로 migration backfill한다.

## 데이터와 API 원칙

- 클라이언트 검증만 믿지 않고 초대 사유, 관리자 콘텐츠 신고 차단, 신고 스냅샷, 프로필 파일 형식·크기, 팝업 위치를 서버에서도 검증한다.
- 신고 스냅샷은 원본 삭제·수정 후에도 유지한다.
- 프로필 및 팝업 DB 변경은 Drizzle migration으로 생성하고 기존 migration 이력과 번호 충돌을 확인한다.
- 익명 게시글 여부는 `0088_redundant_barracuda.sql`에서 `community_post.is_anonymous`로 추가한다. 기존 글은 `false`로 유지한다.
- 기존 API 응답과 과거 데이터에는 안전한 fallback을 제공한다.

## 검증 범위

불필요한 전체 테스트는 실행하지 않는다. 다음만 수행한다.

- 변경 파일 Biome 및 `git diff --check`
- web/api/db TypeScript 검사
- 초대 사유 10·200자 경계와 재제출 핵심 테스트
- 관리자 콘텐츠 신고 차단 및 신고 스냅샷 핵심 테스트
- 프로필 파일 검증과 팝업 페이지 매칭 핵심 테스트
- 관련 UI 정적/컴포넌트 테스트 중 기존 패턴으로 빠르게 실행 가능한 항목

## 완료 조건

- 확정된 모든 UI가 모바일·데스크톱에서 동작한다.
- 과거 데이터가 깨지지 않고 신규 데이터는 필요한 스냅샷·프로필·팝업 위치를 저장한다.
- 설계서에 실제 migration 파일명과 검증 결과를 갱신한다.
