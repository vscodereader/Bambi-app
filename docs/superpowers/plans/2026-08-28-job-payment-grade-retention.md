# 공고 결제 포인트 사용 시 회원 등급 유지 계획

## 문제

- 회원 등급은 포인트 원장 합계에서 포인트몰 구매·환불 reason을 제외한 `등급 기준 포인트`로 계산한다.
- 공고 등록 결제에 사용한 포인트와 공고 취소 환급은 등급 제외 거래로 연결되지 않아, 공고 결제에 포인트를 쓰면 보유 포인트뿐 아니라 등급 기준 포인트도 감소한다.
- 포인트몰 구매는 등급에 중립이므로 동일한 포인트 소비인데도 기능에 따라 등급 결과가 달라진다.

## 목표

- 공고 결제 포인트 사용과 취소 환급을 포인트몰 구매·환불과 동일한 등급 중립 거래로 취급한다.
- 보유 포인트는 실제 사용·환급 금액대로 변하되, 회원 등급과 다음 등급 진행 기준은 공고 결제 전후로 변하지 않게 한다.
- 이미 저장된 공고 결제 거래도 별도 데이터 수정 없이 즉시 올바른 등급으로 계산한다.

## 설계

1. 기존 포인트몰의 `POINT_SHOP_REASONS`와 등급 제외 합계 구조를 재사용한다.
2. `bambi-member-points.ts`에 공고 결제 사용·환급 reason을 판별하는 공통 규칙을 둔다.
   - 현재 공고 원장은 공고 ID를 포함한 동적 reason을 저장하므로 정확 일치가 아니라 기존 접두사를 판별한다.
   - 공고 취소 시 상한으로 환급액이 전부 소멸한 0P 완료 reason도 같은 환급 계열로 취급한다.
3. 등급 기준 포인트를 계산하는 두 경로에 동일한 제외 규칙을 적용한다.
   - 여러 회원의 배지를 계산하는 `getGradeBasisPoints`
   - 본인 출석·포인트 요약을 계산하는 `attendance.getMine`
4. 공고 생성·환급 원장의 reason 생성도 공통 헬퍼를 재사용해 판별 규칙과 기록 형식이 어긋나지 않게 한다.
5. 보유 포인트 합계, 거래 내역, 공고 결제 금액, 환급 상한 정책은 변경하지 않는다.

## 기존 데이터 호환

- 기존 사용 거래: `공고 등록 포인트 사용: {jobPostId}`
- 기존 환급 거래: `공고 취소 포인트 환급: {jobPostId}`
- 기존 0P 환급 완료 거래: `공고 취소 포인트 환급 완료(상한 소멸): {jobPostId}`
- 위 접두사를 조회 시점에 제외하므로 migration이나 backfill 없이 기존 회원의 등급이 복구된다.

## 테스트

- 포인트몰 구매·환불이 기존처럼 등급 기준에서 제외된다.
- 공고 결제 사용·일반 환급·0P 환급 완료가 등급 기준에서 제외된다.
- 출석·가입·커뮤니티 적립과 콘텐츠 회수는 기존처럼 등급 기준에 포함된다.
- 보유 포인트 합계에는 공고 사용·환급이 계속 포함된다.
- 관련 API 단위 테스트, API TypeScript 검사, Ultracite/Biome 검사, `git diff --check`를 실행한다.

## 제외 범위

- 등급표 기준값·명칭 변경
- 포인트 원장 스키마 변경 또는 Drizzle migration
- 공고 결제·취소 환급 정책 변경
- 포인트몰 구매·혜택 사용 정책 변경

## 검증 중 발견한 공고 결제 설정 저장 경계

- 운영자 `기타 포인트 설정`에서 공고 클릭 보상과 공고 결제 포인트 사용이 하나의 저장 버튼·유효성 검사·API 입력을 공유하고 있었다.
- 클릭 보상 로테이션 시간이 비어 있으면 공고 결제 최소·최대값이 유효해도 저장 버튼이 비활성화되어 공고 결제 포인트 사용을 활성화할 수 없었다.
- 기존 통합 `saveAdmin`을 회원가입·출석, 공고 포인트, 공고 결제의 세 저장 API로 분리한다.
- 화면도 세 설정을 각각 아코디언으로 유지하고 저장 버튼을 각 아코디언 내부에 배치한다.
- 각 저장 버튼은 자기 섹션 값이 유효하고 서버에서 불러온 값과 실제로 달라졌을 때만 활성화한다.
- 두 API는 자기 컬럼만 갱신하며 DB 스키마와 포인트 정책값은 변경하지 않는다.

## 구현 결과

- `gradeBasisPointsSql`을 공통 등급 기준 합계로 추출해 여러 회원 배지와 본인 출석·포인트 요약이 같은 계산식을 사용하도록 연결했다.
- 포인트몰 구매·환불과 함께 공고 등록 포인트 사용·취소 환급·상한 소멸 환급 완료를 등급 기준에서 제외했다.
- 공고 원장의 기존 동적 reason 접두사를 그대로 호환하므로 migration이나 backfill 없이 과거 거래도 재계산 시 정상 등급으로 복구된다.
- 공고 사용·환급 reason 생성은 `JOB_PAYMENT_POINT_REASONS`로 모아 기록 형식과 등급 제외 규칙이 어긋나지 않게 했다.
- 보유 포인트 합계와 공고 결제·환급 정책은 변경하지 않았다.
- 회원가입·출석, 공고 클릭 보상, 공고 결제 포인트 사용의 프론트 검증·아코디언 내부 저장 버튼·API 컬럼 업데이트 범위를 분리했다.
- 클릭 보상 설정이 비어 있어도 공고 결제 최소·최대값을 독립적으로 저장할 수 있다.
- 초기 조회 직후에는 세 저장 버튼이 모두 비활성화되고, 해당 아코디언 값이 실제로 변경된 경우에만 활성화된다.
- 하드코딩 감사에서 발견한 공고 결제 reason 판별·SQL 패턴, 멱등키 접두사, 사이트 설정 행 ID, 포인트 입력 상한, 공고 포인트 카테고리를 각각 기존 서비스의 공통 상수·헬퍼로 통합했다.
- 기존 원장 호환에 반드시 필요한 한국어 reason 형식은 한 서비스에만 남기고, 라우터·조회·테스트는 공통 판별 함수와 생성 함수를 재사용한다.
- 변경 UI에는 임의 px·색상·폭·인라인 스타일을 추가하지 않고 기존 Tailwind 디자인 토큰만 사용한다.
- PR 원격 diff 재감사에서 남아 있던 출석 라우터의 사이트 설정 ID 직접값, 환급 reason family 중복, 임의 포인트 입력 상한을 제거했다.
- 최종 엄격 재검색에서 직접 사이트 설정 ID, reason 판별·SQL 문자열, 카테고리 중복, 임의 숫자 상한, px·hex·인라인 스타일이 남지 않았음을 확인했다.
