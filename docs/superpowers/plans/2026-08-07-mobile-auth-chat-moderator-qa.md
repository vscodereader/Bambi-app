# 모바일 인증·운영자 메뉴·채팅 배포 검수 수정 계획

> **For agentic workers:** 이 문서의 체크박스는 구현과 검증이 실제로 끝난 뒤에만 완료 처리한다.

**Goal:** 모바일 배포 환경에서 재현된 회원가입 인증 복귀 오류, 운영자 더보기 메뉴 누락·스크롤 불가, 채팅 신고의 양측 상태 불일치, 방 진입 후 안 읽음 핀 잔존, 키보드 표시 시 채팅 UI 붕괴를 교정하고, 같은 배포 검수 범위에서 요청된 사업자 인증 서류 첨부와 사이트 공통 SEO 키워드를 보완한다.

**Architecture:** 최신 `develop`에서 통합 브랜치 `fix/mobile-auth-chat-moderator-qa` 하나를 사용하고 변경은 검토 가능한 3개 커밋 영역으로 나눈다. 모바일 본인인증은 기존 PortOne 리디렉션 intent를 복구해 회원가입 단계로 정확히 돌아오게 한다. 운영자 모바일 내비게이션은 데스크톱 목적지 목록을 빠짐없이 미러링하고 shadcn Sheet 내부만 스크롤한다. 채팅 신고는 기존 `report` 상태를 단일 진실원으로 삼아 양쪽 참여자의 목록·열람·발신·안 읽음 집계를 같은 서버 가드로 차단하고, 채팅 읽음은 활성 방 진입과 실시간 수신 모두 서버 정본과 전역 핀 캐시를 함께 갱신한다. 모바일 채팅은 Visual Viewport 기반 높이와 기존 Tailwind 레이아웃을 사용해 키보드 위에 입력창을 유지한다.

**Tech Stack:** Next.js 16 App Router, React 19, TanStack React Query, oRPC, Socket.IO, Server-Sent Events, PortOne Browser SDK, shadcn/base-ui, Tailwind CSS v4, Drizzle ORM, Vitest.

## 확정 요구사항

- 모바일에서 회원가입 본인인증을 마치면 로그인 폼을 거치지 않고 즉시 회원가입 폼이 보여야 한다. 데스크톱 인증 흐름은 유지한다.
- 운영자 모바일 `더보기`는 데스크톱 운영자 내비게이션과 같은 목적지를 제공한다. 현재 빠진 `채팅`, `면접 일정`을 포함하고, 메뉴가 화면보다 길면 Sheet 내부를 손가락으로 세로 스크롤할 수 있어야 한다.
- 구직자가 채팅방 또는 채팅 메시지를 신고하면 접수 즉시 그 방을 양쪽 참여자의 목록에서 숨기고 양쪽 모두 열람·메시지/미디어 발신·면접/연락처 상호작용을 할 수 없게 한다.
- 신고가 `open` 또는 `reviewing`이면 양쪽 차단 상태를 유지한다. 운영자가 `dismissed`로 기각하면 양쪽에 방을 다시 복구하고, `resolved`로 해결하면 종료 상태를 유지한다.
- 신고로 숨겨진 방은 양쪽 안 읽음 합계와 하단 채팅 핀에서 제외하고 이후 도착 알림으로 핀이 다시 생기지 않아야 한다.
- 채팅방에 진입해 문서가 보이는 순간 현재 기준선까지 읽음 처리한다. 활성·표시 중인 방에서 새 메시지를 받으면 즉시 읽음 처리하고, 백그라운드 탭에서는 기존처럼 안 읽음 상태를 유지한다.
- 읽음 처리는 메시지 작성이나 전송을 전제로 하지 않는다. 사용자가 채팅방에 들어가 마지막 수신 메시지를 화면에서 확인하기만 해도 서버 읽음 정본, 채팅 목록의 방별 안 읽음 수, 계정 전체 안 읽음 합계와 하단 채팅 핀이 함께 `0`으로 갱신되어야 한다.
- 채팅방을 나간 뒤 목록을 새로고침하거나 30초 이상 기다렸다가 다시 조회해도 읽음 상태가 유지되어야 한다. 메시지를 하나 보내야만 핀이 사라지는 동작은 허용하지 않는다.
- 이번 키보드 대응 범위는 사진에서 확인된 모바일 채팅방 화면으로 한정한다.
- 모바일 키보드가 열리면 사이트 하단 내비게이션은 숨기고, 메시지 입력창은 키보드 바로 위에 유지하며, 메시지 목록 영역만 남은 높이에 맞춰 줄어들고 내부 스크롤되어야 한다.
- 모바일 채팅 제목은 글씨 크기를 줄여 한 줄로 유지하고 넘치는 부분은 `…`으로 표시한다. `공고 보기`, 채팅 상태, 실시간 연결 상태는 제목 아래 별도 행에 배치한다.
- 브랜치와 PR은 하나로 유지하고 PR base는 `develop`으로 한다. 커밋은 아래 3개 작업 영역으로 분리한다.
- 사용자가 별도로 요청하기 전에는 커밋하거나 원격에 push하지 않는다.
- 사업자 인증 서류는 업체당 최대 5개다. JPG·PNG·WEBP·PDF만 허용하고 파일당 10MB 상한과 실제 파일 서명 검사를 채팅 첨부 정책과 동일하게 적용한다.
- 서류가 없어도 업체 정보 제출 API는 허용한다. 운영자 화면에는 `첨부 서류 없음`을 명확히 표시하고 승인·반려는 운영자가 판단한다.
- 기존 승인·심사 중 업체에는 서류를 다시 요구하지 않는다. 배포 후 신규 제출과 반려 후 재제출부터 첨부 UI를 제공한다.
- 업체 정보 최초 제출 전에는 조직 ID가 없으므로 파일을 첨부하지 않는다. 최초 제출로 조직이 생성된 뒤에는 승인 대기 중에도 누락 서류를 추가할 수 있지만 기존 서류 삭제·교체는 잠근다. 반려 후에는 삭제·교체·재제출할 수 있고, 승인 완료 후 파일을 추가·교체하면 사업자 정보 변경과 동일하게 승인 대기로 전환한다.
- 교체·삭제된 서류 객체는 즉시 삭제한다. 운영자는 이미지 원본 미리보기와 PDF 열기, 모든 서류 다운로드를 제공받는다.
- 사용자 결정에 따라 사업자 인증 서류도 기존 `GCS_PUBLIC_BUCKET`에 저장한다. 따라서 객체 URL을 아는 비로그인 사용자도 접근할 수 있으며 별도 비공개 버킷·서명 다운로드는 이 범위에 포함하지 않는다.
- 사이트 공통 metadata의 `keywords`는 기존 목록과 요청 목록의 합집합을 한 개의 `<meta name="keywords">`로 출력한다. 중복은 제거하고 `구인구직 사이트`는 하나의 키워드 문구로 유지한다.

## 현재 원인

1. `usePortOneVerification`의 모바일 리디렉션 복귀 과정에서 `router.replace(pathname)`가 `auth=signup` 검색 파라미터를 제거한다. `AuthPanel`은 URL의 초기 모드만 상태로 잡으므로 저장된 `auth-panel:signup` intent가 있어도 로그인 모드로 다시 마운트될 수 있다.
2. 모바일 운영자 `MOD_MORE_GROUPS`는 데스크톱 `MODERATOR_NAV_ITEMS`를 수동 복제하면서 `회원 관리`의 `채팅`, `면접 일정`을 누락했다. `SheetContent`와 메뉴 래퍼에도 사용 가능한 높이·`overflow-y-auto`가 없어 하단 고정 탭 뒤의 `사이트` 그룹까지 스크롤할 수 없다.
3. `throwIfHiddenByMyReport`와 `getRoomIdsHiddenByMyReport`는 이름과 구현 모두 신고자 본인만 차단한다. 상대 참여자는 같은 방을 계속 조회하고 발신할 수 있고, 상대 발신이 신고자의 전역 안 읽음 이벤트와 핀을 다시 증가시킬 수 있다.
4. 최신 `develop`에는 기준선 기반 `markRead`, 실패 재시도, 전역 안 읽음 정본 덮어쓰기와 재주장 로직이 있지만, 실제 배포 검수에서는 상대가 보낸 안 읽은 메시지 `1`이 있는 방에 들어가 읽고, 메시지를 보내지 않은 채 목록으로 나온 뒤 즉시 및 30초 후 새로고침해도 `1`이 남았다. 로컬 DB 재현에서도 방 진입 시 두 번째 최신 메시지까지 읽음 영수증이 생성되고 정확히 최신 한 건만 남았다. 메시지 조회와 실시간 수신 경계에서 클라이언트가 한 단계 오래된 기준선을 보낸 뒤, 서버가 `unreadCount: 1`을 반환해도 클라이언트가 같은 오래된 기준선만 재주장해 영구히 수렴하지 않는 것이 원인이다. 같은 방에서 메시지를 하나 보내면 더 최신 기준선이 생겨 그제야 이전 한 건이 읽히므로 발신 의존 증상도 설명된다.
5. 채팅 헤더는 모바일에서도 제목과 모든 액션을 하나의 `flex-wrap` 행에서 경쟁시킨다. 제목 컨테이너가 `min-w-0 flex-1`이라 버튼·배지가 공간을 차지하면 제목이 한두 글자 폭까지 압축된다.
6. 채팅 패널 높이는 CSS `100dvh` 계산만 사용한다. Android Chrome에서 소프트 키보드와 브라우저 UI가 Visual Viewport를 바꾸는 동안 레이아웃 뷰포트·고정 하단 내비·입력창이 서로 다른 높이를 기준으로 배치되어 헤더와 메시지 영역이 찌그러질 수 있다.
