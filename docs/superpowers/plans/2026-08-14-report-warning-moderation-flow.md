# 신고·경고 운영 흐름 개선 계획

**Goal:** 로그인 후 페이지가 준비된 뒤 팝업을 노출하고, 신고 중복 안내·신고 내역 페이지네이션·운영자 바로가기와 신고 대상 사용자 조치를 보완하며, 누적 경고 5회에 한정된 72시간 기능 제한과 경고 되돌리기를 구현한다.

**Base:** 최신 `origin/develop`의 `482319f5`를 반영한 `feat/report-warning-moderation-flow` 브랜치.

## 확정 정책

- 팝업은 로그인 화면에 노출하지 않고 로그인 성공 후 도착한 페이지의 인증·라우트·팝업 조회가 준비된 다음 노출한다.
- 같은 신고자가 같은 대상을 다시 신고할 때 기존 신고가 `open` 또는 `reviewing`이면 새 행을 만들지 않고 `이미 신고된 글입니다. 처리결과를 기다려주세요.`를 표시한다.
- 사용자 신고 내역은 최신순으로 한 페이지에 10개씩 표시한다.
- 운영자 콘솔 통계는 검수 대기 `/moderator`, 신고 대기 `/moderator/reports`, 경고 사용자 `/moderator/users?status=warned`로 이동한다.
- 구직자의 누적 경고가 정확히 5회가 되는 순간부터 72시간 동안 자유수다(`free`), 밤문화 이야기(`work_talk`), 중고거래(`market`)의 글과 댓글 작성을 막는다.
- 구인자의 누적 경고가 정확히 5회가 되는 순간부터 72시간 동안 새 공고 등록만 막는다. 기존 공고 수정·끌어올리기·광고 등은 제한하지 않는다.
- 6·7회 경고에서는 72시간 제한을 새로 시작하거나 연장하지 않는다. 8회 이상 추가 제재는 이번 범위에서 제외한다.
- 제한 안내는 역할별 문구와 서버 기준 남은 시간을 `HH:MM:SS`로 표시한다.
- 정상 복구는 누적 경고 횟수를 유지하고 계정 상태를 정상으로 바꾸며 현재 72시간 제한만 즉시 해제한다.
- 72시간이 모두 지나면 관리자 조작 없이 서버가 계정 상태를 자동으로 `active`로 정리하고 역할별 제한도 종료한다.
- 경고 되돌리기는 가장 최근의 아직 되돌리지 않은 경고 한 건만 취소한다. 5회 경고를 되돌려 4회가 되면 계정 상태를 정상으로 바꾸고 제한을 해제한다.
- 신고 상세는 글·댓글·공고 작성자 또는 채팅방 피신고자를 신고자와 나란히 표시한다. 채팅방 신고의 오른쪽 요약은 `채팅방 → 피신고자 → 신고자` 순서로 표시하고, 채팅방만 말풍선 아이콘을 사용하며 피신고자와 신고자는 사용자 아이콘을 사용한다. 피신고자 카드와 `유저 보기`는 정확한 `/moderator/users/{userId}`로 이동하고 `경고`는 사용자 관리와 동일한 서버 경고 처리를 사용한다.
- 신고 상세의 `경고` 버튼은 즉시 실행하지 않고 shadcn `AlertDialog`로 `정말 이 {유저명}에게 경고를 주시겠습니까?`를 확인한다. `확인`만 경고를 부여하고 `취소`는 아무 변경도 하지 않는다.
- 사용자 목록의 검색·상태·역할·인증·신고/경고 필터와 현재 페이지는 URL에 보존한다. 상세에서 경고 등 조치를 마친 뒤 목록으로 돌아갈 때 해당 URL을 복원하여 기존 필터와 페이지가 유지되어야 한다.
- 경고 제한 다이얼로그의 `확인`은 실제로 다이얼로그를 닫아야 한다. 밤문화 이야기의 저장 key(`work_talk`)와 URL slug(`work-talk`)를 혼동하지 않고 모든 글쓰기 진입 경로를 차단한다.
- 탈퇴 사용자도 보존된 사용자 ID로 상세 화면에 진입할 수 있어야 한다.

## 데이터 모델과 migration

- `bambi_profile.warning_restriction_until` nullable timestamp를 추가한다.
- migration `0093_needy_lightspeed.sql`에서 컬럼과 만료 시각 조회용 인덱스를 추가한다.
- 경고 누적 횟수는 `admin_moderation_action`의 `set_status:warned`에서 `revert_warning`으로 취소된 원본 경고를 제외해 계산한다.
- `revert_warning` metadata에 취소한 경고 action ID를 저장하고 유일한 원본 한 건만 되돌리도록 트랜잭션에서 잠근다.

## 구현 작업

1. 팝업 준비 상태
   - 인증 완료, pathname 확정, 대상 페이지 데이터 및 팝업 조회 완료 후 다음 렌더 프레임에서 팝업을 연다.
   - 로그인 전후 라우트 전환 중 이전 페이지 팝업이 잠깐 보이지 않도록 준비 상태를 pathname마다 초기화한다.
2. 신고 API와 사용자 신고 내역
   - 중복 신고 응답에 기존 신고 여부를 명시하고 모든 신고 UI가 공통 안내 문구를 사용한다.
   - `listMyReports`를 page/pageSize 기반 응답으로 변경하고 10개 단위 페이지 UI를 추가한다.
3. 운영자 콘솔과 신고 상세
   - 통계 카드에 키보드 접근 가능한 링크를 적용한다.
   - 사용자 관리의 status 쿼리 파라미터를 초기 필터에 반영한다.
   - 신고 대상 작성자/피신고자 ID와 표시 정보를 서버 응답에 포함하고 카드·경고·유저 보기 액션을 연결한다.
4. 경고 정책
   - 경고 부여, 정상 복구, 최근 경고 되돌리기를 한 서버 서비스로 통합한다.
   - 1~4회는 `active`, 정확히 5회에서 `warned`와 72시간 제한, 6~7회는 기존 상태·만료 시각 유지로 처리한다.
   - 서버의 커뮤니티 글/댓글 생성과 공고 생성에 범위가 좁은 제한 가드를 추가한다.
   - 구직자 글쓰기/댓글 작성과 구인자 모든 공고 등록 진입점에 남은 시간 다이얼로그를 표시하되 서버 가드를 진실값으로 둔다.
5. 검증
   - 경고 4→5, 5→6, 정상 복구 후 6회, 되돌리기 5→4·1→0과 중복 되돌리기를 테스트한다.
   - 최근 경고를 연속으로 되돌릴 때 목록 집계가 매번 1씩 감소하는지, 제한 다이얼로그 확인 동작과 `work-talk` URL 차단을 회귀 검증한다.
   - 세 게시판 글·댓글만 차단되고 다른 게시판 및 다른 기능은 허용되는지 테스트한다.
   - 구인자 신규 공고만 차단되고 수정·끌어올리기는 유지되는지 테스트한다.
   - 중복 신고, 사용자 신고 내역 10개 페이지, 운영자 링크와 정확한 사용자 ID 이동을 테스트한다.
   - 관련 Vitest, 패키지 typecheck, Ultracite 검사를 실행한다.

## 제외 범위

- 경고 8회·13회 등 후속 제재 단계.
- 기존 게시물·공고 숨김 또는 삭제.
- 구인자의 공고 수정·광고·끌어올리기 제한.
- 지정한 세 게시판 외 구직자 기능 제한.

- web, API, DB `check-types` 통과.

## 사용자 관리 페이지네이션 위치 안정화

- 사용자 관리 표는 페이지마다 10개 행의 표시 공간을 항상 예약해, 조직명 유무나 마지막 페이지의 사용자 수와 관계없이 페이지네이션 위치를 고정한다.
- 이름 셀은 사용자명 1줄과 조직명 1줄의 동일한 높이를 사용한다.
- 조직명이 여러 개인 경우 말줄임으로 숨기지 않고 모두 한 줄에 표시하며, 좁은 화면에서는 표의 가로 스크롤로 전체 내용을 확인할 수 있게 한다.
- 데스크톱과 모바일에서 연속된 페이지를 이동하며 이전·다음 버튼의 세로 위치가 변하지 않는지 확인한다.
- 사용자 관리 표의 건수·현재 페이지와 페이지 이동 컨트롤은 표 테두리 밖의 별도 하단 영역에 둔다.
- 데스크톱에서는 페이지 이동 컨트롤을 화면 가운데에 고정하고, 모바일에서는 건수 정보와 같은 줄의 오른쪽에 배치한다.
- 이전·다음 버튼 사이에 숫자 전용 페이지 입력란을 제공한다. Enter 또는 포커스 해제 시 해당 페이지로 이동하며, 범위를 벗어난 값은 첫 페이지나 마지막 페이지로 보정하고 빈 값은 현재 페이지로 복구한다.
- 운영자 신고 대기 표에도 같은 숫자 전용 페이지 입력란을 제공해 원하는 신고 페이지로 바로 이동할 수 있게 한다.
- 운영자 공고 관리, 검수 대기, 금칙어 관리, 채팅 관리, 수집 공고 관리와 수집 커뮤니티 글 관리에도 같은 숫자 전용 페이지 입력란을 제공한다. 서버 페이지네이션 화면도 숫자 제한, 범위 보정, Enter·포커스 해제 이동 규칙을 공통으로 사용한다.
- 구직자·구인자 신고 내역과 구인자 내 공고·광고 관리의 데스크톱 및 모바일 페이지네이션에도 같은 숫자 전용 페이지 입력란을 제공한다.

## 공용 페이지 이동과 출석·채팅 목록 보완

- 이전 버튼, 숫자 전용 페이지 입력란, 다음 버튼을 하나의 공용 `PageControls` 컴포넌트로 묶고 기존 숫자 입력 페이지네이션 화면도 이를 재사용한다.
- 운영자 채팅 관리는 서버와 화면 모두 페이지당 10개로 통일한다.
- 운영자 출석 관리는 기존 더 보기 방식을 페이지당 10개의 일반 페이지네이션으로 변경하고 전체 건수, 이전·다음 버튼, 숫자 페이지 입력을 제공한다.
- 출석 검색·역할 필터·정렬이 바뀌면 1페이지로 되돌리고, 전체 건수는 현재 검색·역할 필터 기준으로 계산한다.
- 운영자 후기 관리도 상태 필터별로 한 페이지에 10개를 표시하고 공용 페이지 이동 컨트롤을 사용한다.
