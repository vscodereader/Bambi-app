# 메인페이지 운영자 팝업 관리 설계 계획

> **상태:** 2026-08-05 기준 확정 설계. 사용자와 확정한 질문 1~58 및 모든 후속 결정을 구현 계약으로 기록한다.

**Goal:** 운영자가 메인페이지 팝업을 설정하고, PC와 모바일 사용자가 서로 다른 반응형 노출 방식으로 이미지형 또는 글쓰기형 팝업을 확인할 수 있게 한다. 각 팝업은 개별 닫기와 정확히 24시간 숨김을 지원하며, 이미지형 팝업은 로그인 후 밤비 내부 경로로 이동하는 링크를 선택적으로 제공한다.

**Architecture:** 최신 `develop`에서 통합 기능 브랜치 하나를 사용한다. 운영자 설정은 서버의 운영자 전용 API와 영속 저장소를 통해 관리하고, 공개 메인페이지에는 현재 노출 가능한 팝업만 최소 공개 투영으로 전달한다. 브라우저의 24시간 숨김 상태는 팝업 ID별 `localStorage` 만료 시각으로 관리하고 단순 `창닫기`는 영속화하지 않는다. PC에서는 비모달 다중 팝업 레이어, 모바일에서는 배경을 차단하는 단일 팝업 큐로 렌더링한다. 이미지 편집 PR #82가 아직 `develop`에 없으므로 구현 시 전체 편집 화면을 복제하지 않고 팝업에 필요한 공용 편집 경계를 별도로 가져와 재사용하며, 추후 병합 충돌이 생기면 공용 컴포넌트 한 벌로 정리한다.

**Tech Stack:** Next.js 16 App Router, React 19, TanStack Query, better-auth, oRPC, Drizzle ORM/PostgreSQL, Tiptap, shadcn/ui(base-ui), Tailwind CSS v4, Vitest, Turbo/pnpm.

## 작업·브랜치 규칙

- 기준 브랜치는 최신 `origin/develop`이다.
- 통합 브랜치는 `feat/main-popup-management`이며 별도 worktree `C:\Users\user\bambi\.worktrees\main-popup-management`에서 작업한다.
- 설계서를 먼저 별도 커밋하고, 사용자와 나머지 결정을 확정한 후 구현을 시작한다.
- 이미지 편집 기능은 팝업 브랜치에 필요한 부분을 별도로 가져올 수 있다. 다만 동일 기능의 복제본 두 벌을 유지하지 않고 공용화 가능한 resize·preview 경계를 재사용한다.
- 운영자 화면은 기존 shadcn/ui와 Tailwind 구성, 운영자 콘솔의 카드·입력·버튼·상태 UI를 재사용한다. 새 인라인 스타일과 새 CSS 파일은 만들지 않는다.
- DB 변경은 Drizzle migration으로 남기며 `db:push`를 사용하지 않는다. migration 번호는 구현 직전에 최신 번호를 다시 확인한다.
- API와 화면 양쪽에서 운영자 권한을 강제한다.
- 미확정 요구사항은 사용자 답변 전 임의로 정하지 않는다.

## 확정 범위

### 1. 노출 페이지와 대상

- 루트 `/`는 현재 역할 확인 뒤 `/seeker`로 이동하므로, 1차 범위에서는 실제 메인 화면인 `/seeker`에서만 팝업을 노출한다. 로그인 화면(`/seeker?auth=login|signup`)에는 팝업을 겹쳐 띄우지 않는다.
- 비회원·구직자·구인자·운영자를 포함한 모든 방문자에게 같은 활성 팝업 목록을 적용한다.
- PC와 모바일 웹을 모두 지원한다.
- 팝업은 별도 브라우저 창이 아니라 현재 페이지 위에 표시되는 인페이지 레이어다.
- 팝업 바깥 클릭과 `Escape` 키로는 닫히지 않는다. 사용자는 반드시 해당 팝업의 `오늘 하루 보지 않기` 또는 `창닫기`를 사용해야 한다.

### 2. PC 노출 동작

- 활성 팝업 여러 개를 동시에 표시한다.
- 설정 번호 순서대로 화면 왼쪽에서 오른쪽으로, 가능한 한 서로 겹치지 않게 배치한다.
- 가용 너비가 부족해 겹침이 불가피하면 다음 팝업을 바로 위쪽으로 조금씩 어긋나게 배치한다. 정확한 간격은 반응형·최대 개수 결정 후 확정한다.
- 팝업을 사용자가 드래그하여 이동하는 기능은 제공하지 않는다.
- 사용자가 누른 팝업을 현재 팝업 묶음의 맨 앞으로 올린다.
- 팝업 순서는 운영자 설정 번호를 사용하며 별도의 순서 변경 기능은 제공하지 않는다.
- 팝업이 덮지 않은 메인페이지 영역은 클릭·스크롤할 수 있다. 팝업이 덮은 영역은 팝업이 포인터 이벤트를 받으므로 뒤 콘텐츠를 조작할 수 없다.

### 3. 모바일 노출 동작

- 모바일 화면에 맞춰 팝업 전체를 반응형으로 축소한다. 운영자가 정한 비율과 내용은 유지하면서 화면 폭을 넘지 않게 표시한다.
- 활성 팝업을 설정 번호 순서의 큐로 관리하고 한 번에 한 개만 같은 위치에 표시한다.
- 현재 팝업에서 `오늘 하루 보지 않기` 또는 `창닫기`를 누르면 바로 다음 팝업이 같은 자리를 채운다.
- 모든 표시 대상 팝업을 처리하기 전에는 배경 메인페이지의 클릭·스크롤 등 다른 작업을 차단한다.
- 마지막 팝업을 처리하면 차단 레이어를 제거하고 메인페이지를 정상 조작할 수 있다.

### 4. 닫기와 24시간 숨김

- `오늘 하루 보지 않기`는 팝업 전체 묶음이 아니라 팝업 ID별로 따로 적용한다.
- 숨김 기간은 자정까지가 아니라 사용자가 누른 시점부터 정확히 24시간이다.
- 숨김 만료 시각은 해당 브라우저의 `localStorage`에 팝업 ID별로 저장한다. 같은 계정이어도 다른 브라우저·다른 기기에는 공유하지 않는다.
- 사용자가 사이트의 다른 경로를 방문하거나 새로고침·로그인·로그아웃한 뒤 메인페이지로 돌아와도 아직 24시간이 지나지 않은 팝업은 다시 열지 않는다.
- 만료된 저장값은 다음 메인페이지 진입 때 무시하고 정리한다.
- `창닫기`는 브라우저 저장소에 기록하지 않는다. 현재 메인페이지 렌더링 동안만 닫고, 새로고침하거나 다른 경로에서 메인페이지로 다시 진입하거나 로그인 흐름을 거쳐 돌아오면 다시 표시한다.
- 24시간 숨김 중 운영자가 해당 팝업의 저장된 내용이나 설정을 수정하면 기존 숨김을 무효화하고 즉시 다시 노출한다.
- 이를 위해 공개 팝업에 저장 revision을 포함하고, 브라우저 숨김 기록에도 숨길 당시 revision을 함께 저장한다. 현재 revision과 저장 revision이 다르면 만료 시각이 남아 있어도 숨김 기록을 제거한다.

### 5. 이미지형 팝업 내부 링크

- 운영자 설정의 다섯 번째 단계로 팝업별 `링크 삽입`을 제공한다.
- 링크는 이미지형 팝업의 이미지 영역에만 적용한다. 글쓰기형 팝업에는 적용하지 않는다.
- 목적지는 밤비 서비스 내부 주소만 허용한다. 서버는 상대 경로를 검증하고 외부 origin, 프로토콜 포함 URL, protocol-relative URL(`//...`)을 거부한다.
- 링크가 설정된 이미지에는 클릭 가능한 의미와 키보드 접근성을 제공한다. 하단 `오늘 하루 보지 않기`와 `창닫기`는 이미지 링크 영역 밖에 두어 이동 이벤트가 발생하지 않게 한다.
- 로그인한 사용자가 이미지를 선택하면 현재 탭에서 목적지로 이동한다.
- 비로그인 사용자가 이미지를 선택하면 로그인 화면으로 이동하고, 로그인 성공 뒤 원래 설정된 내부 목적지로 자동 이동한다. 기존 인증 흐름의 안전한 return URL 계약을 재사용한다.
- 링크가 없는 이미지형 팝업은 이미지를 눌러도 이동하지 않으며 클릭 커서를 표시하지 않는다.

### 6. 운영자 팝업 관리 화면

- 운영자 콘솔의 `콘텐츠` 메뉴에서 `크롤링` 바로 아래에 `팝업` 메뉴를 추가한다.
- 전용 주소는 `/moderator/popups`로 사용한다.
- 화면 진입, 설정 조회, 이미지 조회·업로드·편집, 저장·삭제를 화면뿐 아니라 모든 서버 API에서 운영자 전용으로 강제한다.
- 팝업 개수에는 제품 정책상 최대치를 두지 않는다. 개수는 0 이상의 정수로 검증하며, 입력한 개수만큼 번호가 고정된 팝업 설정 카드를 만든다.
- 설정 개수를 줄이면 제거 대상 번호와 삭제 영향을 경고하고 운영자 확인을 받은 뒤 해당 팝업의 이미지·글·링크·예약·감사 데이터를 완전히 삭제한다.
- 각 팝업에 `사용/사용 안 함` 스위치를 제공한다. `사용 안 함`인 팝업은 설정과 콘텐츠를 보존하되 공개 목록에서 제외한다.
- 팝업 개수 설정에는 별도 적용/저장 동작을 두고, 각 팝업 카드에도 해당 팝업만 저장하는 별도 저장 버튼을 제공한다. 한 팝업 저장 실패가 다른 팝업의 draft나 저장 상태를 바꾸지 않는다.
- 편집은 서버 저장본에서 만든 클라이언트 draft로 진행한다. 저장 성공 전에는 메인페이지 공개 결과를 바꾸지 않으며, 취소하면 해당 팝업의 모든 미저장 변경을 버리고 마지막 서버 저장본으로 되돌린다.
- 각 팝업에 마지막 수정 운영자의 표시 이름과 마지막 수정 시각을 보여준다. 저장 성공 응답으로 즉시 갱신한다.
- 운영자 화면은 기존 운영자 콘솔의 카드, Field/Input, Button, Switch, AlertDialog, 상태·토스트 UI를 재사용한다.

### 7. 팝업 콘텐츠 유형

- 팝업 하나는 `이미지형`과 `글쓰기형` 중 정확히 하나만 가진다.
- 콘텐츠 유형을 전환하면 현재 유형의 콘텐츠가 삭제된다는 확인을 먼저 표시한다.
- 운영자가 전환을 확인해도 삭제는 draft에서만 수행하며, 해당 팝업의 저장 버튼을 눌러 성공하기 전에는 서버의 기존 콘텐츠를 유지한다.
- 전환 뒤 취소하면 유형과 삭제 예정 콘텐츠 모두 마지막 서버 저장 상태로 복원한다.
- 이미지형 팝업에는 이미지 한 장만 저장한다.
- 이미지 업로드는 기존 정책과 동일하게 JPEG·PNG·WebP, 파일당 최대 10MB를 허용한다. GIF는 이번 범위에서 제외한다.

### 8. 이미지형 편집과 실제 팝업 크기

- `팝업창 사이즈 조절`에서 기존 수집 공고 이미지 편집 기능의 크기 조절, 자르기, 복사, 붙여넣기, 삭제, 다운로드, 실행 취소를 제공한다.
- resize 계약도 기존 편집기와 동일하다. 네 모서리는 드래그 시작 비율을 유지하고, 좌·우 변은 너비만, 상·하 변은 높이만 변경하며 반대편 경계를 고정한다.
- 자르기는 자유 비율이며 기존 밝은 유지 영역·어두운 제거 영역과 8방향 조절 UI를 재사용한다.
- 원본 업로드 이미지는 그대로 보존하고 운영자 편집본을 별도로 저장한다. `원본으로 초기화`를 제공하며 초기화도 저장 전 draft이므로 취소할 수 있다.
- 실행 취소는 저장 전 편집 이력에만 적용하고 저장 성공 시 undo 기록을 초기화한다.
- 다운로드는 현재 이미지 한 장을 원래 MIME에 맞는 확장자로 내려받는다.
- 운영자가 저장한 표시 이미지의 너비·높이에 하단 `오늘 하루 보지 않기`·`창닫기` 버튼 영역 높이를 더한 값이 실제 메인페이지 팝업의 외곽 크기다.
- 운영자가 별도 크기 조절을 하지 않으면 업로드 이미지의 자연 너비·높이를 표시 이미지 크기로 사용하고 동일하게 하단 버튼 영역을 더한다.
- 팝업 관리 페이지 안에서 공유되는 내부 이미지 clipboard를 둔다. 브라우저·운영체제 clipboard에는 Base64를 쓰지 않는다.
- 운영자가 한 팝업의 이미지를 복사한 뒤 다른 팝업의 이미지 영역에 붙여넣을 수 있다.
- 대상 팝업에 이미지가 이미 있으면 기존 이미지가 교체된다는 확인을 먼저 표시하고, 확인한 경우에만 대상 팝업 draft의 한 장을 복사본으로 대체한다.
- 같은 팝업에 다시 붙여넣을 때도 동일한 교체 확인을 거쳐 복사본으로 대체한다.
- 붙여넣은 이미지는 source와 ID·편집 상태를 공유하지 않는 독립 복사본이다. 이후 대상에서 자르기·resize·초기화해도 source 팝업은 바뀌지 않는다.
- 복사·붙여넣기는 저장 전 draft 작업이며 대상 팝업의 실행 취소 한 단계로 기록한다. 대상 팝업을 취소하면 교체 전 서버 저장본으로 돌아가고, 별도 저장에 성공해야 공개 결과가 바뀐다.

### 9. 글쓰기형 편집과 크기

- 글쓰기형의 기본 콘텐츠 영역은 `420 × 320px`이다. 가로형·세로형 모두 만들 수 있도록 초기값일 뿐 비율은 고정하지 않는다.
- 콘텐츠 영역 사방에 네 모서리와 상·하·좌·우 변을 합친 8방향 resize handle을 제공한다.
- 모든 handle은 자유 크기 조절이다. 모서리를 움직여도 기존 비율을 유지하지 않고 너비와 높이를 포인터 이동량에 맞춰 각각 변경한다.
- 콘텐츠 영역의 최소값은 `280 × 160px`, 최댓값은 현재 PC 화면의 `90vw × 80vh`다. 정확한 px 숫자 입력과 마우스 resize를 함께 제공한다.
- 사용자가 글을 입력하면 설정 너비 안에서 줄바꿈하고 내용에 맞춰 팝업 콘텐츠 높이를 자동으로 늘린다. 설정 높이는 최소 미리보기 높이로 취급한다.
- 자동 높이는 현재 viewport의 `80vh`까지만 증가한다. 내용이 그 높이를 넘으면 외곽 팝업은 더 커지지 않고 본문 편집·읽기 영역에 세로 스크롤을 표시한다.
- 최종 콘텐츠 높이에 하단 버튼 영역을 더한 크기를 실제 글쓰기형 팝업 외곽 크기로 사용하므로 운영자 편집 화면이 공개 결과의 WYSIWYG 미리보기다.
- 본문 배경은 흰색, 기본 글자색은 검은색으로 고정한다. 제목 입력은 제공하지 않고 본문만 저장한다.
- 글 정렬 기능은 이번 범위에서 제외하고 기본 왼쪽 정렬을 사용한다.
- 수다방 `community-editor`의 Tiptap StarterKit과 굵게·기울임·취소선·글머리 목록·번호 목록·링크 기능 및 툴바 UI를 공용화해 재사용한다.
- 글쓰기형에서는 이미지 확장과 이미지 삽입 버튼을 제외한다. 이미지 노드가 포함된 비정상 입력도 서버 정규화/검증에서 거부한다.
- 기존 수다방 에디터에는 글자 크기가 없으므로 공용 TextStyle/FontSize 확장을 추가하고 `12·14·16·18·20·24·28·32·40·48px` 목록만 허용한다.
- 팝업 본문에 저장되는 Tiptap JSON은 허용 노드·마크와 글자 크기를 서버에서 다시 검증한다. 공개 화면은 같은 확장 세트의 읽기 전용 renderer로 표시한다.

### 10. 노출 시작·종료 예약

- 각 팝업에 한국 시간(`Asia/Seoul`) 기준의 선택적 `시작 일시`와 `종료 일시`를 저장한다.
- 새로 설정하거나 기존 값을 변경하는 시작 일시는 선택 순간의 한국 시간 현재 분 이상만 허용한다. 과거 날짜는 달력에서 비활성화하고, 오늘의 과거 시각은 현재 분으로 clamp한다.
- 이미 노출을 시작해 DB에 과거 시작 일시가 저장된 팝업은 그 값을 그대로 표시·보존할 수 있다. 운영자가 시작 일시를 새 값으로 바꾸는 순간부터 현재 분 이상 규칙을 적용한다.
- 시작·종료를 모두 설정하면 종료 일시는 반드시 시작 일시보다 뒤여야 한다. 같은 시각이나 더 이른 종료는 화면과 서버에서 거부한다.
- 두 값이 모두 비어 있으면 사용 스위치와 콘텐츠 유효 조건만 만족하는 즉시 상시 노출한다.
- 시작만 있으면 시작 일시부터 종료 없이 노출하고, 종료만 있으면 즉시 노출을 시작해 종료 일시에 내린다.
- 둘 다 있으면 `시작 일시 <= 현재 시각 < 종료 일시` 구간에만 노출한다.
- 종료 시각이 지나면 공개 목록에서 자동 제외하되 운영자 설정·콘텐츠·감사 정보는 보존한다.
- 예약 시간이 맞아도 이미지나 글 본문이 비어 있는 팝업은 공개 목록에 포함하지 않는다.
- 공개 목록 API가 서버 현재 시각을 기준으로 사용 여부·예약 구간·콘텐츠 유효성을 판정한다. 클라이언트 시계만으로 공개 여부를 결정하지 않는다.

### 11. 작은 화면 반응형

- 운영자가 저장한 콘텐츠가 모바일 viewport보다 크면 콘텐츠의 원래 종횡비를 유지하며 화면 안으로 자동 축소한다.
- 이미지형과 글쓰기형 모두 콘텐츠 영역을 동일한 scale로 축소해 내부 배치와 글자 비율을 유지한다.
- 하단 `오늘 하루 보지 않기`와 `창닫기` 버튼 영역은 콘텐츠 scale에 포함하지 않는다. 모바일에서도 누르기 쉬운 고정 컨트롤 크기를 유지한다.
- 모바일 외곽 팝업 크기는 `축소된 콘텐츠 크기 + 고정 하단 버튼 영역`으로 계산한다.

## 사용자 상태 모델

각 공개 팝업에는 서버가 발급한 안정적인 팝업 ID가 있어야 한다. 브라우저 상태는 다음 두 종류를 분리한다.

```ts
interface MainPopupClientState {
	closedPopupIds: Set<string>;
	hiddenByPopupId: Record<
		string,
		{ hiddenUntil: number; revision: number }
	>;
}
```

- `closedPopupIds`는 메모리 상태이며 새 메인페이지 진입 시 초기화한다.
- `hiddenByPopupId`는 `localStorage`에서 읽고 `Date.now()` 및 공개 팝업 revision과 비교한다.
- 공개 활성 목록에서 `hiddenUntil > Date.now()`이고 revision도 같은 팝업과 현재 렌더링에서 닫은 팝업을 제외해 표시 목록을 계산한다.
- 만료되었거나 현재 팝업 revision과 다른 숨김 기록은 즉시 제거한다.
- PC는 계산된 목록 전체를 렌더링하고 모바일은 첫 번째 항목만 렌더링한다.
- 서버 렌더링과 hydration 불일치를 막기 위해 브라우저 저장소 판정은 클라이언트 마운트 후 수행하며, 판정 전 팝업이 순간 노출되지 않게 초기 준비 상태를 둔다.

## 접근성·상호작용 계약

- `오늘 하루 보지 않기`와 `창닫기`는 실제 `button` 또는 기존 shadcn 제어 컴포넌트를 사용하고 명확한 접근성 이름을 제공한다.
- 외부 클릭과 `Escape`가 닫기 동작으로 연결되지 않도록 기본 Dialog dismiss 계약을 그대로 쓰지 않고, 확정된 PC 비모달/모바일 모달 동작에 맞는 전용 레이어를 구성한다.
- 모바일 단일 팝업은 배경을 비활성화하고 포커스를 현재 팝업에 가둔다.
- PC 다중 팝업은 배경을 비활성화하지 않으며, 클릭된 팝업의 전면 순서를 상태로 관리한다.
- 이미지 링크는 마우스뿐 아니라 키보드로도 실행할 수 있어야 한다.

## 예상 구현 영역

미확정 요구사항을 모두 확정한 뒤 파일과 커밋 단위를 구체화한다. 현재 예상 경계는 다음과 같다.

1. DB schema·migration·운영자/공개 oRPC 계약
2. 운영자 팝업 개수·콘텐츠·크기·시간·링크 설정 화면
3. 이미지 편집 공용 경계와 글쓰기형 Tiptap 편집/미리보기
4. 메인페이지 PC 다중 레이어·모바일 큐·24시간 브라우저 상태
5. 로그인 return URL과 내부 링크 검증
6. API·Web 단위 테스트, 반응형·권한·브라우저 수동 검증

## 확정 요구사항 테스트 기준

- 비회원과 모든 회원 역할에서 실제 메인 `/seeker`에 같은 활성 목록이 조회된다.
- 다른 경로에는 팝업이 렌더링되지 않는다.
- 바깥 클릭과 `Escape`로 팝업이 닫히지 않는다.
- PC에서는 여러 팝업이 동시에 왼쪽부터 배치되고 배경의 노출 영역을 조작할 수 있다.
- PC에서 선택한 팝업이 전면으로 올라오고 팝업 자체는 드래그되지 않는다.
- 모바일에서는 한 개씩 같은 자리에 표시되고 닫으면 다음 팝업이 즉시 나타난다.
- 모바일에서 마지막 팝업 처리 전까지 배경을 조작할 수 없다.
- 한 팝업의 24시간 숨김이 다른 팝업에 영향을 주지 않는다.
- 숨김은 정확히 24시간 동안 새로고침·경로 이동·로그인 왕복 후에도 유지되고 다른 브라우저에는 공유되지 않는다.
- 단순 닫기는 새로고침·메인 재진입·로그인 왕복 후 복원된다.
- 운영자가 숨겨진 팝업을 다시 저장해 revision이 바뀌면 24시간이 지나기 전이어도 다시 노출된다.
- `/moderator/popups`와 관련 API는 운영자만 접근할 수 있다.
- 개수 감소 확인 전에는 아무 데이터도 지우지 않고, 확인·저장 뒤 제거된 번호의 모든 설정을 삭제한다.
- 사용 스위치를 끈 팝업은 공개되지 않지만 다시 켰을 때 기존 콘텐츠가 유지된다.
- 각 팝업 저장은 다른 팝업 draft에 영향을 주지 않고, 취소는 해당 팝업의 미저장 변경을 모두 버린다.
- 콘텐츠 유형 전환을 취소하면 기존 유형과 콘텐츠가 유지되고, 확인 후 저장하면 이전 유형 콘텐츠가 삭제된다.
- 이미지형은 JPEG·PNG·WebP 한 장과 원본/편집본을 보존하고 원본 초기화를 지원한다.
- 이미지 resize·crop·삭제·다운로드·undo와 페이지 내부 clipboard의 팝업 간 복사·확인 후 교체를 검증한다.
- 붙여넣은 대상 이미지를 편집해도 source 팝업 이미지가 바뀌지 않고, 대상 취소·undo가 교체 전 상태를 복원한다.
- 실제 외곽 팝업 크기가 표시 이미지 크기와 하단 버튼 영역의 합과 일치한다.
- 글쓰기형은 420×320에서 시작하지만 280×160~90vw×80vh 범위에서 8방향 자유 resize되고 모서리도 비율을 고정하지 않는다.
- 글쓰기형은 제목·정렬·이미지 없이 굵게·기울임·취소선·목록·링크와 지정된 열 가지 글자 크기만 저장·렌더링한다.
- 입력 내용이 늘면 설정 너비에서 줄바꿈하며 공개 팝업과 동일하게 높이가 자동 증가하고, `80vh`부터는 본문 내부 스크롤로 전환한다.
- 시작·종료가 비어 있음, 시작만 있음, 종료만 있음, 둘 다 있음의 네 예약 조합을 한국 시간 경계값에서 검증한다.
- 신규·변경 시작 일시는 서버 현재 분보다 이를 수 없고, 종료 일시는 시작 일시와 같거나 이를 수 없다.
- 과거 시작 일시가 이미 저장된 활성 팝업은 시작 값을 변경하지 않는 저장에서 기존 값을 보존한다.
- 종료된 팝업은 공개 목록에서 제외되지만 운영자 데이터는 보존된다.
- 비어 있는 이미지형·글쓰기형은 활성 스위치와 예약 조건을 만족해도 공개되지 않는다.
- 포팅한 날짜·시간 피커가 월 이동·날짜 선택·시분 순환과 직접 입력·확인·설정 안 함을 지원한다.
- 모바일에서는 콘텐츠 비율을 유지해 viewport 안으로 축소하고 하단 버튼은 고정된 접근 가능 크기를 유지한다.
- 이미지형 내부 링크만 허용되고 외부 URL·`//host/path`는 서버에서 거부된다.
- 로그인 사용자는 현재 탭에서 목적지로 이동한다.
- 비로그인 사용자는 로그인 후 원래 내부 목적지로 이동한다.
- 링크가 없을 때 이미지 클릭은 아무 동작도 하지 않고 클릭 커서도 표시하지 않는다.

## 2026-08-05 운영자 수동 검수 보완

- 팝업 개수와 시·분 직접 입력은 문자열 draft를 사용한다. 입력 중 빈 문자열을 허용하고 포커스 시 기존 숫자를 전체 선택해 새 숫자로 바로 교체할 수 있게 하며, 확정 시에만 0 이상의 정수 또는 시·분 범위로 변환한다.
- 팝업 이미지 저장은 10MB 이미지의 원본·편집본 Base64 두 벌과 RPC 포장 오버헤드를 수용하도록 `/rpc/*` 요청 본문 제한을 명시한다. 다른 Fastify 경로의 기본 제한은 변경하지 않는다.
- 이미지 요청이 본문 크기 제한에서 거부되면 `Failed to fetch`를 그대로 노출하지 않고 이미지 용량 때문에 저장하지 못했다는 안내를 표시한다.
- 창 포커스 복귀 재조회와 한 팝업 저장 후 목록 갱신은 미저장 상태인 다른 팝업 draft를 덮어쓰지 않는다. 저장·취소·삭제가 완료된 팝업만 최신 서버 값으로 동기화한다.
- 각 팝업 카드 제목 옆에 휴지통 아이콘 버튼을 제공한다. 확인 후 해당 팝업의 이미지·글·링크·예약·감사 정보를 완전히 삭제하고, 뒤 팝업의 번호를 한 칸씩 당기며 상단 팝업 개수도 즉시 갱신한다.
- 마지막 팝업 카드와 페이지 하단 사이에 충분한 여백을 둔다.

### 추가 검증 기준

- 개수·시·분의 `0`을 지우고 `1`, `34` 등을 입력했을 때 `01`, `034`로 되돌아가지 않는다.
- 1.46MB PNG를 이미지형 팝업에 넣고 저장했을 때 Fastify 본문 제한에 막히지 않는다.
- 이미지를 추가하거나 글을 작성한 뒤 다른 창을 보고 돌아와도 저장 전 draft가 유지된다.
- 한 팝업을 저장해도 다른 팝업의 미저장 이미지·글·예약 값은 유지된다.
- 중간 팝업을 삭제하면 이후 번호가 연속으로 재정렬되고 개수 입력값도 하나 줄어든다.

## 2026-08-05 PC 다중 팝업 계단식 배치 보완

- 현재 `flex-wrap` 배치는 화면 너비에 들어가지 않는 팝업을 다음 줄로 내려 화면 아래에 숨기므로 사용하지 않는다.
- PC에서는 활성 팝업을 설정 번호 순서대로 모두 동시에 렌더링하고, 좌상단을 기준으로 다음 팝업을 오른쪽·아래에 일정 간격씩 어긋나게 겹치는 계단식 스택으로 배치한다.
- 팝업 개수에 제품상 최대치가 없으므로 인덱스별 인라인 좌표나 제한된 클래스 목록을 만들지 않는다. 재귀 중첩 레이아웃으로 같은 간격을 누적해 임의 개수를 지원한다.
- 큰 팝업이 포함돼도 뒤 팝업의 어긋난 가장자리가 보여 선택할 수 있어야 하며, 레이어 자체의 스크롤은 전체 스택이 viewport보다 커지는 경우에만 사용한다.
- 선택한 팝업을 전면으로 올리는 기존 동작과 각 팝업의 `오늘 하루 보지 않기`·`창닫기`, 배경 페이지 클릭·스크롤 허용은 유지한다.
- 모바일은 기존처럼 한 번에 한 팝업만 중앙에 표시하고 닫으면 다음 팝업이 같은 자리를 채우므로 변경하지 않는다.

### 추가 검증 기준

- PC에서 크기가 서로 다른 활성 팝업 6개를 열면 여섯 개가 모두 DOM에 존재하고, 여섯 번째가 별도 flex 행으로 내려가지 않고 계단식 스택 안에 표시된다.
- 뒤쪽 팝업의 보이는 가장자리를 누르면 해당 팝업이 전면으로 올라온다.
- 한 팝업을 닫아도 나머지 팝업의 설정 순서와 계단식 간격이 연속으로 다시 채워진다.
- 모바일에서는 첫 팝업 한 개만 표시되고 닫으면 다음 팝업이 같은 위치에 나타난다.
