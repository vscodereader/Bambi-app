# 메인페이지 운영자 팝업 관리 설계 계획

> **상태:** 2026-08-06 기준 확정 설계. 사용자와 확정한 질문 1~58, 수동 검수 보완 및 팝업 대상·이벤트 공지·광고 기간 할인 확장을 구현 계약으로 기록한다.

**Goal:** 운영자가 메인페이지 팝업을 설정하고, PC와 모바일 사용자가 서로 다른 반응형 노출 방식으로 이미지형 또는 글쓰기형 팝업을 확인할 수 있게 한다. 각 팝업은 개별 닫기와 정확히 24시간 숨김, 공통·개인회원·승인 업소회원 대상 구분을 지원하며, 이미지형 팝업은 로그인 후 밤비 내부 경로로 이동하는 링크를 선택적으로 제공한다. 같은 기능 확장에서 이벤트 공지 강조와 광고 가격 옵션별 기간 할인도 운영자가 안전하게 관리한다.

**Architecture:** 최신 `develop`에서 통합 기능 브랜치 하나를 사용한다. 운영자 설정은 서버의 운영자 전용 API와 영속 저장소를 통해 관리하고, 공개 메인페이지에는 서버가 세션 역할과 업소 승인 상태까지 판정한 현재 노출 가능 팝업만 최소 공개 투영으로 전달한다. 브라우저의 24시간 숨김 상태는 팝업 ID별 `localStorage` 만료 시각으로 관리하고 단순 `창닫기`는 영속화하지 않는다. PC에서는 비모달 다중 팝업 레이어, 모바일에서는 배경을 차단하는 단일 팝업 큐로 렌더링한다. 공지는 저장된 이벤트 여부를 정렬·표시의 단일 소스로 사용한다. 광고 기간 할인은 과거 행사를 모두 보존하는 별도 캠페인 이력과 서버 시각 기반 유효 할인 계산을 두고, 상품 노출 가격과 최종 결제 금액이 같은 공용 계산기를 사용한다.

**Tech Stack:** Next.js 16 App Router, React 19, TanStack Query, better-auth, oRPC, Drizzle ORM/PostgreSQL, Tiptap, shadcn/ui(base-ui), Tailwind CSS v4, Vitest, Turbo/pnpm.

## 작업·브랜치 규칙

- 기준 브랜치는 최신 `origin/develop`이다.
- 통합 브랜치는 `feat/main-popup-management`이며 별도 worktree `C:\Users\user\bambi\.worktrees\main-popup-management`에서 작업한다.
- 설계서를 먼저 작성·검토하고 사용자 승인 후 구현을 시작한다. 커밋과 원격 push는 사용자의 별도 지시 없이 실행하지 않는다.
- 이미지 편집 기능은 팝업 브랜치에 필요한 부분을 별도로 가져올 수 있다. 다만 동일 기능의 복제본 두 벌을 유지하지 않고 공용화 가능한 resize·preview 경계를 재사용한다.
- 운영자 화면은 기존 shadcn/ui와 Tailwind 구성, 운영자 콘솔의 카드·입력·버튼·상태 UI를 재사용한다. 새 인라인 스타일과 새 CSS 파일은 만들지 않는다.
- DB 변경은 Drizzle migration으로 남기며 `db:push`를 사용하지 않는다. migration 번호는 구현 직전에 최신 번호를 다시 확인한다.
- API와 화면 양쪽에서 운영자 권한을 강제한다.
- 미확정 요구사항은 사용자 답변 전 임의로 정하지 않는다.

## 확정 범위

### 1. 노출 페이지와 대상

- 루트 `/`는 현재 역할 확인 뒤 `/seeker`로 이동하므로, 1차 범위에서는 실제 메인 화면인 `/seeker`에서만 팝업을 노출한다. 로그인 화면(`/seeker?auth=login|signup`)에는 팝업을 겹쳐 띄우지 않는다.
- 완전 비회원(`anon`)은 현재 `/seeker`에서 인증 게이트만 보며 메인 목록과 팝업을 보지 않는다.
- 휴대폰 인증만 마쳐 메인 목록을 볼 수 있는 게스트(`guest`)에게는 `공통` 팝업만 노출한다.
- 로그인 개인회원(`job_seeker`)에게는 `공통`과 `개인회원` 팝업을 노출한다.
- 로그인 업소회원(`employer`) 중 연결된 업소의 운영자 승인이 하나 이상 `verified`여서 실제 공고 등록 자격이 있는 회원에게만 `공통`과 `업소회원` 팝업을 노출한다.
- 승인 대기·반려·미승인 업소회원은 `공통`만 보고 `업소회원` 팝업은 보지 않는다.
- 운영자(`admin`)에게는 메인 팝업을 하나도 노출하지 않는다.
- 대상 판정은 클라이언트 필터가 아니라 공개 목록 API의 서버 세션·프로필·업소 승인 조회로 강제한다.
- PC와 모바일 웹을 모두 지원한다.
- 팝업은 별도 브라우저 창이 아니라 현재 페이지 위에 표시되는 인페이지 레이어다.
- 팝업 바깥 클릭과 `Escape` 키로는 닫히지 않는다. 사용자는 반드시 해당 팝업의 `오늘 하루 보지 않기` 또는 `창닫기`를 사용해야 한다.

### 2. PC 노출 동작

- 활성 팝업 여러 개를 동시에 표시한다.
- 설정 번호 순서대로 화면 왼쪽에서 오른쪽으로, 가능한 한 서로 겹치지 않게 배치한다.
- 가용 너비가 부족해 겹침이 불가피하면 다음 팝업을 바로 위쪽으로 조금씩 어긋나게 배치한다. 정확한 간격은 반응형·최대 개수 결정 후 확정한다.
- 팝업을 사용자가 드래그하여 이동하는 기능은 제공하지 않는다.
- 사용자가 누른 팝업을 현재 팝업 묶음의 맨 앞으로 올린다.
- 팝업 순서는 운영자 설정 번호를 사용하며 별도의 순서 변경 기능은 제공하지 않는다.
- 팝업이 덮지 않은 메인페이지 영역은 클릭·스크롤할 수 있다. 팝업이 덮은 영역은 팝업이 포인터 이벤트를 받으므로 뒤 콘텐츠를 조작할 수 없다.

### 3. 모바일 노출 동작

- 모바일 화면에 맞춰 팝업 전체를 반응형으로 축소한다. 운영자가 정한 비율과 내용은 유지하면서 화면 폭을 넘지 않게 표시한다.
- 활성 팝업을 설정 번호 순서의 큐로 관리하고 한 번에 한 개만 같은 위치에 표시한다.
- 현재 팝업에서 `오늘 하루 보지 않기` 또는 `창닫기`를 누르면 바로 다음 팝업이 같은 자리를 채운다.
- 모든 표시 대상 팝업을 처리하기 전에는 배경 메인페이지의 클릭·스크롤 등 다른 작업을 차단한다.
- 마지막 팝업을 처리하면 차단 레이어를 제거하고 메인페이지를 정상 조작할 수 있다.

### 4. 닫기와 24시간 숨김

- `오늘 하루 보지 않기`는 팝업 전체 묶음이 아니라 팝업 ID별로 따로 적용한다.
- 숨김 기간은 자정까지가 아니라 사용자가 누른 시점부터 정확히 24시간이다.
- 숨김 만료 시각은 해당 브라우저의 `localStorage`에 팝업 ID별로 저장한다. 같은 계정이어도 다른 브라우저·다른 기기에는 공유하지 않는다.
- 사용자가 사이트의 다른 경로를 방문하거나 새로고침·로그인·로그아웃한 뒤 메인페이지로 돌아와도 아직 24시간이 지나지 않은 팝업은 다시 열지 않는다.
- 만료된 저장값은 다음 메인페이지 진입 때 무시하고 정리한다.
- `창닫기`는 브라우저 저장소에 기록하지 않는다. 현재 메인페이지 렌더링 동안만 닫고, 새로고침하거나 다른 경로에서 메인페이지로 다시 진입하거나 로그인 흐름을 거쳐 돌아오면 다시 표시한다.
- 24시간 숨김 중 운영자가 해당 팝업의 저장된 내용이나 설정을 수정하면 기존 숨김을 무효화하고 즉시 다시 노출한다.
- 이를 위해 공개 팝업에 저장 revision을 포함하고, 브라우저 숨김 기록에도 숨길 당시 revision을 함께 저장한다. 현재 revision과 저장 revision이 다르면 만료 시각이 남아 있어도 숨김 기록을 제거한다.

### 5. 이미지형 팝업 내부 링크

- 운영자 설정의 여섯 번째 단계로 팝업별 `링크 삽입`을 제공한다. 설정 순서는 `4. 시작·종료 일시`, `5. 게시 구분`, `6. 링크 삽입`으로 통일한다.
- 링크는 이미지형 팝업의 이미지 영역에만 적용한다. 글쓰기형 팝업에는 적용하지 않는다.
- 목적지는 밤비 서비스 내부 주소만 허용한다. 상대 경로와 개발 주소 `http://localhost:23001/...`, 운영 주소 `https://bambialba.com/...`를 입력할 수 있다.
- 절대 주소를 저장할 때는 host를 그대로 보존하지 않고 pathname·query·hash만 추출해 `/...` 내부 경로로 정규화한다. 따라서 localhost에서 입력한 공지 링크도 배포 환경에서는 현재 접속 중인 `bambialba.com`의 동일 경로로 이동한다.
- 서버는 허용되지 않은 host·port·scheme, 사용자 정보가 포함된 URL, protocol-relative URL(`//...`), 역슬래시와 제어 문자를 거부한다. 공개 응답에는 정규화된 내부 경로만 포함한다.
- 링크가 설정된 이미지에는 클릭 가능한 의미와 키보드 접근성을 제공한다. 하단 `오늘 하루 보지 않기`와 `창닫기`는 이미지 링크 영역 밖에 두어 이동 이벤트가 발생하지 않게 한다.
- 로그인한 사용자가 이미지를 선택하면 현재 탭에서 목적지로 이동한다.
- 비로그인 사용자가 이미지를 선택하면 로그인 화면으로 이동하고, 로그인 성공 뒤 원래 설정된 내부 목적지로 자동 이동한다. 기존 인증 흐름의 안전한 return URL 계약을 재사용한다.
- 링크가 없는 이미지형 팝업은 이미지를 눌러도 이동하지 않으며 클릭 커서를 표시하지 않는다.

### 6. 운영자 팝업 관리 화면

- 운영자 콘솔의 `콘텐츠` 메뉴에서 `크롤링` 바로 아래에 `팝업` 메뉴를 추가한다.
- 전용 주소는 `/moderator/popups`로 사용한다.
- 화면 진입, 설정 조회, 이미지 조회·업로드·편집, 저장·삭제를 화면뿐 아니라 모든 서버 API에서 운영자 전용으로 강제한다.
- 팝업 개수에는 제품 정책상 최대치를 두지 않는다. 개수는 0 이상의 정수로 검증하며, 입력한 개수만큼 번호가 고정된 팝업 설정 카드를 만든다.
- 설정 개수를 줄이면 제거 대상 번호와 삭제 영향을 경고하고 운영자 확인을 받은 뒤 해당 팝업의 이미지·글·링크·예약·감사 데이터를 완전히 삭제한다.
- 각 팝업에 `사용/사용 안 함` 스위치를 제공한다. `사용 안 함`인 팝업은 설정과 콘텐츠를 보존하되 공개 목록에서 제외한다.
- 팝업 개수 설정에는 별도 적용/저장 동작을 두고, 각 팝업 카드에도 해당 팝업만 저장하는 별도 저장 버튼을 제공한다. 한 팝업 저장 실패가 다른 팝업의 draft나 저장 상태를 바꾸지 않는다.
- 편집은 서버 저장본에서 만든 클라이언트 draft로 진행한다. 저장 성공 전에는 메인페이지 공개 결과를 바꾸지 않으며, 취소하면 해당 팝업의 모든 미저장 변경을 버리고 마지막 서버 저장본으로 되돌린다.
- 각 팝업에 마지막 수정 운영자의 표시 이름과 마지막 수정 시각을 보여준다. 저장 성공 응답으로 즉시 갱신한다.
- 팝업 카드 본문은 접고 펼칠 수 있다. 카드 헤더의 화살표뿐 아니라 팝업 번호가 있는 빈 헤더 행 전체를 버튼으로 사용할 수 있게 하되, 삭제 등 헤더 내부의 별도 조작은 펼침 이벤트와 충돌하지 않게 분리한다.
- 새 개수 적용으로 생성된 팝업은 전부 접힌 상태로 시작한다. 기존 팝업은 팝업 ID별 펼침 상태를 브라우저 저장소에 기록해 운영자가 페이지를 다시 열어도 이전 상태를 복원한다.
- 여러 팝업을 동시에 펼칠 수 있으며 하나를 펼쳐도 나머지를 자동으로 접지 않는다. 접기·펼치기는 클라이언트 표시 상태만 바꾸며 저장 전 이미지·글·시간·대상·링크 draft를 초기화하지 않는다.
- 접힌 헤더에는 팝업 번호, 저장 여부/사용 상태의 간단한 요약, 삭제 버튼과 펼침 화살표를 표시한다. 펼치면 사용 스위치부터 `5. 게시 구분`, `6. 링크 삽입`, 저장·취소까지 전체 편집 내용을 표시한다.
- 운영자 화면은 기존 운영자 콘솔의 카드, Field/Input, Button, Switch, AlertDialog, 상태·토스트 UI를 재사용한다.

### 7. 팝업 콘텐츠 유형

- 팝업 하나는 `이미지형`과 `글쓰기형` 중 정확히 하나만 가진다.
- 콘텐츠 유형을 전환하면 현재 유형의 콘텐츠가 삭제된다는 확인을 먼저 표시한다.
- 운영자가 전환을 확인해도 삭제는 draft에서만 수행하며, 해당 팝업의 저장 버튼을 눌러 성공하기 전에는 서버의 기존 콘텐츠를 유지한다.
- 전환 뒤 취소하면 유형과 삭제 예정 콘텐츠 모두 마지막 서버 저장 상태로 복원한다.
- 이미지형 팝업에는 이미지 한 장만 저장한다.
- 이미지 업로드는 기존 정책과 동일하게 JPEG·PNG·WebP, 파일당 최대 10MB를 허용한다. GIF는 이번 범위에서 제외한다.

### 8. 이미지형 편집과 실제 팝업 크기

- `팝업창 사이즈 조절`에서 기존 수집 공고 이미지 편집 기능의 크기 조절, 자르기, 복사, 붙여넣기, 삭제, 다운로드, 실행 취소를 제공한다.
- resize 계약도 기존 편집기와 동일하다. 네 모서리는 드래그 시작 비율을 유지하고, 좌·우 변은 너비만, 상·하 변은 높이만 변경하며 반대편 경계를 고정한다.
- 자르기는 자유 비율이며 기존 밝은 유지 영역·어두운 제거 영역과 8방향 조절 UI를 재사용한다.
- 원본 업로드 이미지는 그대로 보존하고 운영자 편집본을 별도로 저장한다. `원본으로 초기화`를 제공하며 초기화도 저장 전 draft이므로 취소할 수 있다.
- 실행 취소는 저장 전 편집 이력에만 적용하고 저장 성공 시 undo 기록을 초기화한다.
- 다운로드는 현재 이미지 한 장을 원래 MIME에 맞는 확장자로 내려받는다.
- 운영자가 저장한 표시 이미지의 너비·높이에 하단 `오늘 하루 보지 않기`·`창닫기` 버튼 영역 높이를 더한 값이 실제 메인페이지 팝업의 외곽 크기다.
- 운영자가 별도 크기 조절을 하지 않으면 업로드 이미지의 자연 너비·높이를 표시 이미지 크기로 사용하고 동일하게 하단 버튼 영역을 더한다.
- 팝업 관리 페이지 안에서 공유되는 내부 이미지 clipboard를 둔다. 브라우저·운영체제 clipboard에는 Base64를 쓰지 않는다.
- 운영자가 한 팝업의 이미지를 복사한 뒤 다른 팝업의 이미지 영역에 붙여넣을 수 있다.
- 대상 팝업에 이미지가 이미 있으면 기존 이미지가 교체된다는 확인을 먼저 표시하고, 확인한 경우에만 대상 팝업 draft의 한 장을 복사본으로 대체한다.
- 같은 팝업에 다시 붙여넣을 때도 동일한 교체 확인을 거쳐 복사본으로 대체한다.
- 붙여넣은 이미지는 source와 ID·편집 상태를 공유하지 않는 독립 복사본이다. 이후 대상에서 자르기·resize·초기화해도 source 팝업은 바뀌지 않는다.
- 복사·붙여넣기는 저장 전 draft 작업이며 대상 팝업의 실행 취소 한 단계로 기록한다. 대상 팝업을 취소하면 교체 전 서버 저장본으로 돌아가고, 별도 저장에 성공해야 공개 결과가 바뀐다.

### 9. 글쓰기형 편집과 크기

- 글쓰기형의 기본 콘텐츠 영역은 `420 × 320px`이다. 가로형·세로형 모두 만들 수 있도록 초기값일 뿐 비율은 고정하지 않는다.
- 콘텐츠 영역 사방에 네 모서리와 상·하·좌·우 변을 합친 8방향 resize handle을 제공한다.
- 모든 handle은 자유 크기 조절이다. 모서리를 움직여도 기존 비율을 유지하지 않고 너비와 높이를 포인터 이동량에 맞춰 각각 변경한다.
- 콘텐츠 영역의 최소값은 `280 × 160px`, 최댓값은 현재 PC 화면의 `90vw × 80vh`다. 정확한 px 숫자 입력과 마우스 resize를 함께 제공한다.
- 사용자가 글을 입력하면 설정 너비 안에서 줄바꿈하고 내용에 맞춰 팝업 콘텐츠 높이를 자동으로 늘린다. 설정 높이는 최소 미리보기 높이로 취급한다.
- 자동 높이는 현재 viewport의 `80vh`까지만 증가한다. 내용이 그 높이를 넘으면 외곽 팝업은 더 커지지 않고 본문 편집·읽기 영역에 세로 스크롤을 표시한다.
- 최종 콘텐츠 높이에 하단 버튼 영역을 더한 크기를 실제 글쓰기형 팝업 외곽 크기로 사용하므로 운영자 편집 화면이 공개 결과의 WYSIWYG 미리보기다.
- 본문 배경은 흰색, 기본 글자색은 검은색으로 고정한다. 제목 입력은 제공하지 않고 본문만 저장한다.
- 글 정렬 기능은 이번 범위에서 제외하고 기본 왼쪽 정렬을 사용한다.
- 수다방 `community-editor`의 Tiptap StarterKit과 굵게·기울임·취소선·글머리 목록·번호 목록·링크 기능 및 툴바 UI를 공용화해 재사용한다.
- 글쓰기형에서는 이미지 확장과 이미지 삽입 버튼을 제외한다. 이미지 노드가 포함된 비정상 입력도 서버 정규화/검증에서 거부한다.
- 기존 수다방 에디터에는 글자 크기가 없으므로 공용 TextStyle/FontSize 확장을 추가하고 `12·14·16·18·20·24·28·32·40·48px` 목록만 허용한다.
- 팝업 본문에 저장되는 Tiptap JSON은 허용 노드·마크와 글자 크기를 서버에서 다시 검증한다. 공개 화면은 같은 확장 세트의 읽기 전용 renderer로 표시한다.

### 10. 노출 시작·종료 예약

- 각 팝업에 한국 시간(`Asia/Seoul`) 기준의 선택적 `시작 일시`와 `종료 일시`를 저장한다.
- 새로 설정하거나 기존 값을 변경하는 시작 일시는 선택 순간의 한국 시간 현재 분 이상만 허용한다. 과거 날짜는 달력에서 비활성화하고, 오늘의 과거 시각은 현재 분으로 clamp한다.
- 이미 노출을 시작해 DB에 과거 시작 일시가 저장된 팝업은 그 값을 그대로 표시·보존할 수 있다. 운영자가 시작 일시를 새 값으로 바꾸는 순간부터 현재 분 이상 규칙을 적용한다.
- 시작·종료를 모두 설정하면 종료 일시는 반드시 시작 일시보다 뒤여야 한다. 같은 시각이나 더 이른 종료는 화면과 서버에서 거부한다.
- 두 값이 모두 비어 있으면 사용 스위치와 콘텐츠 유효 조건만 만족하는 즉시 상시 노출한다.
- 시작만 있으면 시작 일시부터 종료 없이 노출하고, 종료만 있으면 즉시 노출을 시작해 종료 일시에 내린다.
- 둘 다 있으면 `시작 일시 <= 현재 시각 < 종료 일시` 구간에만 노출한다.
- 종료 시각이 지나면 공개 목록에서 자동 제외하되 운영자 설정·콘텐츠·감사 정보는 보존한다.
- 예약 시간이 맞아도 이미지나 글 본문이 비어 있는 팝업은 공개 목록에 포함하지 않는다.
- 공개 목록 API가 서버 현재 시각을 기준으로 사용 여부·예약 구간·콘텐츠 유효성을 판정한다. 클라이언트 시계만으로 공개 여부를 결정하지 않는다.

## 사용자 상태 모델

각 공개 팝업에는 서버가 발급한 안정적인 팝업 ID가 있어야 한다. 브라우저 상태는 다음 두 종류를 분리한다.

```ts
interface MainPopupClientState {
	closedPopupIds: Set<string>;
	hiddenByPopupId: Record<
		string,
		{ hiddenUntil: number; revision: number }
	>;
}
```

- `closedPopupIds`는 메모리 상태이며 새 메인페이지 진입 시 초기화한다.
- `hiddenByPopupId`는 `localStorage`에서 읽고 `Date.now()` 및 공개 팝업 revision과 비교한다.
- 공개 활성 목록에서 `hiddenUntil > Date.now()`이고 revision도 같은 팝업과 현재 렌더링에서 닫은 팝업을 제외해 표시 목록을 계산한다.
- 만료되었거나 현재 팝업 revision과 다른 숨김 기록은 즉시 제거한다.
- PC는 계산된 목록 전체를 렌더링하고 모바일은 첫 번째 항목만 렌더링한다.
- 서버 렌더링과 hydration 불일치를 막기 위해 브라우저 저장소 판정은 클라이언트 마운트 후 수행하며, 판정 전 팝업이 순간 노출되지 않게 초기 준비 상태를 둔다.

## 접근성·상호작용 계약

- `오늘 하루 보지 않기`와 `창닫기`는 실제 `button` 또는 기존 shadcn 제어 컴포넌트를 사용하고 명확한 접근성 이름을 제공한다.
- 외부 클릭과 `Escape`가 닫기 동작으로 연결되지 않도록 기본 Dialog dismiss 계약을 그대로 쓰지 않고, 확정된 PC 비모달/모바일 모달 동작에 맞는 전용 레이어를 구성한다.
- 모바일 단일 팝업은 배경을 비활성화하고 포커스를 현재 팝업에 가둔다.
- PC 다중 팝업은 배경을 비활성화하지 않으며, 클릭된 팝업의 전면 순서를 상태로 관리한다.
- 이미지 링크는 마우스뿐 아니라 키보드로도 실행할 수 있어야 한다.

### 12. 팝업 게시 구분과 서버 노출 판정

- `main_popup_audience` enum을 `common | job_seeker | employer`로 추가하고 `main_popup.audience`를 `common` 기본값으로 저장한다. 배포 전 기존 팝업을 운영자가 삭제할 예정이지만 migration은 기존 행을 안전하게 `common`으로 backfill한다.
- 운영자 카드의 `5. 게시 구분`은 기존 이미지/글 작성 ToggleGroup UI를 재사용한 단일 선택 컨트롤이다. `공통`, `개인회원`, `업소회원` 중 정확히 하나가 항상 선택되어야 하며 비어 있는 상태는 화면과 API 모두 거부한다.
- 공개 목록 API는 현재 요청의 세션과 `bambi_profile.role`을 확인한다. `admin`이면 빈 목록을 반환하고, `job_seeker`이면 `common | job_seeker`, 게스트 또는 미승인 employer이면 `common`만 반환한다.
- employer 전용 노출은 단순 role만 보지 않는다. 현재 공고 생성 게이트와 같은 조직 멤버십을 기준으로 연결된 `employer_organization_profile.verification_status = verified`가 하나 이상인 경우에만 `common | employer`를 반환한다.
- 승인 대기·반려·미승인 employer는 employer 전용 데이터를 응답으로 받지 않는다. 클라이언트에서 받아 숨기는 방식은 사용하지 않는다.
- 완전 비회원은 현재 `/seeker` layout의 인증 게이트가 children을 렌더링하지 않으므로 팝업 레이어 자체가 생기지 않는다. 휴대폰 인증 게스트는 메인 목록을 볼 수 있으므로 `common`만 서버에서 받는다.
- 대상 변경 저장도 popup revision을 증가시킨다. 따라서 같은 팝업을 오늘 하루 숨긴 사용자가 새 대상 설정에 포함되면 기존 숨김 revision이 무효화되어 변경 내용을 다시 확인할 수 있다.

### 13. 운영자 팝업 카드 접기 상태

- 카드의 펼침 상태는 팝업 ID별 `localStorage` 값으로 저장한다. 슬롯 번호가 삭제·재정렬되어도 다른 팝업의 상태가 뒤바뀌지 않게 slotIndex가 아닌 안정적인 ID를 키로 사용한다.
- 개수 증가로 새로 생성된 ID는 저장값이 없으므로 접힌 상태가 기본이다. 기존 ID는 마지막 저장 상태를 복원한다.
- 여러 카드가 동시에 펼쳐질 수 있다. 헤더의 별도 삭제 버튼·사용 요약을 제외한 행 전체와 화살표 버튼이 같은 펼침 토글을 호출한다.
- 접기 상태는 편집 draft와 분리한다. 접기, 다른 카드 펼치기, 창 포커스 이동, 서버 목록 재조회가 저장 전 값을 버리거나 서버 값으로 덮어쓰지 않는다.
- 삭제된 팝업 ID의 펼침 저장값은 삭제 성공 뒤 제거한다. 개수 감소로 없어진 ID도 최신 목록 동기화 때 정리한다.

### 14. 이벤트 공지

- `community_post.is_event boolean not null default false`를 추가한다. 기존 글은 모두 `false`로 backfill하고, 이벤트는 별도 게시판이 아니라 `notice` 글의 표시·정렬 속성으로 저장한다.
- 공지 작성·수정 화면에서 비밀글 스위치 옆에 운영자 전용 `이벤트` 스위치를 제공한다. 기존 공지를 이벤트로 바꾸거나 이벤트를 일반 공지로 되돌릴 수 있다.
- 이벤트와 비밀글은 함께 사용할 수 없다. 이벤트를 켜면 draft의 비밀글을 끄고 비밀글 스위치를 비활성화한다. 비밀글이 켜진 상태에서 이벤트를 켤 때는 잠금이 해제된다는 것을 화면에 알린다.
- API는 `board === notice`, admin 작성/수정, `isEvent && !isLocked`를 다시 강제한다. 일반 게시판 또는 비운영자 입력으로 `isEvent = true`를 보내면 거부한다.
- 이벤트 스위치를 끄고 저장하면 일반 공지가 되고 이벤트 상단 고정도 즉시 해제된다.
- 공지 정렬은 `is_event desc, created_at desc, id desc`로 고정한다. 여러 이벤트는 최신순, 그 아래 일반 공지도 현재와 동일한 최신순이다. 같은 정렬을 목록·페이지 수·메인 공지 요약 조회에 적용해 페이지 이동 중 중복·누락을 막는다.
- 공지사항 전체 목록의 이벤트 행에만 `이벤트` Badge와 옅은 primary 배경(`bg-primary/10` 계열 시맨틱 토큰)을 적용한다. 일반 공지는 기존 `공지` Badge와 투명 배경을 유지한다.
- 메인페이지 공지 미리보기와 게시글 상세 화면에는 이벤트 전용 배경·Badge를 추가하지 않는다. 다만 공지 요약 정렬에서는 이벤트가 먼저 선택될 수 있다.

### 15. 업소회원 가입 할인 홍보 이미지 산출물

- 구현 작업에서 밤비 로고와 `지금 가입하면 6개월동안 광고비 50% 할인!!` 문구를 사용한 세로형 `600 × 800px` PNG 한 장을 제작한다.
- 스타일은 밤비 primary/coral 브랜드와 기존 로고를 사용하고, 모바일 팝업에서 읽을 수 있는 큰 제목·명확한 할인 수치·충분한 대비를 우선한다.
- 결과 파일은 운영자가 직접 업로드할 수 있는 독립 이미지 자산으로만 제공한다. DB seed, 팝업 자동 생성, 링크·게시 기간 자동 설정은 하지 않는다.
- 운영자가 이 자산을 등록할 때 `업소회원` 게시 구분을 선택한다. 실제 공개 API는 승인 완료 employer에게만 해당 팝업을 전달한다.

### 16. 광고 가격 옵션별 기간 할인 데이터 모델

- 현재 `ad_product.price_options`의 각 `{ days, amount, discountPercent }`에서 `discountPercent`는 행사 종료 후 복귀할 기본 할인율로 유지한다.
- 가격 옵션 기간은 30·60·90일로 고정하지 않는다. 운영자가 만든 1일·3일·5일 등 각 고유 `days` 옵션이 서로 독립된 기간 할인 캠페인을 가진다.
- 과거 캠페인을 전부 보존하기 위해 현재 JSON에 행사 필드를 덮어쓰지 않고 별도 `ad_product_discount_campaign` 테이블을 추가한다.
- 캠페인은 `id`, `adProductId`, `priceOptionDays`, `discountPercent`, `startsAt`, nullable `endsAtExclusive`, nullable `cancelledAt`, `supersededById`, `createdByUserId`, `createdAt`, `updatedAt`을 가진다. 할인율은 기존과 같은 정수 `0~100`이다.
- 선택한 종료 일시는 해당 분 전체를 포함한다. 예를 들어 운영자가 `8월 4일 23:59`를 고르면 서버에는 다음 분 경계인 `8월 5일 00:00`을 `endsAtExclusive`로 저장하고 `start <= now < endsAtExclusive`로 판정한다.
- 종료를 `설정 안 함`으로 두면 `endsAtExclusive = null`이며 시작 시각부터 운영자가 해제하거나 수정할 때까지 무기한 적용한다.
- 시작은 필수이며 현재보다 과거도 허용한다. 종료가 있으면 종료 분 경계가 시작보다 뒤여야 한다. 이미 전부 지난 구간을 저장해도 이력으로는 보존되지만 현재 가격에는 적용되지 않는다.
- 한 가격 옵션에는 활성 또는 예정 상태인 캠페인을 한 건만 둔다. 종료·취소·대체된 캠페인은 여러 건 계속 보존할 수 있다.
- 기간 설정을 직접 해제하고 저장하면 현재 활성/예정 캠페인에 `cancelledAt`을 기록하고 즉시 기본 할인율로 복귀한다.
- 저장된 행사 날짜나 할인율을 수정하면 기존 행을 덮어쓰지 않는다. 기존 캠페인을 취소·대체 상태로 보존하고 새 캠페인을 생성해 `supersededById`로 연결한다.
- 가격 옵션을 삭제하면 해당 상품·days의 캠페인 이력도 같은 트랜잭션에서 삭제한다. 광고 상품을 삭제하면 그 상품의 모든 캠페인 이력을 cascade 삭제한다.
- 가격 옵션의 `days`를 바꾸는 것은 기존 옵션 삭제 후 새 옵션 추가와 같은 계약으로 취급한다. 이전 days의 캠페인 삭제 경고를 표시하고 확인 뒤에만 저장한다.
- migration 파일 번호는 구현 직전 최신 `packages/db/src/migrations`를 다시 확인한다. 2026-08-06 현재 마지막은 `0063`이지만 병렬 브랜치와 충돌할 수 있어 번호를 문서에 고정하지 않는다.

### 17. 광고 기간 할인 운영자 UI와 검증

- 각 가격 옵션 행의 기본 `% 할인` 옆에 `기간 설정` Checkbox를 추가한다. 체크하면 팝업에서 사용 중인 달력·시분 스테퍼를 공용 컴포넌트로 재사용해 시작 일시, 종료 일시, 기간 할인율을 표시한다.
- 시작 일시 피커에서는 `설정 안 함`을 제공하지 않는다. 종료 일시 피커만 `설정 안 함`을 제공하며 이는 무기한을 뜻한다.
- 기간 설정을 켠 동안 기본 할인율 Input은 비활성화하고 포커스·선택·드래그로 값을 바꿀 수 없게 한다. 저장된 기본 값 자체는 지우지 않아 행사 전·종료·취소 후 다시 적용한다.
- 기간 설정을 켰는데 시작 일시 또는 기간 할인율이 비어 있으면 저장을 막고 각각 `시작 일시를 입력하지 않았습니다.`, `기간 할인율을 입력하지 않았습니다.`를 표시한다. 종료는 선택 사항이다.
- 기간 할인율·기본 할인율은 기존과 동일하게 정수 0~100으로 검증한다. 날짜와 할인율 검증은 화면과 API 양쪽에서 수행한다.
- 미래 캠페인은 `예정`, 현재 적용 중이면 `진행 중`, 종료된 최신 캠페인은 체크박스를 해제된 모습으로 두고 `종료됨`을 표시한다. 종료 기록은 DB에서 지우지 않는다.
- 취소·수정 시 영향과 기본 할인 복귀를 확인받는다. 저장 실패 시 기존 서버 캠페인과 가격을 바꾸지 않고 해당 행 draft를 유지한다.
- 일반 구매자 화면에는 행사 기간·예정 안내 배지를 추가하지 않는다. 운영자가 별도의 팝업 이미지로 홍보하며, 상품 화면은 현재 서버 시각에 실제 적용되는 가격과 할인율만 표시한다.

### 18. 서버 시각 기반 유효 가격과 결제 경계

- 공용 순수 함수 `resolveEffectiveAdDiscount`가 기본 할인율, 현재 서버 시각, 활성 캠페인을 받아 실제 할인율과 금액을 계산한다. 기존 `discountedAdAmount`의 10원 단위 내림 규칙은 유지한다.
- 광고 카탈로그 API는 각 가격 옵션에 현재 유효 할인율·할인가와 다음 가격 변경 경계(`nextPricingChangeAt`)를 계산해 반환한다. 웹은 이 값을 사용하고 클라이언트 시계로 임의 할인율을 선택하지 않는다.
- 구매 화면은 다음 가격 변경 경계에 카탈로그 쿼리를 무효화하고, 창 포커스 복귀 때도 재조회해 시작·종료 시각이 지난 가격을 오래 표시하지 않는다.
- 최종 공고 저장/결제 요청 시 서버가 다시 현재 시각으로 상품·가격 옵션·캠페인을 조회해 금액을 계산한다. 화면 진입 시각이 아니라 최종 요청이 서버에 도착한 시각이 기준이다.
- 유료 요청에는 사용자가 확인한 `expectedExposureAmount`를 함께 보낸다. 서버 재계산 금액과 다르면 결제를 진행하거나 공고에 새 금액을 저장하지 않고 `CONFLICT`를 반환한다.
- 화면은 충돌 응답의 이전·현재 금액을 사용해 `할인 기간이 종료되어 결제 금액이 500,000원에서 950,000원으로 변경됐습니다. 변경된 금액을 확인한 후 다시 결제해 주세요.` 형식으로 안내하고 카탈로그를 갱신한다. 사용자가 새 금액으로 다시 실행해야 결제가 진행된다.
- 서버가 확정한 금액은 기존처럼 공고의 `exposureAmount`에 구매 시점 스냅샷으로 저장한다. 이미 구매가 확정된 광고 가격은 이후 행사 시작·종료·수정의 영향을 받지 않는다.
- 카탈로그 표시, 광고 안내 화면, 가격 선택 필드, 운영자 상품 목록과 최종 결제는 모두 같은 유효 할인 계산 결과를 사용한다. 기본 할인과 기간 할인을 화면별로 따로 계산하지 않는다.

## 확정 요구사항 테스트 기준

- 완전 비회원과 운영자에게 팝업이 노출되지 않고, 게스트는 공통만, 개인회원은 공통·개인만, 승인 완료 업소회원은 공통·업소만 조회된다.
- 승인 대기·반려·미승인 업소회원은 공통만 조회되고 업소회원 전용 팝업 데이터는 응답에 포함되지 않는다.
- 다른 경로에는 팝업이 렌더링되지 않는다.
- 바깥 클릭과 `Escape`로 팝업이 닫히지 않는다.
- PC에서는 여러 팝업이 동시에 왼쪽부터 배치되고 배경의 노출 영역을 조작할 수 있다.
- PC에서 선택한 팝업이 전면으로 올라오고 팝업 자체는 드래그되지 않는다.
- 모바일에서는 한 개씩 같은 자리에 표시되고 닫으면 다음 팝업이 즉시 나타난다.
- 모바일에서 마지막 팝업 처리 전까지 배경을 조작할 수 없다.
- 한 팝업의 24시간 숨김이 다른 팝업에 영향을 주지 않는다.
- 숨김은 정확히 24시간 동안 새로고침·경로 이동·로그인 왕복 후에도 유지되고 다른 브라우저에는 공유되지 않는다.
- 단순 닫기는 새로고침·메인 재진입·로그인 왕복 후 복원된다.
- 운영자가 숨겨진 팝업을 다시 저장해 revision이 바뀌면 24시간이 지나기 전이어도 다시 노출된다.
- `/moderator/popups`와 관련 API는 운영자만 접근할 수 있다.
- 개수 감소 확인 전에는 아무 데이터도 지우지 않고, 확인·저장 뒤 제거된 번호의 모든 설정을 삭제한다.
- 사용 스위치를 끈 팝업은 공개되지 않지만 다시 켰을 때 기존 콘텐츠가 유지된다.
- 각 팝업 저장은 다른 팝업 draft에 영향을 주지 않고, 취소는 해당 팝업의 미저장 변경을 모두 버린다.
- 콘텐츠 유형 전환을 취소하면 기존 유형과 콘텐츠가 유지되고, 확인 후 저장하면 이전 유형 콘텐츠가 삭제된다.
- 이미지형은 JPEG·PNG·WebP 한 장과 원본/편집본을 보존하고 원본 초기화를 지원한다.
- 이미지 resize·crop·삭제·다운로드·undo와 페이지 내부 clipboard의 팝업 간 복사·확인 후 교체를 검증한다.
- 붙여넣은 대상 이미지를 편집해도 source 팝업 이미지가 바뀌지 않고, 대상 취소·undo가 교체 전 상태를 복원한다.
- 실제 외곽 팝업 크기가 표시 이미지 크기와 하단 버튼 영역의 합과 일치한다.
- 글쓰기형은 420×320에서 시작하지만 280×160~90vw×80vh 범위에서 8방향 자유 resize되고 모서리도 비율을 고정하지 않는다.
- 글쓰기형은 제목·정렬·이미지 없이 굵게·기울임·취소선·목록·링크와 지정된 열 가지 글자 크기만 저장·렌더링한다.

## 2026-08-05 운영자 수동 검수 보완

- 팝업 개수와 시·분 직접 입력은 문자열 draft를 사용한다. 입력 중 빈 문자열을 허용하고 포커스 시 기존 숫자를 전체 선택해 새 숫자로 바로 교체할 수 있게 하며, 확정 시에만 0 이상의 정수 또는 시·분 범위로 변환한다.
- 팝업 이미지 저장은 10MB 이미지의 원본·편집본 Base64 두 벌과 RPC 포장 오버헤드를 수용하도록 `/rpc/*` 요청 본문 제한을 명시한다. 다른 Fastify 경로의 기본 제한은 변경하지 않는다.
- 이미지 요청이 본문 크기 제한에서 거부되면 `Failed to fetch`를 그대로 노출하지 않고 이미지 용량 때문에 저장하지 못했다는 안내를 표시한다.
- 창 포커스 복귀 재조회와 한 팝업 저장 후 목록 갱신은 미저장 상태인 다른 팝업 draft를 덮어쓰지 않는다. 저장·취소·삭제가 완료된 팝업만 최신 서버 값으로 동기화한다.
- 각 팝업 카드 제목 옆에 휴지통 아이콘 버튼을 제공한다. 확인 후 해당 팝업의 이미지·글·링크·예약·감사 정보를 완전히 삭제하고, 뒤 팝업의 번호를 한 칸씩 당기며 상단 팝업 개수도 즉시 갱신한다.
- 마지막 팝업 카드와 페이지 하단 사이에 충분한 여백을 둔다.

## 2026-08-05 PC 다중 팝업 계단식 배치 보완

- 현재 `flex-wrap` 배치는 화면 너비에 들어가지 않는 팝업을 다음 줄로 내려 화면 아래에 숨기므로 사용하지 않는다.
- PC에서는 활성 팝업을 설정 번호 순서대로 모두 동시에 렌더링하고, 좌상단을 기준으로 다음 팝업을 오른쪽·아래에 일정 간격씩 어긋나게 겹치는 계단식 스택으로 배치한다.
- 팝업 개수에 제품상 최대치가 없으므로 인덱스별 인라인 좌표나 제한된 클래스 목록을 만들지 않는다. 재귀 중첩 레이아웃으로 같은 간격을 누적해 임의 개수를 지원한다.
- 큰 팝업이 포함돼도 뒤 팝업의 어긋난 가장자리가 보여 선택할 수 있어야 하며, 레이어 자체의 스크롤은 전체 스택이 viewport보다 커지는 경우에만 사용한다.
- 선택한 팝업을 전면으로 올리는 기존 동작과 각 팝업의 `오늘 하루 보지 않기`·`창닫기`, 배경 페이지 클릭·스크롤 허용은 유지한다.
- 모바일은 기존처럼 한 번에 한 팝업만 중앙에 표시하고 닫으면 다음 팝업이 같은 자리를 채우므로 변경하지 않는다.

### 추가 검증 기준

- PC에서 크기가 서로 다른 활성 팝업 6개를 열면 여섯 개가 모두 DOM에 존재하고, 여섯 번째가 별도 flex 행으로 내려가지 않고 계단식 스택 안에 표시된다.
- 뒤쪽 팝업의 보이는 가장자리를 누르면 해당 팝업이 전면으로 올라온다.
- 한 팝업을 닫아도 나머지 팝업의 설정 순서와 계단식 간격이 연속으로 다시 채워진다.
- 모바일에서는 첫 팝업 한 개만 표시되고 닫으면 다음 팝업이 같은 위치에 나타난다.

## 2026-08-06 운영자 가격·팝업 라벨 검수 보완

- 가격 옵션마다 진행 중 또는 예정된 기간 할인 상태와 시작·종료 일시를 함께 표시한다. 종료가 없으면 `무기한`으로 표시하고, 서버가 계산한 상태를 기준으로 `진행 중`과 `예정`을 구분한다.
- 운영자 목록의 표시만 클라이언트 시계로 다시 계산하지 않는다. `listCatalogAdmin` 응답이 유효 할인율과 다음 가격 변경 시각을 제공하고, 화면은 그 값을 그대로 사용한다.
- 팝업 설정 카드의 단계 번호가 중복되므로 `게시 구분`, `링크 삽입`, `시작 일시 (KST)` 라벨 앞의 숫자를 제거한다. 기능·배치·저장 계약은 변경하지 않는다.
- 기간 할인 일시는 브라우저에서 지원되는 `Intl.DateTimeFormat` 조합으로 KST 표시하며, `dateStyle`과 개별 시간 옵션을 함께 사용하지 않는다.

### 추가 검증 기준

- 활성 기간 할인 10%와 기본 할인 5%가 함께 저장된 가격 옵션은 운영자 목록에서 활성 기간 동안 10% 할인가를 표시한다.
- 예정 기간 할인은 현재 기본 할인가를 유지하면서 별도 기간 안내에 `예정`과 시작·종료 일시를 표시한다.
- 종료가 없는 기간 할인은 종료 일시를 `무기한`으로 표시한다.
- 팝업 설정 화면에 `5. 게시 구분`, `5. 링크 삽입`, `4. 시작 일시`가 남지 않고 각각 숫자 없는 라벨로 표시된다.
- 기간 할인 일시가 있는 운영자 광고 상품 목록은 브라우저 렌더링 오류 없이 연·월·일·시·분을 KST로 표시한다.

## 2026-08-06 광고 기간 할인 표시·편집 상태 검수 보완

- 구인자 광고 상품 안내의 각 가격 옵션은 현재 기간 할인이 실제 적용 중일 때 할인가 아래에 운영자가 지정한 시작·종료 일시를 KST로 표시한다. 종료가 없으면 `무기한`으로 표시하며, 예정·종료·취소된 행사는 현재 가격 기간으로 노출하지 않는다.
- 공개 카탈로그 API는 기간 할인 이력 전체를 노출하지 않고 현재 적용 중인 캠페인의 시작 일시와 운영자가 선택한 포함 종료 일시만 가격 옵션에 투영한다. 가격·기간은 같은 서버 시각 판정 결과를 사용한다.
- 운영자 광고 상품 목록의 가격 옵션은 한 행에 여러 옵션을 배치하지 않고 상품별 1열 세로 목록으로 표시한다. 각 옵션의 가격, 상태 Badge, 기간을 한 묶음으로 유지한다.
- 광고 상품 편집 화면은 같은 이용 기간의 캠페인 이력 중 `진행 중`, `예정`, `종료됨` 순으로 우선 선택하고, 같은 상태 안에서는 시작 일시가 가장 최신인 항목을 사용한다. 과거 종료 이력이 현재 진행 중인 캠페인보다 시작 시각이 늦더라도 현재 캠페인을 덮어쓰지 않는다.
- 운영자 광고 상품 관리의 위치 카드와 상품 카드에 팝업 설정 카드와 같은 위/아래 Chevron 접기 버튼을 제공한다. 위치를 접으면 위치 설명·상품 목록을 숨기고, 상품을 접으면 해당 상품의 가격 목록만 숨기며 수정·삭제·활성·순서 버튼은 계속 사용할 수 있다.
