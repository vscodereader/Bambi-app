# 운영자 신고 조치 및 회원 프로필 개선 계획

## 목적

- 구인자와 구직자는 역할·성별과 관계없이 구직자 경로의 계정 설정에서 프로필 사진을 등록할 수 있어야 한다.
- 채팅 프로필 이미지가 운영자 신고 기각 사유 오버레이보다 위에 그려지지 않아야 한다.
- 조치 완료 또는 기각된 신고는 일괄 기각·해결 대상으로 다시 선택하거나 서버에서 갱신할 수 없어야 한다.
- 채팅방 신고는 별도 `조치 완료` 버튼을 제거하고, 사유를 입력해 방을 차단하면 신고가 자동으로 조치 완료되어야 한다.
- 글 팝업은 작성 내용에 따라 크기가 자동으로 늘어나지 않고 운영자가 지정한 크기 안에서 스크롤되어야 한다.
- 기존 채팅방의 상대가 탈퇴하면 기존 대화는 열람할 수 있지만 새 메시지와 첨부 전송은 차단되고 `대화 불가능` 상태를 표시해야 한다.

## 설계

1. 계정 설정의 프로필 사진 업로드를 커뮤니티 이미지 업로드 권한에서 분리한다.
   - 온보딩 라우터에 역할·성별과 무관한 활성 회원용 프로필 이미지 업로드 인텐트를 추가한다.
   - JPG, PNG, WebP 및 5MB 제한은 현재 화면 정책과 동일하게 서버에서도 검증한다.
2. 공용 Avatar 루트에 격리와 클리핑을 적용해 이미지 레이어가 오버레이의 쌓임 맥락을 침범하지 않게 한다.
3. 신고 목록에서 `closed` 항목의 데스크톱·모바일 체크박스를 비활성화한다.
   - 선택 상태에도 종결 신고가 남지 않도록 선택 콜백을 방어한다.
   - API 일괄 처리도 `resolved`, `dismissed` 신고를 거부해 직접 호출 우회를 막는다.
4. 채팅방 컨텍스트가 있는 신고는 공통 `조치 완료` 버튼을 표시하지 않는다.
   - 기존 방 차단 API가 방 차단과 열린 신고의 `resolved` 전환을 한 트랜잭션에서 수행하는 흐름을 유지한다.
   - 기각 버튼은 그대로 유지한다.
5. 팝업 글 에디터의 내용 높이 기반 자동 크기 변경을 제거한다.
   - 운영자가 조절 핸들로 정한 가로·세로 크기는 유지한다.
   - 지정 영역을 넘는 내용은 에디터와 실제 팝업 내부 세로 스크롤로 확인한다.
6. 채팅 목록·상세 응답에 상대 회원의 탈퇴 여부를 포함한다.
   - 목록과 상세 헤더에는 `대화 불가능`, 입력 영역에는 `탈퇴한 사용자와는 대화할 수 없습니다.`를 표시한다.
   - 기존 메시지와 첨부는 계속 조회할 수 있고 별도 시스템 메시지는 저장하지 않는다.
   - 메시지, 첨부 업로드 인텐트와 첨부 메시지 등 공통 전송 가드에서 상대의 `user.deletedAt`을 다시 확인해 직접 API 호출도 거부한다.

## 검증

- web 및 API TypeScript 검사
- 변경 파일 Biome 검사
- `git diff --check`
- DB 스키마 변경 없음, Drizzle migration 불필요

## 최초 사업자 인증 서류 보완

- 최초 업소회원도 업체 정보 제출 전 이미지/PDF 선택 버튼을 사용할 수 있게 한다.
- 최초 파일 선택은 브라우저 메모리에만 보관하고 버킷이나 DB에는 저장하지 않는다.
- 사용자가 `업체 정보 제출`을 누르면 미제출 초안 조직 생성, 파일 업로드, 심사 요청을 한 흐름으로 실행한다.
- 심사 요청과 관리자 알림도 `업체 정보 제출` 이후에만 발생한다.
