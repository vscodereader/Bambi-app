# 포인트 관리·가입 보너스·공고 결제 사용·남성 게시판 권한 Implementation Plan

## 목표

운영자 정보 구조에 `포인트 관리`를 신설하고, 가입·출석·게시판별 글/댓글·공고 결제 포인트 정책을 저장 후 반영되는 설정으로 통합한다. 본인인증 후 회원가입을 완료한 구직자·구인자에게 가입 포인트를 한 번만 지급하고, 새 공고 등록 때 등록자 본인의 포인트를 선택적으로 사용해 결제 예정 금액을 낮춘다. 일반 남성 구직자는 공지사항만, 남성 법률자문가는 공지사항과 법률게시판만 접근하도록 UI와 API를 함께 제한한다.

## 확정 정책

- 포인트 관리 경로:
  - `/moderator/points`
  - `/moderator/points/attendance`
  - `/moderator/points/grades`
  - `/moderator/points/settings`
- 기존 `/moderator/attendance`, `/moderator/member-grades`는 새 주소로 redirect한다.
- 데스크톱 상단에서 회원 관리와 광고·결제 사이에 포인트 관리를 둔다. 모바일 더보기에서도 출석·등급·기타 설정을 포인트 관리 아래 묶는다.
- 출석 관리와 등급 관리의 기존 내용·기능은 변경하지 않고 경로와 메뉴 소속만 옮긴다.
- 기타 포인트 설정은 명시적인 저장 버튼을 눌러야 반영한다.
- 설정 항목:
  - 회원가입 포인트(초기 1000P, 0이면 미지급·가입 말풍선 숨김)
  - 출석 포인트(초기 10P)
  - 게시판별 글 작성 포인트
  - 게시판별 댓글 작성 포인트
  - 공고 등록 최소 사용 포인트(null/미설정 또는 0이면 기능 중단)
  - 공고 등록 최대 사용 포인트(null이면 결제 예정 금액까지)
- 최소·최대값이 함께 있으면 최대값은 최소값 이상이어야 한다.
- 로그인 화면 회원가입 링크에 설정값 기반 `지금 회원가입 시, N포인트 지급!` 말풍선을 표시하며 19세 미만 고지를 침범하거나 가리지 않는다.
- 본인인증과 계정·역할 프로필 생성을 모두 완료한 신규 구직자·구인자에게 가입 포인트를 정확히 한 번 지급한다. 재시도·동시 요청으로 중복 지급하지 않는다.
- 설정 변경은 과거 가입·출석·콘텐츠 적립에 소급하지 않는다.
- 가입·출석·게시판 글/댓글 등 모든 신규 적립은 기존 회원 최대 보유 포인트를 적용하며,
  상한을 넘는 금액은 최대치까지만 지급한다. 공고 취소 환급에도 동일한 최대 보유 포인트를
  적용하며, 환급 시점의 잔액 때문에 최대치를 넘는 부분은 소멸한다.
- 새 공고 등록 과정의 유료 노출상품과 무료 공고에 함께 구매하는 끌어올리기·횟수권·자동 끌어올리기 옵션 합계에 포인트를 사용할 수 있다. 광고 관리에서 옵션만 별도 구매할 때는 사용할 수 없다.
- `1P = 1원`; 입력은 정수만 허용한다.
- 사용 가능 최대치는 보유 잔액, 결제 예정 금액, 운영자 최대 설정값(있을 때)의 최솟값이다.
- 보유 잔액 또는 결제금액이 최소 사용값보다 작으면 입력과 전액 사용을 비활성화한다.
- 전액 사용은 사용 가능 최대치까지만 입력한다.
- 포인트 사용은 선택이며 미입력은 0P다.
- 팀원 A가 등록하면 A의 잔액에서 차감·환급한다.
- 공고 생성 트랜잭션에서 포인트를 즉시 차감한다. 잔액 잠금/조건부 차감으로 동시 등록의 초과 사용을 막는다.
- 수정 시 최초 사용 포인트는 유지하고 추가 사용은 허용하지 않는다. 변경 결제금액은 구인자와 Admin에 동일하게 표시한다.
- 수정 후 총액이 기존 사용 포인트보다 작으면 UI 제출을 비활성화하고 API도 저장을 거부한다. 안내: `변경된 결제금액이 이미 사용한 포인트보다 적습니다. 공고를 취소하여 포인트를 환급받은 뒤 다시 등록해 주세요.`
- 결제·공개 이력이 한 번도 없는 공고를 구인자가 기존 삭제 기능으로 삭제하면 사용 포인트를
  최대 보유 포인트의 남은 여유만큼 즉시 환급하고, 초과분은 소멸한다.
- 반려만으로는 환급하지 않는다. 반려 공고를 수정해 재제출하면 기존 사용 포인트를 유지하고,
  구인자가 삭제하면 같은 상한 규칙으로 환급한다.
- 한 번이라도 결제 완료 또는 공개된 공고는 이후 미결제·미공개로 되돌려도 자동 환급하지 않는다. 삭제 확인에 `한 번이라도 결제 완료가 되거나 공개 처리된 공고에 사용된 포인트는 환불이 어렵습니다.`를 표시한다.
- 환급 가능 공고 삭제 확인에는 현재 잔액과 상한으로 계산한 실제 환급액을 표시한다. 전액 환급이면
  `공고를 삭제하면 사용한 N포인트가 즉시 환급됩니다.`를 표시한다. 일부 또는 전부가 소멸하면
  `지금 취소하시면 최대 보유 포인트는 M포인트까지 가능하므로 사용하신 N포인트 중 L포인트는 환급이 불가합니다. 그대로 하시겠습니까?`
  AlertDialog와 확인·취소 버튼을 표시한다.
- 최종 입금액이 0원이더라도 자동 결제완료 처리하지 않는다. 운영자가 결제완료를 누르기 전에는
  구인자가 삭제할 수 있고 위 상한 규칙에 따라 환급하며, 운영자가 결제완료를 누른 뒤부터 환급을 잠근다.
- 운영자 공고 하드 삭제는 제재이므로 결제·공개 여부와 관계없이 포인트를 자동 환급하지 않는다.
  운영자가 잘못 삭제한 경우 기존 운영자 포인트 지급 기능으로 별도 복구하며, 지급 시에도 최대
  보유 포인트를 적용하고 사유를 원장에 남긴다.
- Admin 결제 관리에는 총액에서 포인트를 차감하고 `포인트 -2,500원` 항목을 표시한다.
- 일반 남성 `job_seeker`: 커뮤니티 공지사항만 목록·상세 열람 가능.
- 남성 `legal_advisor`: 공지사항과 법률게시판만 접근 가능하며 법률게시판 기존 글·댓글 작성 권한 유지.
- 남성 구인자, 여성 사용자, Admin, 커뮤니티 밖 기능은 기존 정책을 유지한다.
- 게시판 제한은 내비게이션/목록 UI와 API 권한을 모두 적용해 URL 직접 접근도 막는다.
- 하드코딩된 게시판 표시명이 아니라 기존 게시판 key/정본을 사용한다.

## 데이터 설계

### 전역 포인트 설정

기존 단일행 `bambi_site_settings(id='default')`를 정본으로 사용한다. 사이트 전역 설정을
이미 같은 방식으로 저장하고 있으므로 별도 설정 테이블을 만들지 않는다.

- `signup_points integer not null default 1000`
- `attendance_points integer not null default 10`
- `job_payment_min_points integer null`
- `job_payment_max_points integer null`

게시판별 글/댓글 포인트는 기존 `community_board.post_points/comment_points`를 정본으로 유지한다. 기타 포인트 설정 API는 전역 설정과 게시판별 설정을 한 화면에 제공하며 저장 트랜잭션에서 함께 갱신한다.

### 가입 지급 멱등성

기존 `bambi_point_transaction`에 nullable `external_key`를 추가하고 unique index를 건다.
가입 보너스는 `signup_bonus:{userId}`, 공고 차감은 `job_payment_use:{jobPostId}`,
환급은 `job_payment_refund:{jobPostId}`를 사용한다. 기존 원장 행은 null이라 영향을 받지 않고,
재시도·동시 호출은 DB unique가 중복 원장을 막는다. 단순 reason 조회로 멱등성을 흉내 내지 않는다.

### 포인트 원장 불변식·동시성·재시도

포인트 잔액은 원장 합계라 잠글 단일 잔액 행이 없다. 따라서 가입·출석·글·댓글·운영자 조정·
공고 차감·공고 환급을 포함한 **모든 포인트 변경 트랜잭션**은 사용자 ID 기반 PostgreSQL
transaction advisory lock을 먼저 얻은 뒤 잔액과 상한을 읽고 원장을 기록한다. 일부 경로만
잠그면 공고 차감과 글 적립 등이 동시에 실행될 때 각각 오래된 잔액을 읽을 수 있으므로 공용
원장 서비스 하나를 통하지 않은 직접 insert를 남기지 않는다.

- 적립: 잠금 후 현재 잔액을 다시 읽고 `max_member_points - balance` 범위까지만 지급한다.
- 차감: 잠금 후 현재 잔액을 다시 읽고 잔액 이상 차감을 거부한다.
- 환급: 잠금 후 공고 생성 때 기록된 실제 음수 차감 원장의 절댓값을 환급 대상액으로 삼고,
  `min(환급 대상액, max(0, 최대 보유 포인트 - 현재 잔액))`만 실제 원장에 돌려준다. 최대 보유
  포인트가 null이면 환급 대상액 전부를 돌려준다. 나머지는 소멸한다. 클라이언트 입력, 현재 상품
  가격, 화면의 `points_used` 값을 환급 대상액의 단독 근거로 사용하지 않는다.
- 가입·공고 차감·공고 환급처럼 한 번만 가능한 작업은 `external_key` unique index로 DB에서
  중복 원장을 거부한다. 애플리케이션의 사전 조회만으로 중복을 막지 않는다.
- `job_payment_refund:{jobPostId}` 환급은 `job_payment_use:{jobPostId}` 차감 원장이 정확히
  한 건 있고 아직 환급 원장이 없을 때만 허용한다. 환급 대상액은 `-차감원장.amount`, 실제
  환급액은 환급 시점의 상한 여유로 제한한다. 실제 환급액이 0이어도 환급 처리를 완료한 것으로
  기록할 별도 0원 처리 키/감사 기록을 남겨 재시도에서 다시 계산·환급하지 않는다.
- 차감·공고 스냅샷 저장과 환급·삭제는 각각 하나의 DB 트랜잭션이다. 어느 한쪽만 성공한
  상태를 만들지 않는다.

공고 등록 화면은 매 등록 시도에 안정적인 `submissionKey` UUID를 하나 발급하고 성공 응답까지
같은 키를 재사용한다. `job_post`에는 등록자와 결합한 등록 멱등키를 unique로 저장한다. 더블클릭,
브라우저 재전송, 타임아웃 후 재시도가 같은 키로 들어오면 새 공고·새 옵션·새 포인트 차감을
만들지 않고 최초 결과를 반환한다. 같은 키로 내용이 다른 요청이 오면 재사용하지 않고 충돌로
거부한다. 사용자가 정상적으로 새 공고 작성 화면을 다시 시작한 경우에만 새 키를 발급한다.

삭제 확인용 환급 예상값은 서버가 반환한다. 삭제 요청은 사용자가 확인한 `expectedRefundAmount`와
`expectedForfeitedAmount`를 함께 보내며, 서버는 사용자 포인트 잠금을 얻은 뒤 잔액·상한·차감 원장을
다시 계산한다. 확인창 이후 적립 등으로 실제 환급/소멸액이 바뀌었으면 삭제하지 않고 충돌 응답을
보내 최신 금액으로 AlertDialog를 다시 띄운다. 사용자가 확인하지 않은 더 큰 손실을 만들지 않는다.

### 공고 포인트 결제 스냅샷

기존 공고 결제 스냅샷과 함께 조회·삭제되는 값이므로 `job_post`에 다음 컬럼을 추가한다.

- `points_used integer not null default 0`
- `points_used_by_user_id text null references user(id)`
- `points_refunded_at timestamp null`
- `points_refund_locked_at timestamp null`
- `submission_key uuid not null` 및 등록자와 결합한 unique index

상품·디자인·등록 동시 구매 옵션은 기존 가격 스냅샷을 합산하고, 저장된 사용 포인트를 마지막에 한 번 빼 최종 결제금액을 계산한다. 클라이언트가 보낸 총액·잔액은 신뢰하지 않고 서버가 설정·상품·원장을 다시 읽는다.

포인트 사용 후 최종 입금액이 0원이어도 `payment_status`는 자동으로 `paid`가 되지 않는다. 포인트를
사용한 등록 건과 등록 과정의 유료 청구가 있는 건은 운영자 결제완료 전까지 `unpaid`로 유지한다.
운영자가 0원 결제 건도 명시적으로 결제완료 처리해야 공개·환급 잠금 상태가 된다. 유료 청구와
포인트 사용이 모두 없는 순수 무료 공고만 기존 무료 공고의 자동 결제 상태를 유지한다.

`points_refund_locked_at`은 다음 최초 사건에서 한 번만 채우고 다시 null로 되돌리지 않는다.

- 운영자가 공고 등록 과정에서 생긴 실제 유료 청구(유료 노출상품 또는 함께 구매한 옵션)를
  미결제에서 결제완료로 전환
- 공고가 실제 공개 게이트인 `status='published' AND payment_status='paid'`를 최초로 충족

`status='published'` 단독으로는 잠그지 않는다. 현재 모든 공고는 `pending_review`로 생성되고,
무료 기본 공고는 `job_post.payment_status='paid'`로 생성되므로 생성 시의 `paid` 값만으로도 잠그지
않는다. 무료 공고와 함께 산 등록 옵션이 있으면 그 옵션의 실제 결제 완료 전환 또는 공고가 실제
공개 게이트를 충족하는 전환을 본다. 따라서 “코드상 무료라 paid 기본값”, “published지만 unpaid인
상태”, “운영자가 입금을 확인한 결제완료/실제 공개”를 구분한다.

공고 총 청구액은 `exposure_amount + detail_design_amount + purchase_source='job_registration'인
boost purchase amount 합계`다. 최종 입금액은 `max(0, 총 청구액 - points_used)`이며 구인자와
Admin이 같은 공용 계산 함수를 사용한다. 독립 구매(`purchase_source='standalone'`)는 제외한다.

공고 수정에서는 `points_used` 입력을 받지 않는다. 기존 스냅샷을 보존하고 서버가 새 총 청구액을
계산한 뒤 `총 청구액 < points_used`면 트랜잭션 전에 거부한다. 총액이 증가하거나 사용 포인트
이상으로 감소한 경우에는 기존 사용 포인트를 그대로 둔다.

공고 삭제는 삭제 전에 공고 행과 등록 결제 옵션을 잠그고 환급 가능 여부를 판정한다.
`points_used > 0 && points_refunded_at is null && points_refund_locked_at is null`일 때만
실제 `job_payment_use:{jobPostId}` 음수 차감 원장을 검증하고, 그 절댓값과 `points_used`가
일치할 때만 현재 잔액과 상한으로 실제 환급액·소멸액을 계산한다. 사용자가 확인한 예상값과 같을
때만 동일 트랜잭션에서 양수 환급 원장(0원이면 별도 완료 감사 기록)을 넣고 `points_refunded_at`을
기록한 뒤 삭제한다.
둘이 불일치하면 임의 금액을 환급하지 않고 전체 삭제를 실패시켜 운영자가 확인할 수 있게 한다. 공고 행이
삭제되어도 원장 외래키가 끊기지 않도록 원장은 `external_key` 문자열로 감사 흔적을 보존한다.

운영자 `adminDeleteJobPost`는 위 구인자 취소 환급 함수를 호출하지 않는다. 제재 삭제 사실과 원래
사용 포인트를 운영 기록에 남기되 자동 환급 원장은 만들지 않는다.

### 설정 API와 저장 경계

- 공개 조회는 가입 말풍선에 필요한 `signupPoints`만 최소 응답으로 제공한다.
- 로그인 구인자용 조회는 공고 최소·최대 설정과 본인 잔액을 서버에서 함께 제공한다.
- 운영자 조회는 전역 네 값과 모든 게시판의 key·label·글/댓글 포인트를 sort order대로 제공한다.
- 기타 포인트 설정의 게시판 목록은 공지사항·자유수다·밤문화 이야기·중고거래·무료 법률 자문을 각각 독립 아코디언으로 표시한다. 각 게시판은 자체 저장 버튼으로 해당 게시판 값만 저장하며 다른 게시판의 미저장 입력에는 영향을 주지 않는다.
- 공지사항은 운영자 작성 영역이므로 글 작성 포인트 입력을 노출하지 않고 서버에서도 글 작성 포인트를 0으로 고정한다. 댓글 작성 포인트만 편집할 수 있다.
- 화면 초깃값은 `community_board.post_points/comment_points`의 현재 저장값을 그대로 사용하고, 저장된 값은 기존 적립 로직의 정본으로서 저장 이후 새 글·댓글부터 반영한다.
- 운영자 저장은 전역 값과 게시판별 값을 하나의 DB 트랜잭션으로 갱신한다.
- 저장 payload의 게시판 key가 사라졌거나 중복되면 전체 저장을 거부한다. 일부만 저장하지 않는다.
- 숫자는 정수·0 이상만 허용한다. 최대값이 존재하고 활성 최소값보다 작으면 저장을 거부한다.
- 최소값 null/빈칸/0은 공고 포인트 사용 중단으로 정규화한다. 최대값 빈칸은 null로 저장한다.

### 가입 보너스 경계

`createBambiProfile`의 프로필 insert와 가입 보너스 원장 insert를 같은 DB 트랜잭션으로 묶는다.
인증만 성공했거나 auth 계정만 생성된 상태에는 지급하지 않는다. 구직자·구인자 프로필 생성이
성공한 경우에만 그 트랜잭션에서 읽은 설정값을 지급한다. 설정값 0은 원장 행도 만들지 않는다.
원장 적립은 기존 회원 포인트 상한을 적용하되, unique external key로 재호출을 멱등 처리한다.

### 출석·게시판 설정 적용

- 출석은 체크인 insert와 같은 트랜잭션에서 현재 `attendance_points`를 읽고 그날 스냅샷 금액을 지급한다.
- 가입·출석·게시판 적립은 공용 원장 서비스에서 회원 최대 보유 포인트를 다시 읽어 최대치까지만
  지급한다. 공고 환급도 해당 공고의 검증된 차감액을 대상으로 하되 환급 시점의 최대 보유 포인트
  여유까지만 복원하고 초과분은 소멸한다.
- 출석 화면의 “10포인트” 고정 문구도 조회 응답 금액으로 바꾼다.
- 게시판별 글/댓글은 기존 `community_board.post_points/comment_points`와 콘텐츠별
  `points_awarded` 스냅샷 구조를 그대로 유지한다.
- 설정 변경 후 새 콘텐츠부터 새 금액을 쓰며 과거 콘텐츠 원장/스냅샷은 일괄 수정하지 않는다.

### 남성 커뮤니티 권한

현재 전역 커뮤니티 게이트는 남성 구직자를 게시판 판정 전에 막고, 법률자문가는 성별과 무관하게
법률게시판 하나로 격리한다. 이를 board-aware 정책으로 확장한다.

- 남성 job_seeker + `notice`: 읽기만 허용(공지 작성은 기존 Admin 전용 유지).
- 남성 job_seeker + 그 외 실제/가상 게시판(`best`, 수집 상세 포함): 목록·상세·작성·댓글·추천 거부.
- 남성 legal_advisor + `legal`: 기존 읽기·글·댓글·잠금 우회 권한 유지.
- 남성 legal_advisor + `notice`: 읽기만 허용.
- 남성 legal_advisor + 그 외: 거부.
- 여성 legal_advisor는 기존 정책(legal만)을 그대로 유지한다.
- 거부 판단은 공용 서비스에서 하고 목록, 상세, 댓글, 추천, 글쓰기 API가 같은 함수를 사용한다.
- 활성 게시판/홈 미리보기도 허용 게시판만 필터링해 빈 카드나 접근 불가 링크를 노출하지 않는다.

### 개인 포인트 잔액·이력과 운영자 지급 알림

- 구직자와 구인자가 함께 쓰는 `/seeker/me/settings`의 `프로필 사진 설정` 바로 아래에
  `보유 포인트` 카드를 추가한다. 출석 화면으로 이동하지 않아도 현재 원장 순합계를 볼 수 있다.
- `보유 포인트` 카드는 버튼형 아코디언이다. 펼치면 최신 거래부터 `포인트`, `내용`, `날짜`
  열로 표시하고, 금액은 `+10P`/`-10P`, 날짜는 KST `YYYY.MM.DD` 형식으로 표시한다.
- 거래 이력은 본인 원장만 서버에서 조회하며 최신순 10건씩 커서 페이지네이션한다. 빈 원장은
  잔액 `0P`와 빈 이력 안내를 정상 상태로 표시하고, 실패 상태와 구분한다.
- 원장의 내부 reason 문자열을 그대로 노출하지 않고 가입, 출석체크, 게시판 글·댓글 작성,
  운영자 지급·차감, 공고 등록 사용·취소 환급처럼 사용자가 이해할 수 있는 문구로 변환한다.
- 운영자 수동 조정 중 양수 지급이 성공하면 수신자 개인 알림을 한 건 생성한다. 문구는
  `운영자로부터 N 포인트가 지급되었습니다!`이며, 차감에는 이 지급 알림을 만들지 않는다.
- 지급 알림은 포인트 거래를 식별하는 별도 `point_transaction` 알림 타입을 사용한다. 알림을
  누르면 `/seeker/me/settings#point-history`로 이동하고 포인트 아코디언이 자동으로 열린다.
- 포인트 조정 트랜잭션이 커밋된 뒤 알림을 best-effort로 생성한다. 원장 기록 성공을 알림 실패로
  롤백하지 않으며, 실패한 포인트 조정에는 알림을 만들지 않는다.
- 구직자·구인자 내 정보 메뉴의 기존 `출석체크` 이름을 `포인트 내역`으로 바꾸고 동전 아이콘을
  사용한다. 주소는 기존 `/seeker/attendance`·`/employer/attendance`를 유지한다.
- 계정 설정의 보유 포인트 아코디언은 제거하고 포인트 내역 페이지로 이동한다. 페이지 순서는
  `포인트 내역` 제목 → `오늘 출석` → 기본 접힘 `출석 달력` → 기본 접힘 `보유 포인트` 거래
  내역이다. 지급 알림 딥링크도 새 포인트 내역 위치로 변경한다.
- 출석 달력은 아코디언을 펼친 뒤 월 이동과 출석일을 확인한다. 보유 포인트 아코디언은 기존
  최신순 거래 내역과 더보기를 그대로 재사용한다.
- 내 정보 허브의 기존 5개 메뉴 카드 위에 전체 너비 포인트 요약 카드를 추가한다. 현재 보유
  포인트·현재 등급·다음 등급까지 남은 포인트를 표시하고, 최고 등급이면 `최고 등급입니다`로
  표시한다. 카드 본문은 포인트 내역으로 이동한다.
- 요약 카드 우측 `출석하기`는 페이지 이동 없이 즉시 출석 처리한다. 이미 출석했으면
  `출석 완료`로 바꾸고 비활성화하며, 원장·요약·출석 페이지 쿼리를 함께 갱신한다.

### 운영자 회원 포인트 관리

- 포인트 관리 하위 메뉴는 `출석 관리`, `등급 관리`, `포인트 관리`, `기타 포인트 설정`
  순서로 구성한다. 회원 목록은 `/moderator/points/members`, 상세는
  `/moderator/points/members/{userId}`를 사용한다.
- 목록은 출석 관리의 검색·역할 필터와 회원 표시를 재사용하되 출석 집계 열을 제거하고
  `회원`, `역할`, `포인트`, `관리`만 표시한다. 구직자·구인자를 대상으로 닉네임·로그인
  아이디 검색과 역할 필터를 제공하며 페이지당 10명, 공용 숫자 페이지 컨트롤을 사용한다.
- 행 또는 회원 이름을 누르면 포인트 전용 회원 상세로 이동한다. 상세 상단은 기존 사용자 상세의
  프로필·가입일·상태 표현을 재사용하되 누적 신고·경고·차단 통계와 제재 기능을 제거한다.
- 상세 상단의 `포인트 사용 내역 N건`은 사용자가 소비하거나 환급받은 공고 결제 거래만 모아
  아코디언으로 표시한다. 공고 등록 당시 상품·옵션 이름을 원장 description에 스냅샷으로 남겨
  공고가 수정·삭제돼도 `공고 등록(스페셜 채용)`, `무료 공고 + 끌어올리기`,
  `공고 취소 환급(스페셜 채용)`처럼 당시 내용을 유지한다.
- 계정 정보는 이메일·로그인 아이디·휴대폰 인증 상태를 기존 상세와 동일하게 표시한다.
- `포인트 이력`은 가입·출석·게시판 적립·회수·공고 사용·환급·운영자 지급·차감을 모두 최신순으로
  표시한다. 각 행은 증감 금액, 날짜·시각, 사유, 해당 거래 처리 후 총 보유 포인트, 처리자를
  표시한다. 운영자 수동 거래는 실제 운영자 표시 이름, 기존 거래는 `처리자 기록 없음`, 자동
  거래는 `시스템`으로 표시한다.
- 포인트 이력은 페이지당 10건이며 `< 숫자 입력칸 / 전체 페이지 수 >` 공용 컨트롤을 쓴다.
  기존 원장의 처리 후 잔액은 현재 잔액에서 더 최신 거래 금액을 역산해 표시한다.
- `포인트 적용`에는 `포인트 지급`, `포인트 차감` 두 동작을 둔다. 각각 양의 정수 금액과 필수
  사유를 입력하는 확인/취소 다이얼로그를 사용한다. 지급은 최대 보유 포인트까지만 반영하고,
  차감은 현재 잔액을 초과할 수 없다.
- 원장에 nullable `actor_user_id`, `balance_after`, `description`을 Drizzle migration으로
  추가한다. 신규 수동 거래는 처리 운영자와 적용 후 잔액을, 신규 자동 거래는 적용 후 잔액을,
  공고 사용·환급은 표시용 상품·옵션 스냅샷을 함께 기록한다.

## 핵심 검증

- 가입 1000P 정확히 1회, 설정 500P 변경 후 신규 가입 500P, 0P일 때 미지급·말풍선 숨김.
- 출석 설정 변경 이후 첫 출석에 변경값 지급, 중복 출석 미지급.
- 게시판별 글/댓글 설정을 각각 변경하고 저장 이후 새 작성분에만 적용.
- 최소값 미설정/0, 잔액 부족, 결제액 부족에서 포인트 UI/API 차단.
- 전액 사용과 직접 입력이 동일한 서버 확정값을 생성.
- 동시 공고 등록으로 잔액을 초과해 차감하지 못함.
- 같은 등록 멱등키의 더블클릭·네트워크 재시도는 공고·옵션·차감 원장을 각각 한 번만 생성.
- 포인트 적립과 공고 차감이 동시에 실행돼도 계정 단위 잠금으로 상한 초과·음수 잔액 없음.
- 미결제·미공개 삭제 1회 환급, 중복 삭제/재시도 중복 환급 없음.
- 환급 예상 확인 뒤 잔액이 바뀌어 소멸액이 증가하면 삭제를 거부하고 최신 AlertDialog로 재확인.
- 최대 보유 포인트 여유가 부족하면 일부/0P만 환급되고 초과분은 소멸하며, 같은 공고에서 재환급 없음.
- 포인트로 최종 입금액이 0원이 되어도 운영자 결제완료 전에는 삭제 환급 가능하고 자동 공개·잠금 없음.
- 운영자 하드 삭제는 자동 환급하지 않으며 운영 기록에 사용 포인트를 남김.
- 환급 대상액은 저장된 사용값이나 클라이언트 값이 아니라 원래 음수 차감 원장의 절댓값과
  일치하고, 실제 환급액은 상한 여유로 제한하며, 차감 원장 불일치 시 삭제·환급 모두 실패.
- 반려 후 재제출은 미환급·기존 사용량 유지, 반려 후 삭제는 환급.
- 결제/공개 이력 후 상태를 되돌리고 삭제해도 미환급.
- 수정 금액 증가 시 사용 포인트 유지, 수정 금액이 사용 포인트 미만이면 UI와 API 모두 거부.
- Admin과 구인자의 최종 결제금액 및 포인트 breakdown 일치.
- 일반 남성 구직자와 남성 법률자문가의 허용 게시판 외 직접 API 접근 거부.
- 구직자·구인자 계정 설정에서 원장 순합계와 본인 거래만 보이고, 10건 이후 이력이 중복·누락 없이 이어짐.
- 운영자 양수 지급 성공 시 정확한 금액의 알림 1건이 생성되고, 알림 선택 시 포인트 이력 아코디언이 열림.
- 운영자 차감·실패한 지급에는 지급 알림이 생성되지 않음.
