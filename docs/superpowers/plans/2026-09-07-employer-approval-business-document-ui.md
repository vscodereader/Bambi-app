# 업소 승인 상태·사업자 인증 서류 UI 교정 구현 계획

**Goal:** 운영자 업소 관리에서 이미 승인된 업소를 중복 승인할 수 없게 하고, 구인자·운영자 화면의 이미지/PDF 사업자 인증 서류를 동일한 파일 행으로 표시한다.

**Branch:** `fix/employer-approval-business-document-ui`

**Base:** 최신 `origin/develop` (`06350327`, PR #301 머지 커밋)

## 확정 요구사항

- `verificationStatus === "verified"`인 업소의 승인 버튼만 비활성화한다. 반려 사유 입력과 반려 버튼은 기존처럼 사용할 수 있게 유지한다.
- 반려 업소의 재승인과 변경사항 재제출 후 심사는 기존 상태 전이 동작을 유지한다.
- 사업자 인증 서류의 이미지와 PDF는 미리보기 크기에 따라 서로 다른 UI를 쓰지 않는다.
- 두 형식 모두 파일 종류 아이콘, 말줄임 파일명, 형식·용량, 다운로드 버튼, 삭제 버튼을 같은 행 구조로 표시한다.
- 구인자와 운영자 화면 모두 파일명·아이콘이 있는 파일 정보 영역을 클릭하거나 키보드로 실행하면 원본을 새 탭에서 연다.
- 신규 구인자가 파일을 선택하고 아직 `업체 정보 제출`을 누르지 않은 업로드 대기 상태에서도 이미지/PDF 모두 원본 열기와 다운로드를 제공한다.
- 여러 서류는 같은 크기의 행 카드로 배치하되 모바일은 1열, 데스크톱은 최대 2열로 표시한다. 3~5번째 서류는 다음 행으로 자연스럽게 줄바꿈한다.
- 기존 비공개 문서 열람 URL, 강제 다운로드 URL, 삭제 확인창과 권한 정책은 변경하지 않는다.
- 새 색상값이나 파일 정책을 하드코딩하지 않고 기존 시맨틱 토큰, 공용 버튼, 문서 타입과 URL을 재사용한다.

## 설계

### 1. 공용 파일 행

`apps/web/src/components/bambi/business-document-file-row.tsx`를 추가한다.

- 기존 업로더가 export하던 `BusinessDocument` 타입을 이 파일로 이동하고, 저장 완료 문서와 업로드 대기 파일이 함께 사용할 수 있는 최소 파일 계약을 받는다.
- `apps/web/src/app/employer/me/page.tsx`도 공용 파일 행에서 `BusinessDocument` 타입을 import하도록 변경해 업로더와 공용 행 사이의 순환 참조를 만들지 않는다.
- 이미지에는 `ImageIcon`, PDF에는 `FileTextIcon`을 사용한다.
- 파일명은 `truncate`와 `title`로 짧게 표시하되 전체 이름을 확인할 수 있게 한다.
- 형식 표시는 문서의 `category`에서 `이미지` 또는 `PDF`로 계산하고, 용량 표시는 기존 업로더의 바이트 포맷을 이동해 재사용한다.
- 원본 열기 링크는 구인자·운영자 화면에서 동일하게 행의 파일명·아이콘 정보 영역만 감싸고, 다운로드·삭제 액션과 중첩되지 않게 한다.
- 다운로드는 기존 `?download=1` URL을 호출자가 전달하고, 삭제는 호출 화면의 기존 버튼/확인 로직을 `actions` 슬롯으로 유지한다.
- Tailwind와 `@bambi-app/ui` 버튼 변형만 사용하고 raw 색상·인라인 스타일·새 CSS는 추가하지 않는다.

### 2. 구인자 업체 정보

`business-document-uploader.tsx`의 저장 완료 문서 목록에서 중복 파일 행 마크업을 공용 컴포넌트로 교체한다.

- 기존 새 창 열기 전용 아이콘은 제거하고 파일 정보 영역 자체를 원본 링크로 만든다.
- 저장 완료 문서의 다운로드·삭제 잠금, 승인 상태 변경 확인창과 업로드 대기 목록의 제출·제거 상태 관리는 기존 동작을 유지한다.
- 저장 완료 문서 목록과 업로드 대기 문서 목록 모두 모바일 1열, 기존 업체 정보 화면의 데스크톱 전환 기준인 `md` 이상에서 최대 2열로 표시한다.
- 업로드 대기 파일은 `URL.createObjectURL(file)`로 로컬 열람·다운로드 URL을 만들고 공용 파일 행에 전달한다. 파일 제거·교체 또는 컴포넌트 언마운트 시 `URL.revokeObjectURL`로 해제한다.
- 업로드 대기 파일도 MIME 유형에서 기존 허용 범위 내 `image`/`pdf` category를 계산해 동일한 아이콘·파일명·형식·용량·다운로드·삭제 아이콘을 사용한다. 삭제 아이콘은 서버 삭제가 아니라 기존 staged 목록 제거 동작을 호출한다.

### 3. 운영자 업소 관리

`moderator/employers/page.tsx`에서 채팅 전용 `ChatAttachmentPreview` 사용을 제거하고 공용 사업자 문서 행을 사용한다.

- 이미지 대형 썸네일을 제거해 PDF와 같은 높이의 행으로 표시한다.
- 문서 그리드는 모바일 1열, 기존 업체 정보 화면과 같은 `md` 이상에서 최대 2열로 고정하고 삭제 확인창은 유지한다.
- 승인 버튼은 `decide.isPending || employer.verificationStatus === "verified"`일 때만 비활성화한다. 승인 완료 상태에서도 반려 사유 입력과 반려 버튼은 기존 조건을 유지한다.

### 4. 회귀 테스트

웹 정적 배선 테스트를 추가해 다음을 고정한다.

- 운영자 화면이 승인 완료 상태를 승인 버튼 비활성 조건에 포함한다.
- 구인자와 운영자 화면이 같은 사업자 문서 행 컴포넌트를 사용한다.
- 공용 행이 이미지/PDF 아이콘, 원본 열기, 다운로드 및 액션 슬롯을 제공한다.
- 운영자 화면에서 채팅 이미지 미리보기 컴포넌트를 더 이상 사용하지 않는다.
- 구인자 저장 완료·업로드 대기 목록과 운영자 문서 그리드가 모바일 1열과 데스크톱 최대 2열만 사용한다.
- 업로드 대기 파일이 로컬 객체 URL로 원본 열기·다운로드를 제공하고 수명 종료 시 URL을 해제한다.
