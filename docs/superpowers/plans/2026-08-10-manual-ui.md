# 역할별 사용자 매뉴얼 UI 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docs/manual/`의 역할별 매뉴얼 md 3종을 로그인 사용자에게 역할 위계에 따라 `/manual/*` 웹 UI로 보여준다.

**Architecture:** RSC에서 `fs.readFile`로 md 원본을 읽고(단일 소스, 복사본 없음) 이미 설치된 `streamdown`으로 렌더한다. 역할 위계 가드(`job_seeker`·`legal_advisor`→seeker, `employer`→seeker+employer, `admin`→전부)는 기존 `require-role.ts` 패턴을 확장한다. 목차는 헤딩 파싱으로 생성하고 GitHub식 slug anchor로 본문과 연결한다.

**Tech Stack:** Next.js 16 App Router(RSC), streamdown@1.6.x(설치됨·미사용), shadcn(base-ui) 컴포넌트, Tailwind v4, vitest(루트 설치).

**Spec:** `docs/superpowers/specs/2026-08-10-manual-ui-design.md`

## Global Constraints

- **새 npm 의존성 추가 금지.** md 렌더는 streamdown(설치됨)만 사용.
- **빌드·dev 서버 기동 금지.** 검증은 린트+타입체크+vitest, 시각 확인은 사용자.
- **shadcn + Tailwind만.** 인라인 `style` 금지, 새 `.css` 파일 금지(기존 `index.css` 수정은 가능), 임의 px(`[Npx]`) 금지 — Tailwind 스케일 토큰 사용(계산형 `calc` rem은 허용). 시맨틱 색 토큰(`text-muted-foreground` 등)만. `space-y-*` 금지 → `flex flex-col gap-*`. 조건부 클래스는 `cn()`. base-ui라 커스텀 트리거는 `asChild`가 아니라 `render` prop.
- **내비 링크에 primary 버튼 금지** — primary는 주요 액션 한 곳만.
- **enum/키 원값 화면 노출 금지** — 표시 문구는 라벨 맵(`MANUAL_LABELS`) 경유.
- `typedRoutes: true` — 리터럴 외 경로는 `as Route` 캐스트(기존 관례).
- **작업 전 워크트리에서 `pnpm install` 필수.** 줄바꿈은 LF.
- 커밋 메시지: 한국어 `type: 제목` + 촘촘한 `- ` 블릿 본문(블릿 사이 빈 줄 없음). Bash에서는 temp 파일 + `git commit -F`.
- vitest는 **워크트리 루트에서** 경로를 지정해 실행(리포 루트 실행 금지 — 다른 워크트리까지 긁힘).
- ultracite는 **경로 인자 필수**(`pnpm dlx ultracite fix <paths>` — 경로 없이 돌리면 0파일).
- web 패키지 필터명은 `web`(scope 없음): `pnpm --filter web check-types`.
- push·PR 금지. 로컬 커밋까지만.
- web 테스트는 기존 관례대로 **소스 옆 colocated `*.test.ts` + 상대 경로 import**(web 전용 vitest config가 없어 `@/` alias가 안 풀린다 — `use-block-resize.ts` 주석 참고).

		return ["seeker", "employer", "moderator"];
	}

		return ["seeker", "employer"];
	}
	return ["seeker"];

export const defaultManualKeyForRole = (role: BambiRole): ManualKey => {
	if (role === "admin") {
		return "moderator";
	}
	if (role === "employer") {
		return "employer";
	}
	return "seeker";
};

```ts
// 매뉴얼 md의 제목·목차·헤딩 앵커 파싱. fs 없는 순수 모듈이다 —
// 클라이언트 본문 렌더러(manual-body.tsx)가 githubSlug를 같이 쓴다.

// GitHub 헤딩 앵커 규칙: 소문자화 → 글자·숫자·공백·하이픈·언더스코어 외 제거 →
// 공백 1칸당 하이픈 1개. 매뉴얼 본문의 수기 목차 링크(#3-1-공고-탐색-채용정보)와
// 일치해야 문서 내 이동이 동작한다.
// ponytail: 중복 헤딩에 -1, -2 접미를 붙이는 GitHub 규칙은 생략 — 매뉴얼 헤딩은
// 절 번호로 유일하다. 중복이 생기면 같은 id가 두 번 나올 뿐(첫 앵커로 이동).
const SLUG_STRIP = /[^\p{L}\p{N} _-]/gu;

export const githubSlug = (text: string): string =>
	text.trim().toLowerCase().replace(SLUG_STRIP, "").replace(/ /g, "-");

export interface ManualHeading {
	depth: 2 | 3;
	slug: string;
	text: string;
}

export interface ParsedManual {
	headings: ManualHeading[];
	markdown: string;
	title: string;
}

const HEADING_RE = /^(#{2,3}) (.+)$/;

// 첫 `# 제목`은 페이지 헤더로 따로 렌더하므로 본문에서 뺀다. 수기 "## 목차" 섹션은
// UI 목차 사이드바와 중복이라 다음 헤딩 전까지 통째로 걷어낸다.
export function parseManual(raw: string): ParsedManual {
	const kept: string[] = [];
	const headings: ManualHeading[] = [];
	let title = "";
	let inFence = false;
	let skippingToc = false;

	for (const line of raw.split("\n")) {
		if (line.startsWith("```")) {
			inFence = !inFence;
		}
		if (!inFence) {
			if (!title && line.startsWith("# ")) {
				title = line.slice(2).trim();
				continue;
			}
			const match = HEADING_RE.exec(line);
			if (match) {
				const text = match[2].trim();
				skippingToc = text === "목차";
				if (!skippingToc) {
					headings.push({
						depth: match[1].length as 2 | 3,
						slug: githubSlug(text),
						text,
					});
				}
			}
			if (skippingToc) {
				continue;
			}
		}
		kept.push(line);
	}

	return { headings, markdown: kept.join("\n"), title };
}
```

// docs/manual/*.md를 읽어 파싱한다. node:fs를 쓰는 서버 전용 모듈 —
// 클라이언트에서 import 금지(순수 파싱은 manual-parse.ts에 있다).
import { promises as fs } from "node:fs";
import path from "node:path";
import type { ManualKey } from "./manual";
import { type ParsedManual, parseManual } from "./manual-parse";

const MANUAL_FILES: Record<ManualKey, string> = {
	seeker: "seeker-manual.md",
	employer: "employer-manual.md",
	moderator: "moderator-manual.md",
};

// next dev/build의 cwd는 apps/web, 루트에서 도는 도구는 리포 루트 — 둘 다 시도한다.
const MANUAL_DIR_CANDIDATES = [
	["..", "..", "docs", "manual"],
	["docs", "manual"],
];

export async function loadManual(
	key: ManualKey
): Promise<ParsedManual | null> {
	for (const segments of MANUAL_DIR_CANDIDATES) {
		const filePath = path.join(process.cwd(), ...segments, MANUAL_FILES[key]);
		try {
			const raw = await fs.readFile(filePath, "utf8");

"use client";

// 매뉴얼 md 본문 렌더러. streamdown(react-markdown 호환)을 쓰고, h2/h3에
// GitHub식 slug id를 붙여 md 본문 수기 목차 링크와 UI 목차가 실제로 이동하게 한다.
// components 오버라이드는 함수라 RSC에서 직렬화해 넘길 수 없어 여기(클라이언트)서 정의한다.
import { isValidElement, type ReactNode } from "react";
import { Streamdown } from "streamdown";
import { githubSlug } from "@/lib/bambi/manual-parse";

// 헤딩 children에서 텍스트만 회수한다(굵게 등 인라인 마크업이 섞인 헤딩 대응).
const textOf = (node: ReactNode): string => {
	if (typeof node === "string" || typeof node === "number") {
		return String(node);
	}
	if (Array.isArray(node)) {
		return node.map(textOf).join("");
	}
	if (isValidElement<{ children?: ReactNode }>(node)) {
		return textOf(node.props.children);
	}
	return "";
};

// scroll-mt는 sticky 헤더(top-20) 아래로 앵커가 숨지 않게 하는 오프셋.
function Heading2({ children }: { children?: ReactNode }) {
	return (
		<h2 className="scroll-mt-24" id={githubSlug(textOf(children))}>
			{children}
		</h2>
	);
}

function Heading3({ children }: { children?: ReactNode }) {
	return (
		<h3 className="scroll-mt-24" id={githubSlug(textOf(children))}>
			{children}
		</h3>
	);
}

export function ManualBody({ markdown }: { markdown: string }) {
	return (
		<Streamdown components={{ h2: Heading2, h3: Heading3 }}>
			{markdown}
		</Streamdown>
	);
}
```
