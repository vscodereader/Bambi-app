# 밤비 반응형 마켓플레이스 재설계

작성일: 2026-06-23
상태: 사용자 리뷰 대기

## 1. 목적

밤비를 모바일 전용 앱 프리뷰가 아니라, 모바일과 PC 모두에서 자연스럽게 쓰는 반응형 구인구직 웹으로 재설계한다.

레퍼런스인 foxalba의 장점은 지역, 직종, 급여를 빠르게 훑는 탐색성이다. 단점은 광고판 중심 구조, 업주 중심 카피, 연락처 즉시 노출, 검증 정보 부족, 모바일에서의 선택 피로다. 밤비는 이 탐색성을 가져오되, 2030 여성 구직자가 안전하게 비교하고 플랫폼 안에서 채팅과 면접으로 넘어가는 경험을 중심에 둔다.

이번 재설계 범위는 다음 세 가지다.

1. 구직자 탐색 경험
2. 전체 반응형 뼈대
3. 서비스 첫인상

## 2. 제품 원칙

- 첫 화면은 마케팅 랜딩보다 채용 탐색이 먼저다.
- 구직자 개인정보와 연락처 보호를 제품의 핵심 신뢰 신호로 노출한다.
- PC에서는 많은 정보를 비교할 수 있게 하되, foxalba식 광고 밀도와 과장 카피는 따르지 않는다.
- 모바일에서는 앱처럼 빠르고 단순한 단일 컬럼 흐름을 유지한다.
- 공고 상세와 채팅 시작 전까지 검증 상태, 조건, 위험 신호, 신고 가능성을 계속 보이게 한다.
- 구인자와 운영자 화면은 같은 반응형 셸 위에서 대시보드형으로 확장한다.

## 3. 정보 구조

### 비로그인 사용자

- `/`
  - 바로 탐색 가능한 공고 홈을 보여준다.
  - 상단에는 밤비 로고, 채용정보, 안전가이드, 업체 인증, 로그인/시작하기를 둔다.
  - 첫 화면에는 검색, 지역, 업종, 급여, 검증 완료, 오늘 면접 가능 같은 빠른 필터를 배치한다.
  - 로그인 전에도 공고 목록과 기본 상세는 볼 수 있다.
  - 채팅 시작, 스크랩, 연락처 공개 같은 액션은 로그인과 필요한 인증을 요구한다.

### 구직자

- `/seeker`
  - 로그인한 구직자의 기본 홈이자 공고 탐색 화면이다.
  - 모바일에서는 검색, 신뢰 배너, 추천 필터, 공고 카드 리스트, 하단 탭 순서로 구성한다.
  - PC에서는 필터 사이드바, 공고 리스트, 선택 공고 요약 패널을 한 화면에 배치한다.

- `/seeker/jobs/[id]`
  - 모바일에서는 상세 정보를 단일 컬럼으로 보여주고 하단에 채팅 시작 CTA를 고정한다.
  - PC에서는 본문과 우측 sticky 신뢰/조건/CTA 패널을 분리한다.
  - 연락처는 면접 확정 전까지 비공개임을 상세 상단과 CTA 주변에 반복해서 보여준다.

- `/seeker/chats`와 `/seeker/chats/[id]`
  - 모바일에서는 기존 채팅 중심 흐름을 유지한다.
  - PC에서는 채팅 목록과 채팅방을 2분할하고, 면접 일정 패널을 우측에 둘 수 있게 한다.

### 구인자와 운영자

- 구인자와 운영자는 이번 1차 재설계의 상세 화면 대상은 아니지만, 공통 셸을 공유해야 한다.
- PC에서는 대시보드 내비게이션과 작업 패널을 사용할 수 있어야 한다.
- 모바일에서는 현재처럼 단일 컬럼 폼과 리스트로 자연스럽게 내려온다.

## 4. 반응형 레이아웃

### 모바일: 0px 이상

- 단일 컬럼 앱형 구조를 사용한다.
- 주요 내비게이션은 하단 탭이다.
- 필터는 수평 칩과 전체 필터 바텀시트로 제공한다.
- 공고 카드는 한 손 조작에 맞춰 큰 터치 영역을 가진다.
- 상세 CTA는 화면 하단에 고정한다.

### 태블릿: 768px 이상

- 상단 내비게이션을 노출한다.
- 필터는 접히는 패널이나 좌측 rail로 전환한다.
- 공고 상세는 목록에서 진입하는 별도 페이지를 유지하되, 주요 조건 요약은 상단에 붙인다.

### PC: 1024px 이상

- 최대 폭이 과하게 좁은 모바일 프레임을 폐기한다.
- 공고 탐색은 3영역 구조를 기본으로 한다.
  - 좌측: 빠른 필터와 안전/인증 안내
  - 중앙: 검색, 추천 칩, 공고 리스트
  - 우측: 선택 공고 요약, 조건, 검증 상태, 채팅 CTA
- 상세 페이지는 2영역 구조를 기본으로 한다.
  - 중앙: 공고 본문, 조건, 후기, 신고 안내
  - 우측: sticky CTA 패널
- PC에서도 정보가 카드 더미처럼 흩어지지 않게 리스트와 패널 중심으로 만든다.

## 5. 화면 설계

### 5.1 서비스 첫인상

비로그인 첫 화면은 “밤비 소개 랜딩”이 아니라 “바로 탐색 가능한 신뢰형 채용 홈”이다.

첫 viewport에는 다음 요소가 들어간다.

- 브랜드와 상단 내비게이션
- 한 줄 가치 제안: 안전하게 비교하고, 연락처는 면접 전까지 보호
- 검색 입력
- 지역, 업종, 급여 빠른 필터
- 검증 완료, 오늘 면접 가능, 초보 가능, 당일 지급, 내 주변 같은 추천 칩
- 추천 공고 리스트 일부
- 연락처 보호와 검수 정책을 짧게 설명하는 신뢰 배너

마케팅 설명, 운영 철학, 안전 가이드는 첫 화면 아래로 보낸다.

### 5.2 구직자 탐색 홈

탐색 홈의 핵심 작업은 “조건에 맞는 안전한 공고를 빠르게 고르는 것”이다.

공고 카드에는 다음 정보를 우선순위대로 표시한다.

- 공고 제목과 업체명
- 지역과 업종
- 급여 단위와 금액
- 검증 상태
- 근무 시간 또는 오늘 가능 여부
- 후기 수와 평점
- 채팅 CTA

카드에서 과장된 홍보 문구는 한 줄 이하로 제한한다. 긴 설명은 상세에서만 보여준다.

필터는 다음을 1차로 제공한다.

- 지역
- 업종
- 급여
- 검증 상태
- 근무 가능 시간
- 초보 가능

### 5.3 공고 상세

상세는 “광고 문구를 길게 읽는 화면”이 아니라 “지원 판단을 빠르게 끝내는 화면”이다.

상단에는 다음을 배치한다.

- 공고 제목
- 업체명과 지역
- 검증 상태
- 핵심 급여
- 채팅 시작 CTA
- 연락처 보호 안내

본문은 다음 섹션으로 정리한다.

- 핵심 조건
- 업무와 근무 환경
- 급여와 정산 방식
- 면접 방식
- 업체 검증 정보
- 후기
- 신고와 차단 안내

PC 우측 sticky 패널에는 급여, 위치, 근무 시간, 검증 상태, 후기 요약, 채팅 시작 CTA를 고정한다.

### 5.4 채팅 시작 전 보호 흐름

채팅 시작 버튼을 누르면 바로 외부 연락처로 보내지 않는다.

기본 흐름은 다음과 같다.

1. 로그인 상태 확인
2. 구직자 프로필 여부 확인
3. 휴대폰 인증 필요 여부 확인
4. 공고 상태와 상대 제재 상태 확인
5. 플랫폼 채팅방 생성

채팅방에는 면접 확정 전 연락처 공유 제한 안내, 신고 버튼, 차단 기능 진입점을 보여준다.

## 6. 공통 셸

현재 `AppShell`은 데스크톱에서 모바일 프레임을 가운데 보여주는 프리뷰 성격이 강하다. 실서비스 셸은 다음 책임을 가진다.

- 모바일과 PC의 내비게이션 전환
- 역할별 주요 진입점 제공
- 페이지 최대 폭과 레이아웃 그리드 제공
- 공통 배경, 표면, 여백, 헤더 높이 관리
- 인증 상태와 알림 진입점 표시

### 모바일 셸

- 상단: 로고, 보호 상태, 알림
- 본문: 단일 컬럼
- 하단: 역할별 탭

### PC 셸

- 상단: 로고, 채용정보, 채팅, 안전가이드, 업체 인증, 로그인/내 정보
- 본문: 역할과 화면에 따라 2열 또는 3열 그리드
- 보조 패널: 필터, 상세 요약, 작업 상태를 sticky로 배치

## 7. 디자인 톤

기존 밤비의 코랄과 잉크 색상은 유지한다.

- 코랄: 주요 CTA, 선택 상태, 따뜻한 보호 메시지
- 잉크: 검증된 추천 공고, 헤더 강조, 신뢰 앵커
- 그린: 인증 완료, 안전 상태
- 앰버/레드: 검수 대기, 신고, 위험 신호

다만 PC에서는 코랄이 과하게 넓은 면적을 차지하지 않게 한다. 넓은 배경은 흰색과 옅은 회색을 중심으로 두고, 코랄은 행동과 선택을 표시하는 데 쓴다.

카드는 반복 아이템에만 사용한다. 페이지 전체를 카드 안에 넣거나 카드 안에 카드를 중첩하지 않는다. PC 화면은 리스트, 패널, 섹션 밴드 중심으로 정리한다.

## 8. 컴포넌트 방향

이번 재설계에서 필요한 주요 컴포넌트는 다음과 같다.

- `ResponsiveAppShell`
- `DesktopTopNav`
- `MobileBottomNav`
- `ResponsiveMarketplaceLayout`
- `SearchAndQuickFilters`
- `FilterSidebar`
- `JobList`
- `ResponsiveJobCard`
- `SelectedJobPanel`
- `JobDetailHero`
- `JobTrustPanel`
- `StickyContactSafeCta`

기존 `SeekerHome`, `SeekerDetail`, `JobCard`, `SearchField`, `Badge`, `Button`, `Tag`는 가능한 재사용하되, 모바일 프리뷰 전용 크기와 실제 반응형 웹 책임을 분리한다.

## 9. 상태와 오류 처리

공고 탐색에는 다음 상태를 준비한다.

- 로딩
- 빈 결과
- 필터 결과 없음
- 인증 필요
- 공고 비공개 또는 검수 대기
- 정지된 사용자 액션 차단
- 채팅 시작 실패

빈 상태는 “조건을 줄여보세요” 수준을 넘어, 지역/업종/급여 추천 필터를 바로 제안해야 한다.

## 10. 제외 범위

이번 재설계 스펙에서 제외하는 것은 다음과 같다.

- 실제 결제나 유료 광고 상품
- 고도화 추천 알고리즘
- 실시간 WebSocket 채팅
- 네이티브 앱 전용 화면
- 관리자 심사 기능의 세부 UX
- 구인자 공고 등록 플로우의 전면 재설계

다만 공통 셸과 반응형 규칙은 구인자와 운영자 화면이 이후 자연스럽게 올라탈 수 있도록 만든다.

## 11. 구현 순서 제안

1. 공통 반응형 셸을 만든다.
2. 구직자 탐색 홈을 모바일/PC 양쪽으로 구현한다.
3. 공고 상세의 PC sticky 패널과 모바일 하단 CTA를 구현한다.
4. 비로그인 첫 화면을 탐색 홈 기반으로 정리한다.
5. 채팅 시작 전 인증/보호 메시지를 연결한다.
6. 기존 프리뷰 화면은 실서비스 화면과 분리하거나 디자인 검토용으로만 남긴다.

## 12. 검증 기준

- 모바일 375px에서 탐색 홈, 상세, 채팅 시작 CTA가 겹치지 않는다.
- 태블릿 768px에서 필터와 목록이 자연스럽게 전환된다.
- PC 1280px에서 필터, 목록, 상세 요약 패널이 한 화면에 들어온다.
- 비로그인 사용자가 첫 화면에서 검색과 주요 필터를 즉시 이해한다.
- 로그인 전 채팅 시작은 인증 요구로 이어진다.
- 로그인한 구직자는 공고 상세에서 플랫폼 채팅을 시작할 수 있다.
- 연락처 보호 메시지가 홈, 상세, 채팅 진입 전 중 최소 두 지점에서 보인다.
- `pnpm run check-types`가 통과한다.
- `pnpm run check`가 통과한다.
- 브라우저에서 모바일과 PC 주요 viewport 스크린샷을 확인한다.

## 13. 승인 필요 사항

이 스펙은 추천안 C, 안전 중심 마켓플레이스형을 기준으로 한다. 사용자가 승인하면 다음 단계에서 구현 계획을 작성한다.
