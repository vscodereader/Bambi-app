# 밤비 Web Marketplace MVP 설계

작성일: 2026-06-12
상태: Web MVP 구현 진행 중, 구직자 API 루프와 로그인/온보딩 진입점 완료

## 0. 현재 구현 상태

2026-06-23 기준 Web MVP는 다음 상태다.

완료된 범위:

- `/login`: Better Auth 이메일 로그인/회원가입, seed 구직자 계정 기본 입력값 제공
- `/onboarding`: Bambi 프로필 생성/수정, 구직자/구인자 역할 시작 선택
- `/`: 비로그인도 공고를 탐색할 수 있는 반응형 마켓플레이스 홈
- `/seeker`: `bambi.jobs.list` API 우선 공고 탐색, 샘플 fallback
- `/seeker/jobs/[id]`: `bambi.jobs.getById` API 우선 공고 상세, 샘플 fallback
- `/seeker/jobs/[id]/chat`: Better Auth 세션, `bambi.onboarding.getMine`, 휴대폰 인증 상태, 공고 상태 확인 후 `bambi.chats.startFromJobPost` 호출
- `/seeker/chats`: `bambi.chats.listMine` API 우선 채팅 목록, 샘플 fallback
- `/seeker/chats/[id]`: API 채팅방이면 `bambi.chats.getById`와 `sendMessage`를 사용하고, 샘플 id면 기존 프리뷰 채팅을 유지
- `/employer`, `/moderator`: 공통 반응형 셸 위에 기존 구인자/운영자 화면 배치
- `pnpm run db:seed:bambi`로 seed 계정과 검증용 데이터 생성 가능

아직 남은 범위:

- 구인자 공고 목록을 `bambi.jobs.listMine` API로 교체
- `/employer/new` 공고 등록을 `bambi.jobs.create`와 연결
- 공고 수정 화면과 `bambi.jobs.update` 연결
- 채팅방 면접 일정 제안/확정 UI를 `bambi.chats.proposeInterview`, `setInterviewStatus`와 연결
- 연락처 공개 UI를 `bambi.chats.revealContact`와 연결
- 운영자 화면의 실제 심사/신고/제재 액션 API 연결

## 1. 목표

이번 단계는 밤비의 첫 Web MVP를 만든다. 범위는 구인자가 공고를 등록하고, 구직자가 그 공고를 탐색한 뒤 채팅을 시작하고, 양쪽이 면접 일정을 제안/확정하는 한 바퀴의 마켓플레이스 흐름이다.

구현은 Web 우선으로 진행한다. 공유 가능한 상태/데이터 흐름을 먼저 잡고, Next.js 화면에서 실제 oRPC API와 Better Auth 세션을 연결해 검증한다. Native 앱은 이 흐름이 안정된 뒤 같은 개념을 옮긴다.

## 2. 포함 범위

### 구직자 흐름

- 로그인한 사용자가 Bambi 프로필이 없으면 온보딩 화면으로 이동한다.
- 구직자 프로필을 생성할 수 있다.
- 공고 목록에서 업종, 지역, 최소 급여로 필터링할 수 있다.
- 공고 상세에서 급여, 지역, 업종, 근무 조건, 면접 참고사항, 구인자 인증 상태를 확인한다.
- 공고 상세에서 1:1 채팅을 시작한다.
- 채팅방에서 메시지를 조회하고 보낼 수 있다.
- 채팅방 안에서 면접 일정을 제안하고, 상대방 제안을 확정하거나 거절할 수 있다.

### 구인자 흐름

- 로그인한 사용자가 Bambi 프로필이 없으면 구인자 프로필을 생성할 수 있다.
- 구인자는 자신이 속한 조직/팀의 구인 프로필 상태를 확인한다.
- owner/admin은 조직/팀 프로필을 등록하거나 수정할 수 있다.
- 구인자는 공고를 등록하고 수정할 수 있다.
- 공고 상태를 확인할 수 있다.
  - 인증된 조직의 안전한 공고는 공개된다.
  - 미인증 조직 또는 위험 키워드가 있는 공고는 검수 대기 상태로 남는다.

### 공통 화면

- 로그인 화면은 기존 흐름을 사용한다.
- 로그인 후 첫 진입 화면은 역할과 프로필 상태에 따라 다음 행동을 안내한다.
- 상단/측면 내비게이션은 공고, 채팅, 일정, 구인자 관리로 구성한다.
- seed 데이터 계정으로 전체 흐름을 바로 확인할 수 있어야 한다.

## 3. 제외 범위

이번 단계에서 제외하는 기능은 다음과 같다.

- 관리자 심사 화면
- 구인자 인증 승인/거절 화면
- 신고 처리 화면
- 실시간 WebSocket 채팅
- 읽음 표시, 입력 중 표시, 이미지 전송
- 면접 후 후기 작성
- 연락처 공개 UI
- 화상채팅
- 유료 상단노출/광고 상품
- Native 앱 화면

단, 기존 API나 데이터 모델에 이미 있는 상태는 화면에서 읽거나 표시할 수 있다.

## 4. 화면 구조

### `/`

로그인 상태에 따라 진입점을 나눈다.

- 비로그인: 마켓플레이스 홈을 보여주며, 시작하기 CTA는 `/login`으로 이동한다.
- 로그인 + 프로필 없음: 온보딩 선택 화면으로 이동한다.
- 로그인 + 구직자: `/seeker` 공고 탐색으로 이동할 수 있다.
- 로그인 + 구인자/admin: `/employer` 구인자 관리로 이동할 수 있다.

### `/onboarding`

Bambi 프로필을 생성한다.

- 구직자 시작
- 구인자 시작
- displayName, phoneNumber 입력
- 생성 후 역할에 맞는 기본 화면으로 이동

기존 프로필이 있으면 생성 폼 대신 현재 프로필과 다음 이동 버튼을 보여준다.

### `/login`

seed 계정과 일반 이메일 계정으로 로그인하거나 회원가입할 수 있다.

- 기본 seed 구직자 계정 값을 미리 채워 빠른 검증을 돕는다.
- 로그인 성공 후 `/onboarding`으로 이동해 Bambi 프로필 상태를 확인한다.
- 회원가입 성공 후에도 같은 온보딩 흐름으로 이어진다.

### `/seeker`

구직자 공고 목록 화면이다.

- 업종 필터
- 지역 필터
- 최소 급여 필터
- 공고 카드 목록
- 인증 상태 배지
- 급여/지역/업종 요약
- 빈 상태와 오류 상태

목록은 기존 `bambi.jobs.list` API를 사용한다.

### `/seeker/jobs/[id]`

공고 상세 화면이다.

- 공고 상세 정보
- 구인자 인증 상태
- 면접 참고사항
- 채팅 시작 버튼

채팅 시작 후 생성된 채팅방으로 이동한다.

### `/seeker/jobs/[id]/chat`

채팅 시작 전 보호 확인 화면이다.

- 로그인 상태 확인
- Bambi 프로필과 역할 확인
- 휴대폰 인증 상태 확인
- 실제 API 공고면 `bambi.chats.startFromJobPost`로 채팅방 생성
- 샘플 공고면 기존 프리뷰 채팅으로 이동

### `/seeker/chats`

내 채팅방 목록이다.

- 공고 제목
- 상대 역할
- 최근 메시지 요약
- 면접 상태 요약

### `/seeker/chats/[id]`

채팅방 상세 화면이다.

- 메시지 목록
- 메시지 입력
- 면접 일정 패널
- 일정 제안 폼
- 제안된 일정의 확정/거절 액션

첫 버전은 실시간 구독 대신 전송 후 refetch 또는 수동 새로고침으로 충분하다.

### `/employer`

구인자 관리 홈이다.

- 내 Bambi 프로필
- 내 조직/팀 구인 프로필
- 공고 목록
- 공고 등록 버튼
- 공고 상태 배지

### `/employer/new`

공고 등록 화면이다.

- 조직 선택
- 팀 선택
- 제목
- 업종
- 지역
- 급여 금액과 단위
- 근무 조건
- 설명
- 면접 참고사항

등록 후 공고 상태를 보여준다.

### `/employer/jobs/[id]/edit`

공고 수정 화면이다. 아직 현재 라우트에는 구현되어 있지 않다. 조직과 팀은 변경하지 않는다. 공개 내용 수정 후 상태가 다시 검수 대기로 바뀔 수 있음을 표시한다.

## 5. 데이터 흐름

Web은 기존 oRPC client와 TanStack Query를 사용한다.

- 세션: Better Auth client/server session
- 내 온보딩 상태: `bambi.onboarding.getMine`
- 프로필 생성: `createJobSeekerProfile`, `createEmployerProfile`
- 조직/팀 프로필: `upsertEmployerOrganizationProfile`, `upsertEmployerTeamProfile`
- 공고 목록/상세/등록/수정: `bambi.jobs`
- 채팅 시작/목록/메시지/면접 일정: `bambi.chats`

필요하면 Web 전용 query/mutation hook 파일을 만든다. hook은 화면과 API의 중간 계층으로만 사용하고, 비즈니스 권한 판단은 API에 둔다.

## 6. 권한과 상태

- Bambi 역할 프로필 생성은 한 번만 가능하다. 기존 Bambi 프로필이 있으면 온보딩 화면에서 구직자/구인자 role을 직접 변경할 수 없다.
- 구직자는 본인의 표시명, 휴대폰 번호, 휴대폰 인증 상태와 같은 프로필 정보를 수정할 수 있다.
- 구인자는 본인의 개인 프로필 정보를 수정할 수 있다. 단, 조직/팀 구인 프로필 정보는 owner/admin 권한 규칙을 따른다.
- 구직자에서 구인자로, 구인자에서 구직자로 역할을 바꾸는 전환은 별도 전환 신청 또는 운영 정책이 필요한 기능으로 두고 이번 MVP에서는 제공하지 않는다.
- 구인 조직/팀 프로필 관리는 Better Auth organization member role이 owner/admin인 사용자만 가능하다.
- 직원 member는 자신에게 배정된 팀의 공고 작성은 가능하지만 조직/팀 프로필 관리는 할 수 없다.
- 구직자 role은 공고 등록 화면에 접근할 수 없다.
- 채팅 시작은 구직자만 가능하다.
- 면접 제안자는 자기 제안을 직접 확정/거절할 수 없다.
- 정지된 사용자는 주요 액션이 차단된다.

## 7. 디자인 방향

UI는 마케팅 랜딩이 아니라 반복 사용 가능한 작업 화면으로 만든다.

- 정보 밀도가 높지만 조용한 운영 도구 톤
- 카드 남발보다 리스트와 패널 중심
- 인증/상태/위험 신호는 배지와 상태 텍스트로 명확히 표시
- 모바일 폭에서도 필터, 목록, 상세, 채팅이 겹치지 않도록 단일 컬럼으로 자연스럽게 전환
- 데스크톱에서는 목록/상세/보조 패널을 나눠 스캔하기 쉽게 구성

기존 Next.js, Tailwind, shadcn 계열 UI 톤을 따른다. 별도 브랜드 비주얼이나 이미지 자산은 이번 단계에서 만들지 않는다.

## 8. 테스트와 검증

현재 구현 기준으로 다음을 확인한다.

- seed 계정으로 로그인할 수 있다.
- 구직자 계정이 공고 목록에서 공고를 보고 상세로 이동할 수 있다.
- 구직자 계정이 채팅을 시작하고 메시지를 보낼 수 있다.
- `pnpm --filter @bambi-app/api test`가 통과한다.
- `pnpm run check-types`가 통과한다.
- `pnpm run check`가 통과한다.
- Web 화면은 브라우저에서 주요 플로우를 수동 확인한다.

후속 구현 완료 시 추가로 다음을 확인한다.

- 구인자 계정이 API 기반 채팅방에서 메시지를 확인하고 면접 일정을 제안할 수 있다.
- 상대방이 면접 일정을 확정할 수 있다.
- 구인자 계정이 API로 새 공고를 등록하고 상태를 확인할 수 있다.
- 연락처 공개 요청과 동의 상태가 `bambi.chats.revealContact`와 연결된다.

## 9. 구현 메모

- 구현은 별도 worktree/branch에서 진행한다.
- 첫 구현은 Web에 집중한다.
- UI가 API 부족을 드러내면 필요한 API를 작게 추가하되, 관리자/후기/연락처 공개/실시간 채팅으로 범위를 넓히지 않는다.
- 기존 sample todo/dashboard 화면은 필요하면 제거하거나 밤비 진입점으로 대체한다.
