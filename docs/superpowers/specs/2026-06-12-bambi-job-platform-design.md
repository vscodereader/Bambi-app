# 밤비 구인구직 플랫폼 MVP 설계

작성일: 2026-06-12
상태: 사용자 리뷰 대기

## 1. 제품 방향

밤비는 유흥업 구인구직을 위한 연결 중심 플랫폼이다. 일반적인 이력서, 경력, 학력 기반 채용보다 빠른 공고 탐색, 1:1 대화, 면접 일정 확정을 핵심 가치로 둔다.

핵심 MVP 흐름은 다음과 같다.

1. 구인자가 공고를 등록한다.
2. 구직자가 공고를 탐색하고 상세 내용을 확인한다.
3. 구직자가 공고 상세에서 1:1 채팅을 시작한다.
4. 구인자와 구직자가 채팅 안에서 면접 일정을 제안하고 확정한다.
5. 면접 일정 확정 후 각자가 동의한 경우에만 연락처를 공개한다.

밤비는 넓은 유흥업 구인구직을 다루되, 불법 성매매, 강요, 미성년 관련 내용, 이를 암시하거나 우회하는 내용은 명확히 금지한다. 이 원칙은 약관 문구에만 머물지 않고 공고 등록, 공고 검수, 채팅 신고, 사용자 제재, 관리자 운영 흐름에 반영되어야 한다.

## 2. MVP 전략

추천 MVP 전략은 안전 중심 연결 MVP다.

1차 제품에서 우선할 기능은 다음과 같다.

- 빠른 공고 탐색
- 공고 기반 1:1 채팅
- 면접 일정 제안과 확정
- 구직자 익명성 보호
- 단계형 인증
- 미인증 구인자 공고 검수
- 신고, 차단, 관리자 제재

1차 제품에서 제외할 기능은 다음과 같다.

- 네이티브 앱 출시
- 1:1 화상채팅
- 고도화된 추천 알고리즘
- 공개 구직자 목록
- 구인자의 선제 제안 기능
- 전통적인 이력서와 경력 관리
- 유료 상단 노출과 광고 상품

첫 버전은 "쉽게 연결되지만 위험한 연결은 줄이는 구조"에 집중한다.

## 3. 사용자 역할

### 구직자

구직자는 모바일 웹에서 공고를 탐색하고, 관심 있는 공고에서 채팅을 시작하며, 면접 일정을 관리한다. 유흥업 특성상 구직자의 익명성이 중요하므로 기본 경험은 비공개 중심으로 설계한다.

MVP 기준 구직자 원칙은 다음과 같다.

- 공개 구직자 목록은 제공하지 않는다.
- 구직자 검색 기능은 제공하지 않는다.
- 채팅 전 상세 개인정보는 노출하지 않는다.
- 실명과 연락처는 기본 비공개로 둔다.
- 연락처 공개는 면접 일정 확정 후 본인 동의가 있을 때만 가능하다.
- 신고와 차단 기능은 필수로 제공한다.

### 구인자

구인자는 공고를 등록하고, 구직자와 채팅하며, 면접 일정을 제안하거나 확정한다.

공고 등록은 누구나 가능하지만 인증 여부에 따라 노출과 신뢰 표시가 달라진다.

- 인증 구인자의 공고는 즉시 노출될 수 있다.
- 인증 구인자의 공고에는 인증 배지를 표시한다.
- 인증 구인자의 공고는 목록에서 우선 노출한다.
- 미인증 구인자의 공고는 관리자 승인 후 노출한다.

### 관리자

관리자는 웹 관리자 화면에서 신뢰와 안전을 관리한다.

관리자 역할은 다음과 같다.

- 미인증 구인자 공고 승인과 반려
- 구인자 인증 심사
- 신고 처리
- 위험 공고 숨김 또는 복구
- 사용자 경고, 정지, 제한
- 위험 키워드, 신고 누적, 운영 정책 위반 검토
- 관리자 조치 로그 관리

## 4. 핵심 기능

### 공고

공고는 빠른 연결에 필요한 정보만 받는다.

MVP 필수 입력 항목은 다음과 같다.

- 업종
- 지역
- 급여
- 근무 시간 또는 근무 조건
- 간단 설명
- 면접 가능 방식 또는 면접 참고사항

공고 노출 규칙은 다음과 같다.

- 인증 구인자 공고는 위험 신호가 없으면 즉시 공개한다.
- 미인증 구인자 공고는 관리자 승인 전까지 공개하지 않는다.
- 위험 키워드가 포함되거나 신고가 누적된 공고는 재검수 대상으로 이동하거나 숨김 처리한다.
- 반려된 공고에는 반려 사유를 남긴다.
- 미인증 구인자가 승인된 공고의 공개 내용을 수정하면 다시 검수 대상으로 전환할 수 있다.

### 공고 탐색

사용자 모바일 웹의 첫 화면은 마케팅 랜딩 페이지가 아니라 공고 목록이어야 한다.

MVP 필터는 다음 세 가지로 제한한다.

- 업종
- 지역
- 급여

MVP 정렬은 다음을 지원한다.

- 인증 구인자 우선
- 최신순
- 급여순

기본 목록은 인증 구인자 공고를 우선하되, 승인된 미인증 구인자 공고도 함께 노출한다.

### 1:1 채팅

구직자는 공고 상세에서 1:1 채팅을 시작한다. 채팅방은 공고 단위로 생성해 신고와 분쟁 대응 시 맥락을 추적할 수 있어야 한다.

채팅 원칙은 다음과 같다.

- 기본 대화는 플랫폼 안에서 진행한다.
- 면접 일정 확정 전 외부 연락처 공유는 제한하거나 경고한다.
- 위험 문구는 신고 또는 검수 대상으로 표시할 수 있다.
- 사용자는 채팅방을 신고할 수 있다.
- 사용자는 상대방을 차단할 수 있다.
- 관리자는 신고된 채팅 맥락을 운영 정책 범위 안에서 확인할 수 있다.

MVP에서 실시간 입력 표시, 읽음 표시, 이미지 전송 같은 부가 기능은 필수가 아니다. 첫 버전은 메시지 신뢰성, 신고 가능성, 일정 연결에 집중한다.

### 면접 일정

면접 일정은 채팅 흐름 안에서 제안하고 확정한다.

구인자와 구직자 모두 면접 시간을 제안할 수 있다. 상대방은 수락, 거절, 다른 시간 제안을 할 수 있다. 한쪽의 제안을 상대방이 수락하면 일정은 확정 상태가 되고 양쪽의 일정 화면에 표시된다.

면접 일정 상태는 다음과 같다.

- 제안됨
- 확정됨
- 거절됨
- 취소됨
- 완료됨

면접 일정이 확정된 뒤에도 연락처는 자동 공개하지 않는다. 각 사용자가 본인의 연락처 공개에 동의해야 한다.

### 연락처 공개

연락처 공개는 다음 원칙을 따른다.

- 플랫폼 채팅을 기본 소통 채널로 둔다.
- 면접 일정 확정 전에는 연락처 공개를 허용하지 않는다.
- 각 사용자는 자신의 연락처 공개에 직접 동의해야 한다.
- 한쪽이 동의해도 상대방의 연락처가 자동으로 공개되지는 않는다.

시스템은 누가, 언제, 어떤 연락 수단 공개에 동의했는지 기록해야 한다.

### 인증

밤비는 단계형 인증을 사용한다. 가입 장벽은 낮게 두되, 중요한 행동 앞에서 필요한 인증을 요구한다.

MVP 인증 체크포인트는 다음과 같다.

- 회원가입: 기본 계정 생성
- 채팅 시작: 휴대폰 인증 필요
- 공고 등록: 구인자 휴대폰 인증 필요
- 미인증 구인자 공고 공개: 관리자 승인 필요
- 인증 배지와 우선 노출: 사업자 또는 업체 인증 필요
- 면접 확정과 연락처 공개: 휴대폰 인증 필요

성인 인증은 민감 업종 열람, 채팅 시작, 특정 공고 접근에 붙일 수 있는 확장 지점으로 남긴다. MVP 구현 시 나중에 성인 인증을 추가하기 어렵지 않은 구조를 잡아야 한다.

### 후기

후기는 면접 이후의 신뢰 기능으로 가볍게 시작한다.

MVP 후기 원칙은 다음과 같다.

- 면접 일정이 완료된 뒤에만 후기를 작성할 수 있다.
- 후기는 면접 기록에 연결한다.
- 후기는 신고할 수 있다.
- 관리자는 악성 후기나 정책 위반 후기를 숨길 수 있다.

처음에는 간단한 평점과 짧은 텍스트 피드백으로 충분하다. 고도화된 평판 점수는 2차 이후로 미룬다.

### 신고와 차단

사용자는 다음 대상을 신고할 수 있다.

- 공고
- 채팅방 또는 채팅 메시지
- 후기
- 사용자 계정

신고 사유는 다음을 포함한다.

- 불법 또는 금지 내용
- 강요 또는 안전 문제
- 미성년 관련 우려
- 사기 또는 허위 정보
- 괴롭힘
- 공고 내용과 실제 조건 불일치
- 기타

차단은 상대방의 추가 메시지를 막되, 운영상 필요한 신고 증거와 이력은 삭제하지 않는다.

## 5. 주요 화면

### 사용자 모바일 웹

사용자용 1차 플랫폼은 모바일 웹이다. 앱 설치 없이 접근할 수 있어 초기 검증과 유입에 유리하다.

주요 화면은 다음과 같다.

- 공고 목록 홈
- 공고 필터
- 공고 상세
- 채팅 목록
- 채팅방
- 면접 일정 목록
- 면접 일정 상세
- 구인자용 내 공고 목록
- 공고 등록과 수정
- 인증 상태와 인증 요청
- 신고 흐름
- 계정 설정

### 관리자 웹

관리자 웹은 MVP에 포함한다. 유흥업 구인구직에서는 운영과 검수가 제품 신뢰의 핵심이기 때문이다.

주요 화면은 다음과 같다.

- 관리자 대시보드
- 승인 대기 공고 목록
- 구인자 인증 심사 목록
- 신고 목록
- 공고 상세와 조치 화면
- 사용자 상세와 제재 화면
- 숨김 또는 위험 콘텐츠 목록
- 관리자 조치 로그

## 6. 핵심 데이터 모델

기존 인증 스키마 위에 밤비 도메인 테이블을 추가한다.

MVP 핵심 엔티티는 다음과 같다.

- 사용자 계정
- 사용자 역할과 계정 상태
- 구인자 프로필
- 구인자 인증 요청
- 공고
- 공고 검수 상태
- 채팅방
- 채팅 메시지
- 면접 일정
- 연락처 공개 동의
- 신고
- 차단
- 후기
- 관리자 조치 로그

중요 관계는 다음과 같다.

- 공고는 한 명의 구인자에게 속한다.
- 채팅방은 하나의 공고, 한 명의 구인자, 한 명의 구직자에 연결된다.
- 면접 일정은 하나의 채팅방에 연결된다.
- 연락처 공개 동의는 하나의 면접 일정과 동의한 사용자에 연결된다.
- 신고는 공고, 채팅방, 메시지, 후기, 사용자 중 하나를 대상으로 할 수 있다.
- 관리자 조치 로그는 관리자, 대상, 조치 종류, 사유, 시간을 기록한다.

구직자 프로필은 불필요하게 자세히 저장하지 않는다. 구직자 신원과 연락처는 인증과 동의가 필요한 행동에서만 사용한다.

## 7. 안전과 운영 정책

신뢰와 안전은 1차 제품에 포함되어야 한다.

운영 규칙은 다음과 같다.

- 미인증 구인자 공고는 승인 전까지 노출하지 않는다.
- 인증 구인자 공고는 즉시 노출할 수 있다.
- 위험 키워드, 신고, 관리자 판단에 따라 어떤 공고든 숨김 처리할 수 있다.
- 신고가 반복되는 사용자나 공고는 검수 우선순위를 높인다.
- 관리자 조치는 로그로 남긴다.
- 정지된 사용자는 공고 등록, 채팅 시작, 메시지 전송 등 주요 행동을 할 수 없다.

정책 적용 대상은 다음과 같다.

- 공고 내용
- 채팅 내용
- 연락처 공유 시도
- 후기
- 반복적인 신고와 악성 행동

첫 버전은 키워드 기반 검수와 신고 기반 검수로 시작한다. 더 정교한 자동 검수는 2차 이후로 미룬다.

## 8. 예외 상황 처리

MVP에서 고려해야 할 주요 예외 상황은 다음과 같다.

- 채팅이 시작된 뒤 공고가 숨김 처리되는 경우
- 면접 일정이 있는 상태에서 구인자나 구직자가 정지되는 경우
- 면접 완료 전 한쪽이 상대방을 차단하는 경우
- 확정된 면접을 한쪽이 취소하는 경우
- 사용자가 면접 확정 전에 연락처를 공유하려는 경우
- 이미 숨김 처리된 공고에 신고가 들어오는 경우
- 미인증 구인자가 승인된 공고의 공개 내용을 수정하는 경우

처리 원칙은 다음과 같다.

- 숨김 처리된 공고는 신규 채팅을 막되, 기존 채팅 참여자와 관리자는 제한된 맥락을 확인할 수 있다.
- 정지된 사용자는 위험 행동을 할 수 없지만, 운영 기록과 신고 증거는 유지한다.
- 취소된 면접은 이력으로 남긴다.
- 연락처 공개는 면접 확정과 본인 동의 조건을 모두 만족해야 가능하다.
- 미인증 구인자가 승인된 공고의 공개 내용을 수정하면 다시 검수 대상으로 전환한다.

## 9. 테스트 전략

MVP 테스트는 사용자 흐름과 안전 게이트를 중심으로 작성한다.

우선 테스트할 항목은 다음과 같다.

- 인증 구인자 공고는 즉시 공개된다.
- 미인증 구인자 공고는 승인 전까지 공개되지 않는다.
- 구직자는 필요한 인증 후에만 채팅을 시작할 수 있다.
- 면접 일정 확정 전에는 연락처를 공개할 수 없다.
- 연락처 공개는 본인 동의가 있어야만 가능하다.
- 면접 제안, 수락, 거절, 취소, 완료 상태 전이가 올바르게 동작한다.
- 신고 제출 시 관리자 검토 가능한 기록이 생성된다.
- 차단된 사용자는 추가 메시지를 보낼 수 없다.
- 정지된 사용자는 공고 등록과 메시지 전송을 할 수 없다.
- 미인증 구인자가 승인된 공고의 공개 내용을 수정하면 다시 검수 대상으로 전환된다.

구현 시에는 먼저 API 절차와 데이터 상태 전이를 검증하는 도메인 테스트를 우선한다. UI 테스트는 핵심 플로우가 안정된 뒤 추가한다.

## 10. 2차 이후 후보 기능

2차 이후로 검토할 기능은 다음과 같다.

- 대면 면접 전 1:1 화상채팅
- 네이티브 앱과 푸시 알림
- 공고 추천 고도화
- 유료 상단 노출과 구인자 홍보 상품
- 구인자 통계
- 후기와 평판 시스템 고도화
- 특정 카테고리 또는 행동에 대한 성인 인증
- 고도화된 자동 콘텐츠 검수

이 항목들은 제품 리스크나 출시 요구가 바뀌지 않는 한 MVP 필수 범위에 포함하지 않는다.
